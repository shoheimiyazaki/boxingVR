# 掴み・崩し・投げ・関節技 — 調査と実装案

柔道・合気道のような「掴んで姿勢を崩す・投げる・関節を極める」技を、このゲームにどれだけ入れられるかを調べた記録と、
軸（`CLAUDE.md` §1）に沿った実装の順番の案。2026-11-12 時点のコード（`PhysicsVersion` 7）を読んで書いた。まだ何も実装していない。

---

## 1. 結論

入れる余地は大きい。掴む仕組み・体同士の接触・捕捉点で踏み直す足の運びはもうある。
ただし今は **体を立たせる力が床からではなく体へ直接かかっている** ため、引いても押しても上体が傾かず、
**「崩し」が物理として起きない**。今の投げはその不足を場合分けで埋めた近道になっている。
先に支えの力を床（両足の支え）から出すように直すのが、すべての土台になる。

---

## 2. もうあるもの（使える土台）

| もの | 場所 | 中身 |
|---|---|---|
| 掴み | `Fighter.TryGrab` / `Fighter.UpdateGrab` | グリップを握った瞬間（`HandCommand.Grip` の立ち上がり）に、拳から `GrabRadius`（4 cm）以内で最も近い相手の部位と、壊れる玉継手（`AddBallSocket` + `MakeBreakable`、`GrabBreakForce` = 260 N）でつながる。切り落とされた腕・立っていない間は離す |
| 掴まれた側の弱り | `Fighter.IsGrabbed` / `GrabbedDriveScale`（0.55） | 掴まれている間は、体を動かす力が弱まる |
| 入力 | `VrPlayerControl`（グリップボタン、ヒステリシス 0.55 / 0.35）・`AiControl`・`BoxerBot`（クリンチ・投げ） | `FighterCommand` の `Grip` で掴む |
| 体同士の接触 | Bepu の接触（`BoxingGame.DetectHits` が拾う） | 体同士はぶつかる。押す・腰を当てる・足を掛けることは、接触としてはもう起きる |
| 捕捉点で踏み直す | `Footwork.PlanStep` | 重心の捕捉点（位置 + 速度 / ω）が両足を結ぶ線から `CaptureMargin` 以上外れると「倒れる」と見て足を踏み出す。崩しへの立ち直りは、これがそのまま使える |
| 関節の制限 | `Aigis.Physics.HumanoidRagdoll`（スイング・ねじれの制限） | 関節が曲がりすぎない拘束がある |
| 拘束の力の読み出し | `PhysicsWorld.GetConstraintImpulseMagnitude` | 拘束にかかった力積が読める（関節技で靭帯・骨にかかる力に使える） |
| テスト | `FighterPhysicsTests.Grab_HoldsOpponentAndReleases` | 掴んで離せることだけを確かめている |

## 3. 軸から外れている所・足りない所

### 3.1 投げが場合分け（§1.3 違反）
`Fighter.Release`（`allowThrow: true`）は、離した瞬間の前腕の速さが `ThrowSpeed`（1.1 m/s）を超えると、
相手を `ThrowAssist` で押してから `Knockdown`（状態を `Down` へ切り替え、胸を押す）にする。
「速さが閾値を超えたら倒れる」は物理量として説明できない閾値で、状態の書き換え。`CLAUDE.md` §8 に載せた。

### 3.2 体を立たせる力が、どこからともなく出ている（崩せない一番の原因）
| 力 | 場所 | 問題 |
|---|---|---|
| 上体を起こすねじり | `ApplyUprightImpulse`（`UprightKp` 600、`MaxUprightAccel` 1500 rad/s²） | 世界から胸・骨盤へ直接かかる角力積。足がどこにあっても体を起こし続ける |
| 腰を持ち上げる力 | `ApplyHover` | 上体へ直接かかる上向きの力（§8 の「ホバー」の負債） |
| 支えの中心へ寄せる力 | `ApplyBodyOverFeet`（`Centering`・`Tether`・`MaxMoveAccel` 6 m/s²） | 床を経ずに体を水平に引く |

崩しとは「相手の重心を支え（両足）の外へ出し、足の踏み直しでは戻せなくする」こと。
支える力が足の届く範囲を超えて出ている限り、どれだけ引いても体は傾かず、倒れるのは意識が薄れて張り（`Tone`）が抜けたときだけになる。

### 3.3 足が入力の契約にない
`FighterCommand` は両手・頭のずれ・胴のひねり・移動・向きだけ。足は `Footwork` が自動で置く。
足払い・大外刈り・小内刈りのように「相手の足を刈る」「自分の足を相手の足の外へ置く」ことを指示できない。

### 3.4 掴む力が固定値
`GrabBreakForce` = 260 N は材料・筋肉から出た値ではない。前腕の肉が削られても握る力は落ちず、相手が振りほどく力とも関係しない。
グローブ（ボクシング）か素手（柔道着を掴む）かの違いも無い。

### 3.5 床に落ちても傷つかない
`BoxingGame.DetectHits` は静的な物（床・ロープ）との接触を読み飛ばす。叩きつけ・受け身・頭から落ちることが意味を持たない。

### 3.6 関節技の材料が無い
関節の制限はあるが、制限が受ける力で何かが壊れることは無い（靭帯の材質も無い）。

## 4. 実装案（軸に沿った順番）

どの段も **場合分けを書かない**。技の名前で分岐せず、結果は力・位置関係・材料の値から連続に出す。
各段で `PhysicsVersion` を上げ、ボクシングの既存のテスト・ドリル・リーグで回帰を確かめる。

### 段 1. 支えの力を床から出す（土台。最優先）
- 体を立たせる力（起こすねじり・持ち上げる力・寄せる力）の **合計の力とモーメントを、両足が床から出せる分に制限する**。
  - 出せる分 = 着いている足の裏の範囲（支持多角形）に圧力中心（CoP）が収まり、水平の力が摩擦（μ × 足への垂直抗力）に収まる範囲。
  - 必要な力が範囲をはみ出す分は出さない。すると重心が足の外へ出たときに体は傾き、踏み直し（`Footwork` の捕捉点）が間に合えば立ち直り、間に合わなければ倒れる。
- 反作用を足へ返す（足が床を押す力として `DriveFoot` と同じ扱いにする）と、片足立ちの間は足を払われやすい、という性質が自然に出る。
- これで §8 の「ホバー」の負債と、3.2 の起こすねじりを同時に返せる。
- 影響: ボクシングのバランス全体（打たれて揺れる・踏み込み・回避）が変わる。調整値（`UprightKp` など）の取り直しと、ドリル・リーグでの確かめが要る。
- テストの例: 「静かに立つ相手の胸を水平に引くと、引く力が一定を超えた所で一歩踏み出す」「踏み出す足を床に留めて（ほかの体で塞いで）引くと倒れる」「両足を広げて腰を落とすほど、倒すのに要る力が大きい」。

### 段 2. 入力の契約に足を足す
- `FighterCommand` に足の指令を任意で足す（例: `FootCommand? Left/RightFoot` = 足の目標位置（体フレーム）と、床から離すかどうか）。
- 何も渡さなければ今の自動の足の運びのまま。渡した足は `Footwork` の置き場所の代わりにその目標をバネで追う。
- 記録（`ReplayTests`）の形式が変わるので、記録の版も上げる。
- VR では足は取れないので、コントローラ／ボットの技の経路から出す（§2 の「意図 → 技の選択 → 目標の経路」）。

### 段 3. 投げの場合分けを消す
- 段 1・2 があれば、引き手で崩し（重心を前へ）、腰・足を相手の踏み直す所へ入れる（足を刈る・腰に乗せる）ことで、倒れるかどうかは物理で決まる。
- `ThrowSpeed` / `ThrowAssist` / `Release` の中の `Knockdown` を消す。倒れたかどうかは審判の読み（姿勢から。§8 の Down の判定）に任せる。
- `GrabbedDriveScale`（掴まれたら力が弱まる）も、掴まれた部位を引かれる力として物理で出るので消せるか確かめる。

### 段 4. 掴む力を材料から出す
- 外れる力 = 握る側の前腕・指の筋肉の残り（`Strength`）× 握りの面の摩擦。掴まれた側の部位の形（細い手首は握りやすい、太い胴は抱えるしかない）も効く。
- グローブ（革・詰め物）は握れず、引っ掛けるか抱えるだけになる（グローブの材質の摩擦と形から）。素手・柔道着（服の材質）は握れる。
- 振りほどき: 掴まれた側が腕を回して握りの面に剪断をかけると、摩擦を超えて外れる。

### 段 5. 床との衝撃
- 床・ロープとの接触も、拳の打撃と同じ当たりとして扱う（衝撃 = 当たった部位の有効質量 × 落ちる速さ）。
- 頭から落ちれば頭のねじれ・揺れとして意識のモデル（`Fighter.TwistHead`）へ、体なら材料（打撲）へつなぐ。
- 受け身は「腕・背中を先に当てて頭の速さを落とす」動きとして目標の経路で書く（場合分けで減らさない）。
- 部屋（`LivingRoom`）の床・ローテーブルも同じ扱いになる。

### 段 6. 関節技（合気道）
- 関節の制限が受ける力（`GetConstraintImpulseMagnitude` / dt）を、その関節の靭帯・骨の材料の強さと比べ、超えた分だけ靭帯を痛める・骨を断つ（`BoxerBody` の断裂と同じ流れ）。
- 靭帯の材質（強さ・伸び）を `BoxerAnatomy` に足す。痛めた関節は制限が緩み、力が落ちる（肉が減ると力が落ちるのと同じ）。
- 小手返し・四方投げは、相手の手首を掴んで関節の制限の向きへ回す目標の経路。相手は痛みから逃れるため（入力元の判断）に体ごと回り、そこで段 1 の崩しが起きて倒れる。逃げなければ関節が壊れる。
- 合気道の「相手の勢いを使う」は、段 1 があれば相手が打ち込む運動量と足の位置関係から自然に出る。

### 段 7. 技と入力
- 技は **目標の経路** として書く（`PunchSpec` / `DefenseBook` と同じ形）: 掴む → 引き手で崩す → 体を入れる → 刈る・回す。
- ボット: 相手の重心・捕捉点・足の位置を読む（`OpponentRead` の延長）。`FighterSense` に相手の足の位置と重心の速度を足す。
- コントローラ: 「掴む」ボタン ＋ 方向 = 崩す向き。状況（相手の重心・足の位置・掴んでいる所）から最も効く技を選ぶ（§2 の決まり）。
- VR: 自分の手で掴んで引けば、そのまま崩しになる（段 1 があれば追加の仕組みは要らない）。足は自動か、腰の動きから推す。

## 5. 決まり・注意

- 段 1 はボクシングの手触り全体に響く。単独で入れ、ドリル（`drill` / `basics`）とリーグで前後を比べて `docs/BOT_PDCA.md` に記録する。
- 決定性（§1.6）: 新しい拘束の追加・削除の順は、試合の計算の順（ステップ内の決まった順）で行う。
- 武器を握る仕組み（`Fighter.Wield`、玉継手 + 手首の角度サーボ）と、相手を掴む仕組み（`TryGrab`）は、「手が相手の体／物に玉継手でつながる」点で同じ。段 4 で握る力を材料から出すときは、両方を一つのモデルにする（§1.5）。
