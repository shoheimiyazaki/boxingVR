# ボット改善の記録（PDCA）

ボット同士を戦わせ、データを見て直す、を繰り返した記録です。ボットと対戦場の仕組みは [BOTS.md](BOTS.md) にあります。各サイクルの生の出力（順位表・技の内訳・調整のログ）は [docs/arena/](arena/) にあります。

**評価の決まり**

- 総当たりは、各組 6〜8 試合を 60 秒ずつ行い、半分ずつコーナーを入れ替えます。
- 勝敗は KO・リングアウトで取ったラウンド数で決め、同じなら与ダメージの差で決めます（差が 5% 以内なら引き分け）。
- この POC ではダメージで動きが落ちないので、倒れるのは物理的にバランスを崩したときだけです。どのサイクルでも KO・ダウンは 0 で、勝敗は実質「与ダメージの差」です。
- 結果は種で決まり、同じコマンドで再現できます。

## サイクル 0 — 基準（全スタイルの総当たり）

- **Plan**: ボットの全スタイル（boxer / outboxer / swarmer / counter / slugger）と最初の CPU（legacy）を総当たりさせ、基準を取る。
- **Do**: `run.cmd arena league --bots legacy,boxer,outboxer,swarmer,counter,slugger --bouts 6 --seconds 60`（[cycle0_baseline.md](arena/cycle0_baseline.md)）
- **Check**:

| 順位 | ボット | 勝-分-敗 | 与 / 被ダメージ |
|---|---|---|---|
| 1 | outboxer | 30-0-0 | 747 / 353 |
| 2 | boxer | 24-0-6 | 702 / 451 |
| 3 | slugger | 15-1-14 | 533 / 595 |
| 4 | counter | 11-2-17 | 425 / 494 |
| 5 | swarmer | 7-3-20 | 467 / 668 |
| 6 | legacy | 0-0-30 | 285 / 599 |

  - 技を持つボットは全員、最初の CPU に全勝した。
  - **守りがほとんど出ていない**（1 試合に 1 回未満）。無防備に受けた打撃は 1 試合に 70〜90 発。
  - ジャブの 1 発平均ダメージが 14.5 で、ストレート（約 7）とフック（約 3）より大きい。
- **Act**: 守りが出ない原因を調べる（サイクル 1）。

## サイクル 1 — 拳の速さのしきい値を体の大きさに合わせる

- **Plan**: 被弾の直前 0.3 秒について、相手の拳の速さ・近づく速さ・到達までの時間を記録するプローブで原因を探る。
  - 分かったこと: 人形は 60cm なので腕の長さは 0.19m、パンチは 0.5〜0.8m/s しかない。
  - 「向かってくる拳」とみなすしきい値が人間の大きさの絶対値（0.7m/s）だったため、ほとんどのパンチを見落としていた。
- **Do**: しきい値を腕の長さ基準（2 × 腕の長さ/s ≈ 0.38m/s）にした（[cycle1_threat_scale.md](arena/cycle1_threat_scale.md)）。
- **Check**:
  - 守りが出るようになった。
    - outboxer: 1 試合に 24 回、成功率 64〜79%
    - counter: 1 試合に 17 回、成功率 46〜65%
  - カウンターも出るようになった（outboxer・counter で 1 試合に約 15 発、命中 78〜87%）。
  - 無防備な被弾は 65〜95 発と、まだ多い。反応時間（0.18 秒）は、近い間合いのパンチの到達時間（約 0.2 秒）とほぼ同じなので、見てから守れるのは一部だけ。人並みの制約としてこれは残す。
  - 順位は変わらず、counter が 4 位から 3 位に上がった（11-2-17 → 17-1-12）。
- **Act**: 採用。

## サイクル 2 — フックの軌道

- **Plan**: 技ごとに当たった部位を集計した（boxer 同士、4 試合 × 60 秒）。

| 技 | 平均ダメージ | 拳の速さ | 主に当たった場所 |
|---|---|---|---|
| ジャブ | 14.9 | 1.21 m/s | 頭・あご（クリーンヒット） |
| ストレート | 5.9 | 0.78 m/s | 195 発中 113 発が相手のグローブ |
| リードフック | 2.6 | 0.88 m/s | 主に肘。拳に乗る質量は 1.5kg で、体重もあまり乗っていない |

  - ジャブ（前の手）は相手の後ろの手の外側を通って顔に届く。
  - ストレート（後ろの手）は中央を通るので、相手の前の手に止められる。
  - フックは溜めが肘の高さで、相手の構えの腕に当たる。
  - 仮説: フックを肘より高い位置から振り、相手の顔を横切って振り抜けば当たる。
- **Do**: 頭へのフックの溜めを上げ（`Low` −0.3）、狙いの奥を反対側へずらした（`Sweep` 0.3）。
- **Check**: 平均ダメージは 2.6 → 3.0、肘に当たる回数は 42 → 27、あごに当たる回数は 13 → 16。改善は小さい。
- **Act**: 採用。ただしフックが弱いのは軌道だけの問題ではない。ひねりが小さく体重が乗らないという物理の結果でもあるので、軌道では限界がある。

## サイクル 3 — 相手の構えを読む

- **Plan**: 相手の拳の位置は見えている。そこで次の二つを試す。
  - 両拳が顔の前にあるとき（ハイガード）は、ストレートを胴打ちに切り替える。
  - 頭を打つときは、拳が覆っていない側へ狙いをずらす。
- **Do**: `ReadGuard` を追加した。同じ boxer の「読む（0.7）」と「読まない」を、全員と 8 試合ずつ総当たりさせた（[cycle3_read_guard.md](arena/cycle3_read_guard.md)）。
- **Check**:
  - 直接対戦は「読む」側から見て 4-1-3。
  - 全体の勝率は両方とも 76% で、与ダメージは 660 と 676。差は誤差の範囲。
- **Act**: **効果なしとして、既定では使わない**。機能は残し、自動調整が値を探せるようにした。

## サイクル 4 — 自動調整（1 回目）と、その反省

- **Plan**: いちばん強い outboxer を出発点に、値を変えた候補を 8 人作り、相手陣（全スタイル + legacy）との点で選ぶ。良かった候補は、別の種で王者と直接対戦させ、相手陣とも再戦させてから採用する。
- **Do**: `tune --base outboxer --gens 10 --pop 8`（[cycle4_tune_log.md](arena/cycle4_tune_log.md)）
- **Check**:
  - 3 世代で、調整後のアウトボクサーが相手陣の全員に全勝した。
  - 点が上限（1.05）に張り付き、4 世代目からは候補の差を見分けられなくなった。
- **Act**: **計り方を変える**（途中で打ち切った）。
  - 点数: 勝率とダメージ比を半々にし、ダメージ比は tanh(log 比) で滑らかに効かせる。全勝してからも「より大差で勝つ」改善を見分けられる。
  - 殿堂: 採用した王者を、相手陣に直近 3 人まで加える。強くなるほど相手も強くなる。

## サイクル 5 — 自動調整（2 回目: 殿堂入りあり）

- **Do**: `tune --base outboxer --gens 10 --pop 8 --bouts 4 --seconds 45 --seed 21`（[cycle5_tune_log.md](arena/cycle5_tune_log.md)、結果は [cycle5_tuned.json](arena/cycle5_tuned.json)）
- **Check**:
  - 10 世代のうち 7 世代で採用、3 世代は確認で不採用（別の種では王者に勝ち越せなかった）。
  - 採用された変更の流れ:
    1. 世代 2・3: 手の速さを上限近く（1.12 → 1.14）にし、手数を増やす（0.45 → 0.60）。
    2. 世代 4・5: 踏み込む距離を伸ばし（1.05 → 1.09）、1-2 を増やす（3.0 → 4.9）。
    3. 世代 6・9: 1-1（ジャブ 2 連打）の重みを 2 → 5.9 → 20.4 に増やす。
  - 守る率は 0.65 → 0.42 に**下がった**。守るより打ったほうが得、という結果。
  - 構えは高くなった（0.40 → 0.87）。
- **Act**: 総当たりで確かめる（サイクル 6）。

## サイクル 6 — 調整結果の確認（総当たり）

- **Do**: レビューの修正（守りは拳が向かってくる間は続ける、投げの最中は守らない、など）を入れたボットで総当たりした（[cycle6_league.md](arena/cycle6_league.md)）。
- **Check**:

| 順位 | ボット | 勝-分-敗 | 与 / 被ダメージ | 比 |
|---|---|---|---|---|
| 1 | **tuned5** | **48-0-0** | 895 / 258 | **3.46** |
| 2 | outboxer | 40-0-8 | 630 / 390 | 1.61 |
| 3 | boxer | 32-0-16 | 641 / 523 | 1.23 |
| 4 | counter | 19-3-26 | 421 / 551 | 0.76 |
| 5 | slugger | 14-6-28 | 514 / 676 | 0.76 |
| 6 | swarmer | 9-3-36 | 439 / 750 | 0.58 |
| 7 | legacy | 0-0-48 | 275 / 666 | 0.41 |

  - tuned5 は全員に全勝した。
  - ただし中身はジャブ連打で、1 試合にジャブ 73.6 発、ストレート 18.8 発。それ以外の技はほとんど使わない。
- **Act**: 強さでは採用に値する。ただ、技の幅が消えた原因は物理の偏り（ジャブだけが構えの外を通る）にある。技の幅を持つ boxer から出発して、tuned5 に勝てる組み立てが見つかるかを試す（サイクル 7）。

## サイクル 7 — 技の幅を保ったまま、ジャブ連打に勝てるか

- **Plan**: 技の幅を持つ boxer を出発点に、tuned5 を入れた相手陣で調整する。強さだけを求めると技が痩せることが、サイクル 5 で分かったため。
- **Do**: `tune --base boxer --gens 8 --pop 8 --gauntlet legacy,outboxer,swarmer,counter,slugger,docs/arena/cycle5_tuned.json`（[cycle7_tune_log.md](arena/cycle7_tune_log.md)、結果は [cycle7_tuned.json](arena/cycle7_tuned.json)）
- **Check**:
  - 8 世代のうち 6 世代で採用され、点は 0.648 → 0.834 に上がった。
  - 採用された変更の流れ:
    1. 世代 3・4: 手数を増やす（0.50 → 0.70）、カウンターを増やす（0.50 → 0.83）、踏み込みを深くする（0.95 → 1.04）、手の速さを上げる（1.03 → 1.10）。
    2. 世代 5〜8: 手数を最大（1.0）にし、1-2（3.0 → 9.5）と 1-2-3（2.0 → 4.6）を増やす。打ったら離れるのを減らす（0.40 → 0.16）。
  - 行き着いたのは「休まず 1-2・1-2-3 を出し続ける攻めのボクサー」（tuned7）。
- **Act**: 最終の総当たりで比べる（サイクル 8）。

## サイクル 8 — 最終の総当たりと、CPU の選定

- **Do**: 全員と tuned5・tuned7 で総当たりした（各組 10 試合 × 60 秒、[cycle8_final_league.md](arena/cycle8_final_league.md)）。
- **Check**:

| 順位 | ボット | 勝-分-敗 | 与 / 被ダメージ | 技の内訳（1 試合） |
|---|---|---|---|---|
| 1 | tuned5 | 64-5-1 | 882 / 333 | ジャブ 73・ストレート 19・ほかはほぼ無し |
| 2 | tuned7 | 61-5-4 | 1266 / 511 | ジャブ 56・ストレート 48・リードフック 14・アッパー 4 |
| 3 | outboxer | 50-0-20 | 633 / 460 | |
| 4 | boxer | 40-0-30 | 637 / 635 | |
| 5 | counter | 25-2-43 | 419 / 643 | |
| 6 | slugger | 18-5-47 | 498 / 814 | |
| 7 | swarmer | 12-3-55 | 456 / 881 | |
| 8 | legacy | 0-0-70 | 273 / 789 | |

  - tuned5 と tuned7 の直接対戦は、tuned5 から見て 4-5-1（種 4）。
  - 別の種でもう 10 試合すると 7-2-1 だった。合わせると **tuned5 が 11-7-2 で強い**。
  - どちらも、最初のスタイルと legacy には全勝した。
- **Act**:
  - **ゲームの CPU（`champion`）には tuned7 を選んだ**。理由: 総当たりの勝率はほぼ同じ（95% と 91%）。技の幅（1-2・1-2-3・フック・アッパー）がずっと広く、与ダメージも 1.4 倍あり、相手として面白い。
  - tuned5 は `jabber` として名簿に残した。強さを優先するなら、`BotCatalog.DefaultCpu` を `"jabber"` に変えるだけで差し替えられる。

## 分かったこと

1. **単位はその世界の大きさで決める**: 60cm の人形の世界では、人の大きさの絶対値（0.7m/s）のしきい値が全く働かなかった。腕の長さで割った値にして初めて守りが動いた（サイクル 1）。
2. **計り方が頭打ちになったら、計り方を変える**: 固定の相手に全勝した時点で、自動調整は改善を見分けられなくなった。殿堂入り（自分の過去の王者を相手に加える）と、滑らかな点（ダメージ比の tanh）にして、調整がまた進んだ（サイクル 4 → 5）。
3. **偶然を採用しない**: 候補の選抜とは別の種で、王者と直接対戦させて確かめた。サイクル 5 では 10 世代中 3 回、サイクル 7 では 8 世代中 2 回、選抜では 1 位でも確認で負けて不採用になった。
4. **物理が戦術を決める**: この体と当たり判定では、前の手のジャブだけが相手の構えの外を通り、クリーンヒットになる（1 発平均 13〜15 ダメージ。ストレートは約 6、フックは約 3）。強さだけを求めると、どの出発点からもジャブとストレートの比率が上がった。
5. **守るより打つ**: どちらの調整でも、守る率と「打ったら離れる」は下がるか横ばいで、手数と手の速さは上限まで上がった。反応時間（人並みの 0.12 秒以上）では近い間合いのパンチの多くが見てからでは間に合わず、守りの効果が小さいためと考えられる。

## 次に試すとよいこと

- **フックとアッパーを生かす物理の調整**: 技の幅を広げたいなら、ボットではなく物理の側（ひねりで体重が乗る量、構えの腕の当たり判定）を見直すのが近道。これはゲームの手触りに関わるので、別に判断が要る。
- **先読みの守り**: 相手の肩や腰の動き出しを見て守る。反応時間の制約の中で、守りを効かせる方法として。
- **VR での人との対戦**: ボット同士で強い型が、人にとって面白い相手とは限らない。champion（手数最大）は人には休みがなく感じる可能性がある。実機で確かめたうえで、手数（`Aggression`）を下げた版を用意するとよい。

# 防御編 — 防御技と間合いを磨く

方針: **まず防御技を 1 つずつドリルで最適化し、そのあと実戦で磨く**。

## 準備 — 防御を値で表す

- **Plan**: 防御の動き（頭の位置・時間・足・拳）がコードに直書きされていて、最適化できない。
- **Do**:
  - 防御技ごとの動きを `DefenseMove`（`DefenseBook`）の値にした。
  - 技を 2 つ増やした。
    - ウィービング（`Weave`）: 頭を U 字に沈めながら反対側へ抜ける。
    - サイドステップ（`SideStep`）: 足で横へ出て、拳の線から外れる。
  - 間合いの技を 2 つ増やした。
    - ストップジャブ（`StopJab`）: 踏み込んでくる相手にジャブを合わせる。
    - ピボット（`PivotAfterCombo`）: 打ち終えたら前の手の側へ回り込む。
- **防御ドリル**（`run.cmd arena drill` / `drilltune`、`DefenseDrill`）:
  - 攻め手は 1 種類の拳（ストレート・フック・アッパー・ボディ）だけを打つ。受け手は 1 つの防御技だけで守り、守り切ったらカウンターだけ返す。
  - 同じ種で「守らない受け手」とも戦わせ、1 発あたりの被ダメージがどれだけ減ったか（減り）と、カウンターでどれだけ取り返したかを測る。

## D1 — 見てからでは間に合わない（「動き出しを読む」を加える）

- **Check**（最初のドリル）: 近い間合い（胸と胸が腕の長さの 0.95〜1.15 倍）では、反応時間 0.18 秒の受け手が**一度も守れなかった**。

| 反応時間 | 間合い | 守った回数 | 1 発あたりの被ダメージ（ストレート） |
|---|---|---|---|
| 0.18 秒 | 0.95〜1.15 | 0 回 | 16〜18（守らないのと同じ） |
| 0.12 秒 | 0.95 | 64 回 | 16.7（ほとんど減らない） |
| 0.12〜0.18 秒 | 1.3 | 0〜77 回 | 0〜1.8（そもそも届かない） |

  - 拳が「向かってくる」と判定できてから当たるまでが 0.12〜0.18 秒しかない。
  - フックの拳を 1 コマずつ追うと、外へ約 0.09 秒振りかぶってから、約 0.11 秒で振り込んでいた。振り込みを見てからでは、人並みの反応時間（0.12 秒以上）では物理的に間に合わない。
  - 一方で、間合いを 1.3 倍に取れば拳はほぼ届かない。**間合いがいちばん強い守り**。
- **Act**: 人間のボクサーと同じく、動き出しを読むようにした（`Anticipation`、反応時間の下限はそのまま）。
  - 拳の速さは、相手の胴の速度を差し引いた「腕の動き」で見る（歩いて近づくだけでは反応しない）。
  - フックのように横から回り込む拳も判定する。
  - 読みが強いほど、振りかぶりの時点で気づく。振りかぶりから振り込みへの切り返しで一瞬遅くなっても、追跡は続ける。
  - 結果（読み度合い 1.0）: フックを守れた回数は 0 → 59〜66 回。ストレートも 0 → 46〜69 回。
  - 代わりに、読みすぎるとフェイントや構えの揺れにも反応する。どこまで読むかは実戦で決める。

## D2 — 点の付け方の欠陥（カウンターの取り返しに上限）

- **Check**（最適化前の表）: ボディとアッパーで、カウンターの取り返しが 777%、885% のように膨れていた。
  - 1 発が軽い拳では「守らない被ダメージ」がほぼ 0 で、割り算が膨らむためだった。
  - この点のまま最適化すると、ブロックの世代 1 のように、被ダメージを増やしてでもカウンターを打つ動きが選ばれた。
- **Act**: 点を「被ダメージの減り + 0.25 × カウンターの取り返し（上限 1）」に直して、やり直した（欠陥のあった記録は [defense_tune0_flawed_score.md](arena/defense_tune0_flawed_score.md)）。

## D3 — 防御技ごとの最適化（1 回目）と、ボディ打ちの発見

- **Do**: 7 技を順に最適化した（記録は [pre_review_defense_tune_log.md](arena/pre_review_defense_tune_log.md)）。
- **Check**: **ボディ打ちには、どの技でも被ダメージが増えた**（−68〜−139%）。
  - 守らない受け手は、ボディ打ち 181 発中 136 発を構えのグローブで受けていた。
  - ブロックで守ると被ダメージは 1.6 倍（みぞおち・心臓に入る）、バックステップでは 2 倍になった。
  - 構えたままの拳がもともと胴を覆っていて、動けば外れる。
- **Act**: ボディは、どの技にも受け持たせない（効き目の表でも 0 = 使わない）。

## D4 — レビューで見つかった欠陥と、作り直し

1 回目の実戦調整まで終えたところで（そのときの最終成績は 67-2-1、記録は `pre_review_*`）、独立したレビューが防御の仕組みの欠陥を見つけた。どれも「技の中身」そのものなので、**データを全部作り直した**。

| 欠陥 | 何が起きていたか | 直し方 |
|---|---|---|
| U 字の軌道を推し量っていた | 「始めと終わりの横位置が 0.001 以上違えば U 字」としていたため、最適化で値が揺れただけで、ダッキングやスリップまで U 字になっていた（始めは沈まず、途中で最も深く、終わりに起き上がる） | 横へ抜ける技かどうかを値（`Sweep`）で明示する。ウィービングだけが U 字 |
| 守りの延長中に頭が起きる | 拳が来ている間は守りを延ばすが、進み具合を時間で割っていたので、延長中は U 字の終わり（起き上がった姿勢）になっていた | 拳が来ている間は、守りの最も深い形で留まる |
| 引き戻す拳を振りかぶりと数えていた | 追跡が切れず、同じ手の 2 発目（ジャブの 2 連打など）に守りの判断が入らなかった。守りの最中に来た拳は、判断済みのまま見捨てられた | 相手自身の胸へ戻る拳は合図にしない（頭から離れるかどうかでは見分けられない。フックの振りかぶりも頭から斜めに離れる）。守りの最中は判断を保留する |
| ストップジャブが揺れで出る | 胸と胸の距離の差をそのまま速さにしていたので、相手の上体の揺れや物理の揺れで出ていた | 相手の胴の速度から測り、0.05 秒でならす |
| ピボットが最後のパンチの踏み込みを消す | 最後のパンチを打ち始めた瞬間に回り込み始め、そのパンチの踏み込みを打ち消していた | パンチを打ち終えてから回り込む |
| リプレイが黙ってずれる | スタイルの値は記録していたが、ボットの判断の仕組みの版は記録していなかった | 見出しに仕組みの版（`BoxerBot.LogicVersion`）を入れ、違えばはっきり断る |

## 防御編で分かったこと

1. **間合いがいちばん強い守り**: ドリルでも実戦でも、答えは同じだった。拳が届かない距離にいれば技は要らず、実戦の調整は「腕の長さ 1.3 倍の外から打ち、踏み込まれたらジャブで止め、打ったら出る」に行き着いた。
2. **守りは「読み」で決まる**: 近い間合いでは、人並みの反応時間で見てから守れる拳はほとんど無い。フックは振りかぶりを読んで初めて守れる。実戦での最善の読みは 0.7（読みすぎると、フェイントや構えの揺れで手が止まる）。
3. **ボディは構えで受ける**: 構えたままの拳がもともと胴を覆う。動く守りはかえって急所を開ける。
4. **拳の種類ごとに効く守りが違う**: フックにはくぐる（ウィービング）・覆う（ブロック）・反る（スウェー）、ストレートには反る・下がる。アッパーに頭を下げるのは自分から当たりに行く。
5. **技の中身の欠陥は、結果をまるごと変える**: レビューで見つかった欠陥（推し量った U 字、延長中に起きる頭、引き戻しの誤読）を直すと、「ドリルの技だけでは弱くなる」という 1 回目の結論が逆になった。測る前に、測る対象が意図どおり動いているかを確かめる必要がある。
6. **確認は最後にもう一度**: 世代ごとの確認を通った採用の積み重ねでも、出発点より悪くなることがあった（スリップ）。最後に、まだ見ていない種で出発点と比べる。

# 回避編 — 回避を磨き、回避からカウンターへつなぐ

方針: **まず回避技だけ（カウンターなし）を磨き、次に回避からのカウンターを研究し、最後に実戦で確かめる**。

## 準備 — 回避技を増やし、回避しながら打てるようにする

- 回避技を 2 つ増やした（回避はブロックを除く 8 技）。
  - インサイドスリップ（`SlipIn`）: 頭を外しながら半歩踏み込み、カウンターの届く距離に入る。
  - ローリング（`Roll`）: 拳の進む向きへ頭を沈めながら流す。
- 回避からのカウンターを値にした（`DefenseMove.CounterStraight` / `CounterHook` / `CounterUppercut` と、それぞれの打ち始め `…At`）。
  - 来る拳の種類ごとに、打ち返しの型を持つ。
  - 回避の途中（進み具合 0.2〜1）で打ち始められる。1 は回避を終えてから。
  - ブロックは両手で覆うので、打ち返しは常に守り終えてから。
- 回避だけのドリル: `drilltune --defense evasions --counters false`。受け手は打ち返さず、被ダメージの減りだけで点を付ける。

## E1 — 前回の守りの効果は、大半がカウンターだった

- **Check**: 2 代目 champion の回避の値を、カウンターを切ったドリルで測り直した。

| 回避（ストレートに対して、間合い 1.15） | カウンターあり | カウンターなし |
|---|---|---|
| ダッキング | 被ダメージ −23% | **+2%（減らない）** |
| バックステップ | −22% | **+2%** |
| スウェー | −31% | −7% |

  - 前回の「守りで被ダメージが減った」の大半は、打ち返して相手の攻めを止めた効果だった。回避の動きそのものは、近い間合いのストレートにはほとんど効いていなかった。

## E2 — ロープを背負うと、回避は効かない

- **Check**: 間合い 1.3 で、回避する受け手は守らない受け手より 2〜3.6 倍打たれた。

| 受け手 | ロープ際にいた時間 | 被ダメージ |
|---|---|---|
| 守らない | 0% | 750 |
| バックステップで回避 | **63%** | 2703 |
| ダッキングで回避 | 50% | 2485 |

  - 回避のたびに大きく下がるので、ロープまで追い詰められ、そこでは回避が効かずに打たれ続けた。
- **Act**: ロープを背負わない足（`RopeEscape`）。
  - 背中側のロープが近いほど、下がる動きを空いている横への動きに替える。
  - 逃げる向きは、ロープを感じたときに決めて離れるまで変えない。守りの最中は、来る拳から離れる側へ逃げる。
  - バックステップの受け手がロープ際にいた時間は、63% → 18% に減った。

## E3 — 届かない拳は避けない

- **Check**: ロープを直しても、間合い 1.3 では回避する受け手の方が多く打たれた。
  - この間合いでは相手の拳はほとんど届かないのに、受け手は来る拳のほぼ全部（1 試合 142 回）に回避を出していた。

- **Act**: 届く拳だけを避ける（`EvadeReach`）。相手の肩から自分の頭までが腕の長さ × 1.2 より遠い拳は避けない。

|---|---|---|---|
| 1.15・ストレート | 19.7 | 20.1 | 19.0 |
| 1.3・ストレート | 4.2 | **12.9** | **4.2** |

（1 発あたりの被ダメージ）

  - 見送った拳も、毎回見直す。相手が踏み込んで届くようになれば避ける。

## E6 — 回避からのカウンターの研究

- **Do**: `counterlab --combos true`。回避技 × 来る拳の種類ごとに、打ち返しの型 12 種 × 打ち始め 3 通り（回避の 35%・65%・回避の後）と、決まった返しを比べた（[counter_combo_lab_log.md](arena/counter_combo_lab_log.md)）。
  - 点 = (カウンターのダメージ − 打ち返したせいで余計に受けたダメージ) ÷ 攻め手の拳の数。
  - 上位 3 つを別の種で測り直して 1 つ選び、それと決まった返しを、さらに別の種で比べてから採用した。
- **Check**:

| 回避 × 来る拳 | 採用した打ち返し | 点（決まった返し → 採用） |
|---|---|---|
| ローリング × フック | **回避の 35% で 1-2** | 1.92 → **5.67** |
| ウィービング × フック | 回避の 35% で 1-2 | 0.80 → **2.83** |
| インサイドスリップ × ストレート | 回避の 35% で 1-2 | 0.85 → 1.91 |
| スリップ × ストレート | 回避の 35% で 1-2 | 1.39 → 2.14 |
| サイドステップ × ストレート / フック | 回避の 65% で 1-2 | 1.39 → 1.65 / 1.13 → 1.35 |
| ダッキング × ストレート | 回避の後で 3-2（左フック → ストレート） | 0.84 → 1.01 |
| ダッキング × フック | 回避の後で 1-2 | 1.02 → 1.25 |
| スウェー × フック | 回避の後で 6-3（右アッパー → 左フック） | 0.37 → 0.54 |

  - 特に、フックを流す・くぐる回避（ローリング・ウィービング）からの 1-2 は、決まった返しの 3 倍前後。フックを打った相手は、その側の顔が空いている。
  - 沈む回避（ダッキング）と反る回避（スウェー）は、回避を終えてからの方が良かった（沈み・反りの最中は拳が届かない）。

| ボクサー（boxer） | 81% → 78% | 2-3-5 |

  - 回避の間合い（近距離）で戦うインファイターに、はっきり効いた。被ダメージ 728 → 704、与ダメージ 470 → 502。
  - カウンターパンチャーとボクサーは、誤差の範囲（ボクサーはわずかに悪い）。
- **Act**:
  - **インファイター（`swarmer`）に、磨いた回避とカウンターの表を入れた**（`games/MiniRing/Bots/swarmer.json`）。
  - champion（2 代目）は据え置いた。間合いの外で戦うので、回避を使う場面がほとんど無い。

## 回避編で分かったこと

1. **守りの効果を回避とカウンターに分けて測る**: 前回の守りの効果の大半はカウンターだった。カウンターを切って初めて、回避そのものの性能が見えた。
2. **回避は足と一緒に考える**: 下がる回避はロープを背負わせ、ロープ際では回避が効かない。届かない拳まで避けると、自分から間合いを崩す。「ロープを背負わない」「届く拳だけ避ける」は、回避の技そのものの一部。
3. **ドリルは実戦に似せる**: 単発の攻め手で磨いた回避は、前へ入る形が連打の 2 発目に当たりに行き、実戦で効かなかった。連打の攻め手で磨き直して、実戦（インファイター）でも効くようになった。
4. **拳の種類で、回避の効き目がまるで違う**: フックとアッパーには回避がよく効く（30〜52%）。連打のストレートは回避ではほとんど防げない（よくて 17%）ので、間合いと構えで対する。
5. **カウンターは「回避しながら 1-2」**: 回避の途中で打ち始めるジャブ → ストレートが、ほぼすべての回避で最も強い。フックを流す・くぐる回避からなら、決まった返しの約 3 倍。
6. **技を磨いても、使う場面が無ければ勝ちは変わらない**: 間合いの外で戦う champion は、回避をほとんど使わず、回避の改良は効かなかった。改良がどのスタイルに効くかは、実戦で確かめるまで分からない。

# 基本動作編 — 右ストレートを外へ外す回避と、構え

インファイター（`swarmer`）の構えが低く拳を全部もらう、ダッキングも効いていない、という指摘から始めた。
目標は「相手の右ストレートに対して、拳の外側へ頭を滑り込ませ、腰から沈み、頭は自分のブロックの下へ逃がす」回避を、
同じ右ストレートを確実に外せるまで基本動作として磨くこと。

## 準備 — 1 つの型だけを打たせるドリル

- `run.cmd arena basics`（`BasicsLab`）: 攻め手は右ストレート（`2`）だけを打ち続け、受け手は 1 つの回避だけで外す。
  当たった所を、回避の最中の頭・ガード（腕と拳）・そのほか、回避を出していない時の頭に分けて、1 発 1 回だけ数える。
- 回避の値は「形」の中だけで動かす: 拳の外側へ（頭の横 0.15 以上）・腰から沈む（頭の沈み −0.2 以下）・拳は構えの高さに残す・拳を上げる。
- 回避の新しい値: `Outside`（ストレートには打ってくる腕の肩の側へ）、`GloveAnchor`（拳の高さをワールドで構えの高さに残す）。

## B1 — 頭を下げても、体は沈んでいなかった

- **Check**: 体だけで測った（`PostureProbe`）。頭を 0.6 腕の長さ下げる指令で、0.25 秒後に頭が下がったのは **0.12** だけ。
  脚は歩きの角度のまま伸びていて、骨盤を押し下げる力と脚が張り合っていた。頭はむしろ後ろへ逃げた。
- **Act**: しゃがむ量（立つ高さに対する割合）から膝と股の角度を決めて脚を曲げる（腿を前へ θ・すねを後ろへ θ で高さは cos θ 倍）。
  脚で足りない分は、股から上体を前へ折る（ヒップヒンジ、上限 20°）。同じ指令で **0.43** 下がるようになった。
  - 折る上限を 40° にした最初の版では、前傾 30° と足して胸が 70° 傾き、倒れた判定になって、総当たりのダウンが 0 → 54 に増えた。20° で 7 に戻った。

## B2 — 拳が頭を追いかけていた

- **Check**: 合図（練習で「右を打つ」と分かっている形）で、打ち始めと同時に回避を始めても、きれいに外せた拳は 0 %、頭に 79 %。
  ボットの拳は、当たるまで毎回相手の頭の今の位置へ狙い直していた。頭をどう動かしても拳が付いてくる。
- **Act**: 拳が狙いを追うのは打ち始めの 15 % の間だけにし、あとはその点へ打ち抜く（人の拳は打ち出したら直せない）。
  同じ条件で頭への被弾が 79 % → 11 % になった。

## B3〜B4 — 「ブロックの下」の作り方と、点の付け方

- B3: 拳を「頭のあった所」ごと残すと、外したはずのストレートを毎回グローブで受けた（きれいに外した 0 %）。拳は高さだけ残し、横は肩と一緒に動かすようにした。
- B4: 頭に当たらなくなると、点（きれいに外した割合 − 頭に当たった割合）では形の良し悪しを区別できない。
  ガードへの拳は 4 分の 1 のダメージなので、点から 0.25 × ガードに当たった割合を引いた。
- B4: 合図 0.04 秒だけで磨いた形は、その時だけ当たらなかった（0.04 秒で頭 0 %、0 秒で 41 %、0.08 秒で 55 %）。0・0.04・0.08 秒の全部で測るようにした。

## B5〜B6 — 基本動作の最適化

- **Do**: 手で決めた出発点から、0・0.04・0.08 秒の合図で、世代ごとに別の種で確かめて採用（[basics-b5.md](arena/basics-b5.md)、レビュー指摘の修正後に磨き直した [basics-b6.md](arena/basics-b6.md)）。
- **Check**（まだ使っていない種、右ストレートへの頭の被弾）:

| 動き | 頭に当たった | ガードで受けた |
|---|---|---|
| インファイターのダッキング（前） | 93 % | 5 % |
| 磨いた形（後） | **1 %** | 97 % |

  - 磨いた形: 頭を外側へ 0.15・腰から 0.48 沈む、拳は額の前に寄せて高さを残す（頭は自分のブロックの下）。右ストレートはブロックの上に当たる。
  - **もっと外へ出すと悪くなった**: 頭の横 0.15 / 0.25 / 0.35 / 0.45 で、頭への被弾は最大 2 % / 10 % / 11 % / 15 %。大きく横へ動くほど時間がかかり、頭がブロックの下から出る。
- **時間の窓**: 回避を打ち始めから 0〜0.08 秒で始めれば外せる。右ストレートは打ち始めから約 0.2 秒で届くので、ボット自身の目と反応（0.18 秒）では間に合わない（頭 97〜99 %）。
  - 先読みを 2 通り試したが、効かなかった。拍ごとに先に外す: 拳は外した後の頭を狙うので 99 % → 91 % にしかならなかった。相手が打つ間合いに入る瞬間に外す: ドリルの相手は間合いを保ったまま打ち続けるので、入る瞬間が無かった。どちらも外した。

## B7 — 構えは高さより形

- **Check**: 守らない受け手で、構えの高さ × 左右の開き × 前への出しを比べた（[basics-guard.md](arena/basics-guard.md)）。
  - 今の形（拳を左右に開き、前へ出す）では、高さ 0.8 / 1.2 / 1.5 で頭への被弾 99 % / 99 % / 73 %。高くしても真ん中が空いている。
  - 拳を寄せて（開き 0.25）顔に近づける（出し 0.6）と、高さ 0.8 でも **0 %**。ピーカブーの形。
- **Do**: 実戦で、インファイターの構えの形だけを変えた 3 つの版を総当たりした（各組 6 試合、[basics_guard_league.md](arena/basics_guard_league.md)）。

| 版 | 勝率 | 被ダメージ/試合 |
|---|---|---|
| 元の構え | 10 % | 872 |
| **高さ 0.8・開き 0.25・出し 0.6** | **57 %** | 660 |
| 高さ 1.2・開き 0.25・出し 0.6 | 47 % | 641 |
| 高さ 1.2・開き 0.5・出し 0.35 | 34 % | 645 |

  - 寄せた構えは元の版に 5-1-0、カウンターパンチャーとスラッガーに 6-0-0。
- 磨いたダッキングを足した版と足さない版は 31 % と 30 %（各組 10 試合、[basics_duck_ab_league.md](arena/basics_duck_ab_league.md)）で、差は無かった。
  実戦では回避を見てから始めるので、窓に間に合わない。
- **Act**: インファイター（`swarmer`）に、寄せた構え（高さ 0.8・開き 0.25・出し 0.6）と磨いたダッキングを入れた。
- 体の物理と拳の狙いを変えたので、全ボットで総当たりし直した（[前](arena/basics_league_before.md) / [後](arena/basics_league_after.md)、同じ種）。順位はほぼ変わらない（champion 98 % → 93 %、インファイター 15 % → 19 %）。

## 基本動作編で分かったこと

1. **動きを磨く前に、体と拳が本物か確かめる**: 頭を下げても体は沈まず、拳は頭を追いかけていた。どちらも、回避の値をいくら磨いても効かない原因だった。
2. **回避が効くかは、始める時で決まる**: 右ストレートは打ち始めから 0〜0.08 秒で回避を始めないと外せない。見てから避けるのでは間に合わない。
3. **構えは高さより形**: 高くしても、拳が開いて前に出ていれば真ん中が空く。寄せて顔に近づけた構えが、インファイターの勝率を 10 % → 57 % にした。
4. **基本動作の改良が実戦に効くとは限らない**: 磨いた回避はドリルで頭の被弾を 93 % → 1 % にしたが、実戦の勝率は変えなかった。次は回避を始める時（読み）を磨く必要がある。

## B8〜B10 — 「ブロック」ではなく、拳を通過させる回避

指摘: 磨いたダッキングはブロックに見える。頭を横下へしっかり落とし、顔をやや下へ向け、拳の軌跡の横・下横へ顔を持ってきて拳を通過させたい。

- **B8**: 点を「拳が何にも触れずに通過した割合」へ変え、ガードに当たった拳は頭と同じだけ引いた。磨いた形は頭 7 %・ガード 89 %（[basics-b8.md](arena/basics-b8.md)）。
  頭は守れたが、まだ拳をガードで受けていた。
- **B9**: 右ストレートが、外側の下から弧を描いて来ていた。溜めの点（`PunchPath.Windup`）をそのまま使っていたので、頭を横下へ外すと自分から当たりに行った。
  溜めの小さい拳（ジャブ・ストレート）は構えから狙いへまっすぐ出すようにした（`PunchSpec.Curve`）。
- **B10**: まっすぐ来る拳に、外側の横下へ外す形を磨いても、通過したのは 5〜12 %（[basics-b10.md](arena/basics-b10.md)）。
  - 頭が大きい: 腕の長さに対して人の約 1.6 倍（頭の半幅 0.19 R、人は約 0.12 R）。拳は 0.13〜0.16 秒で届き、その間に頭の幅ぶん横へ出られない。
  - 頭を 0.7 倍にすると頭には 22 発中 4 発しか当たらないが、その分が胴に当たった（16 発）。外側への通過は、体の比率を変えないと成り立たない。
  - 内側へのスリップは、打ち始めと同時に始めれば 34〜62 % が通過した。
- 結論: 「見てから避ける」限り、拳を通過させる回避は成り立たない。次の章で、避け始める時（読み）から作り直した。

# 予測編 — 見てからではなく、読んで避ける

指摘: スローにせずに避けるには、実際のボクシングではどうしているか調べ、パンチを見てから避けるのではなく間合いやリズムで次の拳を予測すること。
成り立たせるのに根本的な変更が要るなら、そこから考えること。

## 調べたこと（実際のボクシング）

- パンチは 0.2 秒足らずで届き、人の反応も同じくらいかかる。上級者でも拳を見てからでは間に合わない。
- 上級者は頭と胴を見て、拳は周辺視で捉える。手がかりは拳より先に動く肩と腰（運動連鎖）。
  状況の確からしさ（間合い・相手の癖・リズム）と合わせて予測する（[Martínez de Quel & Bennett 2019](https://www.redalyc.org/journal/710/71065391002/html/)）。
- VR の研究では、上級者は単発の拳は予測して避けて打ち返せたが、連打の 2 発目は予測できなかった（[Limballe ほか 2024](https://www.frontiersin.org/journals/sports-and-active-living/articles/10.3389/fspor.2024.1430719/full)）。
- 間合いの端に立つと、相手は踏み込まないと届かない。踏み込みそのものが合図になる。

## P1 — シミュレーションには、読める手がかりが無かった

- **Check**（`AnticipationProbe`、実戦 120 秒）: 打ち始めの間合いは狭い帯（スラッガー 0.98 ± 0.06 R、ボクサー 1.02 ± 0.08 R）で、強い手がかり。
  攻撃の間隔は ±0.2〜0.35 秒ぶれ、リズムだけでは数十ミリ秒の窓に合わない。
- 拳・踏み込み・頭の動きが同じ瞬間に始まっていた。肩や腰を読もうにも、拳より先に動くものが無い。

## P2 — 打つ前の溜め（根本の変更）

- **Act**: 連打の最初の拳の前に、溜め（`BotStyle.Telegraph` 秒）を入れた。溜めの間に、打つ手の肩を前へ回し（胴のひねり `FighterCommand.TwistBias`）、
  拳をわずかに引き、体重を移して踏み込み始める。拳が出てからの速さは変えない。狙いは溜めの始め（打つと決めた時）に決まる。
- ボットに相手の両肩と腰を見せた（`FighterSense.OpponentBody`）。
- **Check**: 溜め 0.08 秒、ひねり 14° では、溜めの終わりでもひねりの速さは頭の振りの揺れと見分けられなかった（物理の遅れ）。25° にした。
  - 溜めの威力として打ち抜きを深くした版は、外したはずの頭まで拳が届いた（溜め 0.16 秒で頭 99 %）。威力は物理（回した胴と踏み込みの勢い）に任せた。

## P3 — 相手の読み（`OpponentRead`）

- 試合の中で相手を覚える: 間合い・踏み込みの速さ・胴のひねりの速さ・肩の前傾の速さ・前の拳からの時間を区間に分け、
  「0.15 秒以内に拳が出たか」を数えて素朴ベイズで合わせる。手は肩のひねりの向き（連打の途中なら前の手からのつながり）、種類はその手の多い種類。
- 見積もりが閾値（`BotStyle.Prediction` が大きいほど低い）を越え、体の手がかりがそれに反していなければ、拳が出る前に守りを始める。
- **Check**（右ストレートだけのドリル、合図なし、インサイドスリップ、3 種 × 40 秒、`PredictionProbe`）:

| 相手の溜め | 反応だけ（頭に当たった） | 予測（頭に当たった） | 予測の守りがきれいに外した |
|---|---|---|---|
| なし | 100 % | 44 % | 14 % |
| 0.05 秒 | 99 % | 23 % | 95 % |
| 0.08 秒 | 99 % | **17 %** | **100 %** |
| 0.16 秒 | 99 % | 16 % | 100 % |

  - 頭の被弾は全部、覚えるまでの最初の数発（各試合 6 発）と、予測が出なかった拳。予測で始めた守りは、溜め 0.08 秒以上でほぼ全部きれいに外した（レビューの修正後の値）。溜めのある相手は読める、溜めの無い相手は間合いとリズムだけなので半分しか読めない。
  - 体の手がかりを引き金に必須にした版は、動くのが遅れ（溜め 0.12 秒で、拳の 0.05 秒前）、頭を外し切れなかった。間合いとリズムで構え、体の手がかりが反していない時に動くのが最も良かった。
  - 既定の `Slip` の動きは、溜めの始めに合図しても頭 88 %。予測が効くかは、回避の形（腰から沈んで内側へ）にもよる。

## P4 — 実戦で確かめる

- **Act**: スタイルの性格に合わせて溜め・予測・間合いの端を手で決めた（スラッガーは溜め 0.12 秒・予測 0.2、カウンターパンチャーは溜め 0.06 秒・予測 0.9 など）。
  インファイターのスリップを、内側へ腰から沈む形にした。
- **Check**: 総当たり（各組 10 試合 × 60 秒、同じ種。[前](arena/predict_league_before.md) / [後](arena/predict_league_after.md)）。

| ボット | 勝率（前 → 後） | 被ダメージ/試合（前 → 後） | 予測の守り/試合 | 打たれず | 空振り |
|---|---|---|---|---|---|
| champion | 94 % → 88 % | 420 → 369 | 15.8 | 41 % | 17 % |
| jabber | 89 % → 98 % | 413 → 320 | 9.9 | 41 % | 27 % |
| outboxer | 62 % → 61 % | 592 → 450 | 21.5 | 45 % | 28 % |
| boxer | 49 % → 45 % | 795 → 623 | 19.2 | 35 % | 24 % |
| swarmer | 32 % → 34 % | 856 → 737 | 22.5 | 17 % | 3 % |
| counter | 28 % → 35 % | 812 → 575 | 36.1 | 41 % | 30 % |
| slugger | 16 % → 11 % | 1005 → 829 | 11.1 | 19 % | 14 % |

  - 全員の被ダメージが 10〜30 % 減った（与ダメージも同じだけ減った。守りが効いている）。表は P5 の修正後の値。
  - インファイターの予測の守りは 17 % しか打たれずに終わらない。近い間合いで連打とフックを受け、内側のスリップに 2 発目が当たる（研究の「連打の 2 発目は読めない」と同じ）。

## P5 — レビューで見つかった欠陥

- 連打の次の拳の時刻を、溜めの始めから数えていた。溜め 0.12 秒では 1-2 がほぼ同時に出た。拳が出てから数えるようにした（打ち終えた後の間・離れる・回り込むも同じ）。
- 溜めの途中で回避を始めても、溜めの拳が回避の最中に出ていた。溜めの拳は守りで取りやめる。
- 溜めの間（拳は構え）の接触を、その拳の命中に数えていた。
- 相手が倒れて見ていない間の後、1 サブステップの差で速さを測り、跳ねた値を覚えていた。見ていない間は読みを止める（`OpponentRead.Pause`）。
- 踏み込みの速さを胸と胸の距離の変化で測っていたので、自分の踏み込みまで相手の踏み込みに見えた。相手の胴の速度で測る。
- カウンターとストップジャブにも溜めが入っていた。溜めない。打ち始めの間合いは連打の最初の拳だけで測る。
- 直した後の総当たり（同じ種、[後](arena/predict_league_after.md)）: インファイター 32 % → 34 %、カウンターパンチャー 28 % → 35 %。全員の被ダメージは 1〜3 割少ないまま。

## P6 — ボクセルの体を取り込み、頭を人の比率にして、外側へのスリップを成り立たせる

- 別の作業のボクセルの体（打撃で削れ、骨が断たれた腕・脚が落ち、脳を壊すと死ぬ）を取り込んだ。それだけで試合の様子が大きく変わった
  （同じ種の総当たりで、インファイター 34 % → 65 %、全員のダメージが約半分、KO で取るラウンドが出る。[頭 1.15 のまま](arena/predict_league_head115.md)）。
- **Act**: 頭を人の比率にした（`FighterTuning.HeadScale` 1.15 → 0.72。腕の長さに対する頭の半幅が約 0.19 → 0.12）。
- **Check**:
  - 予測で始める外側の横下へのスリップ（相手の右ストレートの外へ、腰から沈んで拳の軌跡の横下へ頭を落とす）を、溜め 0.08 秒の相手に、

## 予測編で分かったこと

1. **見てからでは間に合わない拳は、読んで避ける**: 反応だけでは溜めのある右ストレートでも頭に 99 % 当たった。間合い・リズム・体の手がかりで予測すると、覚えてからはほぼ全部外せた。
2. **読めるのは、拳より先に動くものがあるから**: 拳と体が同時に動き出す作りでは、読む手がかりが無かった。溜め（腰と肩のひねり）を入れて初めて体で読めるようになった。
3. **読むだけでは足りず、避ける形と体の比率も要る**: 既定のスリップは溜めの始めに始めても 88 % 当たった。外側へのスリップは、頭を人の比率にして初めて拳を通過させた。
4. **連打の 2 発目は読みにくい**: 研究と同じく、近い間合いで連打を受けるインファイターの予測の守りは、外の間合いのボットより打たれやすい。

# 足運び編 — 頭を元に戻し、足の置き場所のモデルを作り、しゃがみ過ぎを直し、回避を磨き直す

## F2 — 足の置き場所のモデル（[BOXING.md 1-5](BOXING.md)）

- **Plan**: 足をかかと側とつま先の 2 部位にし（母指球の蝶番）、左足前・かかとを浮かせて構える。倒立振子の捕捉点から足の置き場所を決め、足が先に踏み出して体が付いていく。
- **Do / Check**（`FootworkProbe`）でつまずいたこと:
  1. サーボだけでは、すり足の足が床の摩擦に負けて置き場所へ運べなかった（計画と実際が 4〜5cm ずれる）→ 足首を手の拳と同じ PD の力で引く。

     → 体は移動の指令に 0.08 秒遅れて付いていき（足が先に出る）、足の間へは弱く寄せ、離れすぎたら離れる向きの速さを抑える。

- 前へ歩く: 前足から先に動き（0.03 秒）、体は後から（0.11 秒）。1.5 秒で 0.44m（以前の、脚を振るだけの歩き方は 0.52 m/s、今は約 0.29 m/s）。

# ダメージ編 — 非線形のダメージと一撃のダウン

ユーザーの要望: 急所を的確に重いパンチで振り抜くと一撃でダウンできるように。場合分けせず、物理とボクセルの破壊の範囲で。

- **Check**: 頭への打撃で頭が首の上でどれだけねじられるか（相対角速度の変化）を測ると、最大 7.5 rad/s で、自分の動き（最大 10）より小さかった。
  体重の乗った拳の運動量を全身へ一様に配っていたので、どこを打っても頭は回らなかった。
- **Act**（[VOXEL_DAMAGE.md](VOXEL_DAMAGE.md)「意識と一撃のダウン」）:
  1. 削る量を拳の運動エネルギーに比例させた（非線形。速さ 2 倍で約 4 倍）。
  2. 運んだ運動量の一部を当たった点に掛けて部位を回す（あご・こめかみで大きく、頭の正面の真ん中で 0）。全身を押す速さの上限で頭打ちにしない。
  3. 頭がねじられた速さの 2 乗で脳しんとう、脳のボクセルの残りと合わせて意識、意識で体の張り。崩れ落ちるのは物理、崩れ落ちた判定は「支えようとしている高さより腰が大きく落ちた」。
- 調整でつまずいたこと: 頭のねじれを測った値から取ると自分の動きの揺れ（最大 67 rad/s）が混ざった → 打撃が頭に与えた回転から計算。
  腰の高さだけで崩れ落ちを判定すると深いダッキングでダウンになった → 支えようとしている高さとの差。
  脳が削れて起き上がれない KO と、起きてすぐ崩れる繰り返しダウン → 脳の働きを平方根に、張りが戻りきる意識で起き上がる。
- 結果（[総当たり 各組 4 × 60 秒](arena/damage_league.md)）: ダウンは champion が 1 試合あたり約 1.2 回。あご・こめかみへの体重の乗った速い 1 発で意識が 0 になって崩れ落ち、数秒で起き上がる。
  champion 78 %（奪ったダウン 42、32 試合）、champion-v1 69 %、jabber 67 %、swarmer 58 %。
- レビューで直したもの: 古い記録が新しい体で黙って再生される（記録に体の物理の版を持たせ、違えば断る。ボットの判断の版も 6 へ）、しゃがみから立ち上がる途中を崩れ落ちと取り違えうる、脳が少し削れた体が立てるのに起き上がれない。

# 首編 — 運動量も非線形に、首は硬く、スウェーは上体で

ユーザーの要望: パンチの運動量も非線形にして、首がもっと見た目に激しく持っていかれるように。首のバネは硬くし、殴られていないときにぐらつかないように。スウェーは首ではなく上体全体を後ろへ傾けるように。

- **Check**（`NeckProbe`）: 首はほぼ減衰のないバネ（3.5 Hz、減衰比 0.06、最大トルク 0.7 N·m 相当）だった。殴られていなくても、頭は胴に対して首の可動域の端（±45°）の間を振れ続けていた（傾きの中央値 45°）。
  スウェーでは胸が 28° 後ろへ傾いていたのに、頭が首の上で後ろの端まで倒れるので「首だけで反る」ように見えていた。
- **Act**:
  1. 首を硬く減衰の効いたバネに（9 Hz、減衰比 0.7、最大トルク 3 倍）。殴られていないときの傾きは中央値 3°、スウェー中の首は 4°。
  2. 体重の乗った拳が運ぶ運動量のうち、当たった部位に残る分を当たった点に掛ける（残りで全身を押す）。部位に残る割合は拳の速さに比例して増え、2.5 m/s で 55 %。部位に残る運動量は m v² に比例する（非線形）。
     速い拳ほど接触が短く、その間に首が体へ逃がせる運動量は限られる、という物理の近似。首の最大トルクを押し切る強い 1 発ほど、頭が大きく持っていかれる。部位に与える速さは 6 m/s まで。
  3. スウェー（頭を後ろへ引いた分）では、腰が後ろへの傾きの 6 割を受け持つ（前へ倒すときは 2.5 割のまま）。胸 24°、腰 14° 後ろへ傾く。
- レビューで直したもの: ねじりのてこを、グローブの中心ではなく拳が部位の表面に触れた点から測る（1.3 倍ほど長く見積もっていた）。
  押す・反作用の質量を、付いている部位だけで数える（千切れた後に運動量が湧いていた）。削って千切る前に打撃の力積を掛ける。
  後ろへ歩くときの傾き・ヒップヒンジには、スウェーの腰の受け持ちを掛けない。
- 確かめたこと: 打撃の前後で両者の運動量の和は変わらない（削られた分の質量は破片になって飛ぶ）。あごへの速い 1 発で、相手が受け取る運動量の 52 % が頭に残る。
  強さ 2 倍の打撃で、頭が持っていかれる角度は 2 倍。
- 結果（[総当たり 各組 4 × 60 秒](arena/neck_league.md)）: 脳しんとうの効きを合わせ直したあとのダウンは、全体で 103 回（前は 136 回）。champion 69 %、jabber 70 %、champion-v1 66 %、slugger 34 %（前は 25 %）。

## D2 — ダウンを分かりやすく、頭を人の比率に、ウィービングのドリル

ユーザーの要望: 一定の意識の低下で完全に倒れるように。腰が落ちる段階ももっと分かりやすく、回復にはもう少し時間をかける。頭を現実の大きさに。ウィービングでフックをきれいに通過させる。

- **Check**（`ConsciousnessProbe`: 意識を一定に保って立たせる）: 意識が 0.3 を切れば、体は床まで倒れきっていた。ただ、張りが抜け始めてから抜けきるまでの幅（0.5〜0.2）が狭く、意識 0.4 でも腰は 3 % しか落ちなかった。
  脳しんとうは 2.5 秒で抜けるので、強い 1 発でも力が抜けているのは 0.3 秒ほど。倒れきる前に持ち直し、膝をついたような曖昧なダウンになっていた。
- **Act**:
  1. 体の張りを 3 段に。意識 0.75 から張りが抜け始め、0.3 の手前で 0.5（ふらつく）、0.3 未満で 0（意識が途切れる）。
     ふらつく間は体重を支えつつ膝が折れて腰が落ち（意識 0.3 の手前で立つ高さの 70 %）、腕の力も 3 割に。意識が途切れると、体重を支える力も含めて全身の力が抜けて倒れきる。ダウン中も力は抜けたまま。
  2. 脳しんとうの抜ける時定数 2.5 → 5 秒。起き上がるのは意識 0.55 から。
  3. ガードの下げはボットの判断に（意識の薄れを `FighterSense.SelfFaintness` で知り、構えの拳を腕の長さ 0.35 ぶん下げる）。拳の目標を体の側でずらすと、VR の自分の手からアバターの拳がずれる（レビュー指摘）。腕の力を抜くだけでは、前腕が立った構えは重さで倒れず下がらなかった。
  4. 頭 1.15 → 0.8（身長が頭 5.6 個分 → 7.5 個分）。小さな頭では、同じ削る量で頭蓋を抜けて脳を壊しきった（正面の重い 1 発で脳の働き 0）。正面の重い 1 発で脳が削れる割合が前と同じ（0.78 → 0.75）になるよう、削る量を 45 → 12 / J、上限 450 → 120 に。
     小さな頭はねじれやすい（あご 155 → 220 rad/s）。
- ウィービングのドリル（[記録](arena/weave_drill.md)、左フック、溜め 0.08 秒）: 合図をもらう練習では、今の形でも 98〜100 % きれいに外していた。合図なし（自分の目と読みで反応）で磨き直し、まだ使っていない種で頭に当たる割合 16 % → 9 %、きれいに外した 89 % → 94 %。
  swarmer と champion に入れた。右フックには、予測ありで頭 6 %、きれいに外した 80〜85 %。
- 結果（[総当たり 各組 4 × 60 秒](arena/faint_league.md)）: ダウンは全体で 103 → 54 回。ふらつく段階では倒れずに立っていられるようになった分、少ない（脳しんとうの効きを 1.4 倍にして 44 → 54）。
  ダウンは床に倒れきり、十数秒で起き上がる。champion-v1 88 %、champion 70 %、boxer 67 %。

## D3 — 回避の体の動きを返しの拳へ（拳が体にバネでつながる）

ユーザーの要望: 回避からのコンビネーションのドリルを。回避の動きに使った運動量が、そのまま攻撃に変わる力学モデルにしたい。体の動きに拳がバネで付いてきて、スピードが乗る感じ。

- **Check**: 拳は体に付いた目標へ、強い減衰のバネ（減衰比 0.8）で引かれていた。体の速度は肩を通して物理的に受け継ぐが、体と拳の相対的な動きは減衰が打ち消すので、体の動きがバネに溜まって拳に乗ることはなかった。
- **Act**（`Fighter.TransferBodyMotion`、`HandCommand.Spring`）:
  1. 返しの拳を出し始めた瞬間の体幹（腰と胸）の運動エネルギーを蓄えとし、0.06 秒の時定数で拳へ渡す。その半分が拳の速さになる（`BodyToFistEfficiency`）。体の動きは渡したぶん止まる。
  2. 渡す先は拳の目標の先走り（`Arm.Lead`）: 目標が予定の軌道より先へ走り、体へつなぐバネ（3 Hz）で戻る。腕はそれを筋肉の力の範囲で追う。
     拳そのものに速さを足すと、腕の関節のサーボ（15 Hz）と拳のバネの減衰が、予定の軌道より速い分をすぐ消していた。
  3. ボットは回避からの返しの拳を出していく間だけ使う（引き戻し・倒れている間は使わない。攻撃編 A1 で全ての拳へ広げた）。VR・キーボードの手は使わない。
- 調整でつまずいたこと: はじめは体幹の今の運動エネルギーから渡し続けていて、打っている間も足が体を動かし続けるのでエネルギーが湧いていた（レビュー指摘）→ 出し始めの蓄えまでに。
- 確かめたこと（`BodyToFistTests`）: 横へ動いている体から打つ拳は最高速度 1.36 → 1.69 m/s、体幹は 0.22 → 0.19 m/s に減速。止まった体から打つ拳はほとんど変わらない（1.34 → 1.41）。
  回避ドリルの返しの拳の最高速度: ウィービング 1.77 → 1.98、ローリング 1.70 → 2.11、スリップ 1.29 → 1.57 m/s。ただ、ドリルの返しの多くは近すぎて相手のガードに 0.7〜0.9 m/s で当たり、当たる速さ・ダメージはあまり変わらない。
- 回避からの返しの研究（[記録](arena/counter_spring_lab.md)、swarmer の守り）: ウィービング・ローリングからの返しは回避の途中でなく終えてから、スリップからは 1-2 でなくジャブ単発に。swarmer に入れた。
- 結果（[総当たり 各組 4 × 60 秒](arena/counter_league.md)）: champion-v1 91 %、boxer 61 %、champion 59 %、swarmer 52 %。ダウンは全体で 52 回。

## D4 — ウィービングを腰から前へ、体のバネのタメを返しへ

ユーザーの要望: ドリルのウィービングがスウェーバックに見える。腰を前に折って、頭を U 字に。回避からの攻撃に体のバネのタメも使えるように（ダッキングで体を折り曲げたバネの反発でスピードを乗せる）。

- **Check**: 磨いたウィービングは頭を後ろへ 0.32 引いていた（磨く前も −0.41）。回避の練習場が、フックを外すのに頭を引く形を有利と見て選んでいた。前回のドリル動画は、`--move` を渡さないと外へ外す形を使っていて、磨いたウィービングではなかった（`--style` を足して直した）。
- 前へ折る形を比べた（[記録](arena/weave_forward.md)、`WeaveFormProbe`、合図なし・予測あり、左フック）: 頭を前へ突き出すほど、深く沈むほどフックに当たった（頭 25〜39 %）。フックは相手の頭のあった所の奥まで振り抜かれるので、前へ出た頭は自分からその軌道へ入る。
  頭の前後 0（ヒップヒンジで上体は前へ折れ、頭は突き出さない）・沈み −0.45 で頭 19 %（のけぞる形は 13 %）。見た目の要望を優先してこの形にした（swarmer・champion）。練習場の型も、ウィービング・ダッキングは頭を後ろへ引かないように。
- **体のバネのタメ**（`Fighter.BodySpringEnergy`）: 返しの拳を出し始めた瞬間の蓄えに、体のバネに溜まったエネルギーを足す。屈んだ脚（立つ高さより腰が低い分、体を支えるバネ）と、傾いた・ひねった胸（向きから外れた分、体の軸を保つバネ）。
  渡すのは、その時々の体幹の動き（並進と胸の回転）のうち時定数 0.04 秒で抜ける分: 屈んだ体が起き上がる・ひねった胸が戻る反発の動きをゆるめて、拳へ移す。全部を移すと体が屈んだまま起き上がらなかった。
  拳の目標の先走りを戻すバネの減衰を 0.7 → 0.4 にした（先走りが行き過ぎて戻る: バネ先の拳を振り回す）。
- 確かめたこと（`BodyToFistTests`）: 横へ動いている体から打つ拳 1.36 → 1.82 m/s、しゃがみから起き上がりながら打つ拳 1.28 → 1.51 m/s（起き上がる速さ 0.30 → 0.21 m/s）。
- 返しの研究（[記録](arena/counter_spring_lab.md)）: ウィービングでフックをくぐった後の返しは 1-2 から左アッパー（くぐって上がる体の反発に乗せる）、ローリングからは回避を終えてから。swarmer に入れた。
  ダッキングからは今の返しのまま（回避の途中で打つ候補は上回らなかった）。
- 結果（[総当たり 各組 4 × 60 秒](arena/counter_league.md)）: champion-v1 88 %、champion 72 %、jabber 61 %、swarmer 48 %。

## D5 — 腰から前へ折る（ヒップヒンジ）、お尻を引く

ユーザーの指摘: 出した動画にワンツーが無く、腰も折れていない。

- **Check**: 動画のツールに「スタイルの守りと返しを使う」を入れたつもりの編集が半分しか当たっておらず、返しはずっとオフ、構えも既定のままだった（使っていたのはウィービングの動きだけ）。直した（`--style`・`--counters`）。
  動画と同じ設定で測ると（`WeaveVideoProbe`）、ウィービング中の胸の前傾は最大 14°、腰 6°: 頭の沈みはほぼ膝の曲げで、腰を折るのは膝で足りない分だけ（最大 20°）だった。
- **Act**:
  1. 頭を下げる量の半分を、腰から前へ折る分に（`HipHingeShare` 0.5、最大 40°）。残りを膝と股で。
  2. 腰から前へ折るほど、お尻を後ろへ引く（`HipsBackShare`）: 頭が足の上から前へ出ない。引かないと頭が前へ出て、振り抜かれるフックの軌道に入り、左フックが頭に当たる割合が約 50 % になった。引くと 20 %。
- 結果: ウィービング中の胸の前傾 43°、腰 13°。返しは左アッパー（D4 で選んだ）。
  総当たり（[各組 4 × 60 秒](arena/counter_league.md)）で swarmer が 48 % → 28 % に落ちた（沈む守りを多く使うインファイターで、お尻を引くと返しが届きにくい）。

# 攻撃編 — 予備動作で体のバネを使う拳

## A1 — 溜めを逆へ引く動きに、拳は筋肉の力で打ち抜く

ユーザーの要望: それぞれのパンチで体重が乗る・スピードが乗る拳を研究。予備動作が小さい拳は軽く、大きいほど威力が出るモデルに。場合分けせず物理で（予備動作で体の固有振動・バネを使う）。単発と各種コンビネーション。

- **Check**（攻撃のドリル `attacklab`、相手のいない拳の実験 `PunchSpeedProbe`、1 発の追跡 `AttackTraceProbe`）:
  1. 溜めは打つ手の肩を前へ回す動き（読ませる手がかり）で、力学的に溜まるものが無く、長く溜めても拳は速くならなかった。
  2. 拳は予定の軌道を予定の時間でなぞっていて、速さの上限は時間だった（筋肉の力の上限 35 → 8 でも変わらない）。一気に打ち抜く先へ目標を置くと 1.35 → 2.10 m/s、拳を引いておくと 2.47 m/s。
  3. 拳を目標へ引くバネの減衰が、目標の手前でブレーキをかけていた。
  4. ドリルの的が自分の間合いを保とうと下がり、拳は頭の表面で腕が伸びきっていた（頭を人の比率に小さくして、表面が遠くなった）。
- **Act**:
  1. 溜め（`Telegraph`）は逆へ引く動きに: 打つ手の肩を後ろへ引き（胴のバネ）、頭を引いて膝を沈め（脚のバネ）、拳を引く。溜めの時間が 0.2 秒（`BotStyle.MaxTelegraph`）で引ききる: 短い溜めは浅くしか引けない。打ち出すと胴を前へ回す。
  2. 全ての拳の振り出しで、体の動きとタメを拳へ移す（回避編 D3〜D4 の仕組み）。数える体の動きは、拳の向きへ進む動き・持ち上がる動き・胸の回転だけ（打たれてのけぞる・下がる動きは乗らない）。胴のタメは鉛直軸まわりのひねりだけ（前へ傾けたままの姿勢は数えない）。フェイントには乗せない。
  3. 拳の目標は軌道を先回りして（振り出しの半分の時間で）打ち抜く先へ（`PunchSpec.LaunchShare`）。拳は肩・肘の筋肉の力で追う。振り出しの間は拳のブレーキを弱める（`LooseHandDamping`）。
  4. ドリルの的は下がらない（間合いを攻め手が決める）。
  5. 相手の読み（`OpponentRead`）は、打つ手を拳より先に動いた最初のひねりの向きと結ぶ（打ち出しの大きなひねりと結ぶと、溜めを見て逆の手を予想した。レビュー指摘）。
- 確かめたこと（`BodyToFistTests`）: 踏み込みながら打つ拳 1.67 → 2.29 m/s、下がりながら打つ拳は 1.13 m/s（拳と逆の動きは乗らない）。
- **結果**（[攻撃のドリル](arena/attack_drill.md): 各 3 試合 × 20 秒、守らない的、溜め 0〜0.2 秒 × 間合い 0.85・1.0。1 発の運動エネルギー = ½ × 拳に乗った質量 × 当たった速さ²）:

| 拳 | 間合い | 溜め 0 | 0.1 | 0.2 秒 | 拳に乗った質量 [kg]（溜め 0 → 0.2） |
|---|---|---|---|---|---|
| 右ストレート（2） | 0.85 | 0.83 J | 1.06 J | 1.56 J | 3.8 → 3.9 |
| 右ストレート（2） | 1.0 | 0.96 J | 1.29 J | 1.74 J | 3.6 → 3.8 |
| ジャブ（1） | 1.0 | 1.40 J | 1.41 J | 1.33 J | 2.3 → 3.4 |
| 右ボディ（2b） | 0.85 | 1.38 J | 1.18 J | 1.71 J | 4.1 → 4.1 |
| 右アッパー（6） | 0.85 | 1.14 J | 1.30 J | 1.23 J | 3.9 → 3.8 |
| 左フック（3） | 0.85 | 0.46 J | 0.49 J | 0.44 J | 1.2 → 2.9 |
| 2-3 | 1.0 | 0.74 J | 1.28 J | 1.44 J | 2.7 → 2.9 |

  - ストレート系は溜めるほど強い（右ストレートは約 1.8〜1.9 倍）。ジャブは乗る質量が増える（2.3 → 3.4 kg）が、速さが落ちて相殺。
  - フック・アッパーは溜めても強くならない（フックは乗る質量が増えても速さが落ちる）。弧を描く拳の溜め方は、まだ合っていない。
  - コンビネーション: 溜めは最初の拳にしか効かず、1 本に時間がかかるので、1 秒あたりのダメージはたいてい溜め無しが最も高い（1-2: 36.5 → 22.1、1-2-3: 30.7 → 20.9）。6-3-2 だけは溜めるほど上がった（24.4 → 29.5）。
- 総当たり（[各組 4 × 60 秒](arena/attack_league.md)）: champion-v1 100 %、jabber 62 %、champion 59 %。拳が速く強くなり、ダウンは全体で 52 → 334 回に増えた。

## D6 — ダウンを段階でなく連続に、意識の戻りに合わせてゆっくり起き上がる

- それまで: 意識 0.3 を境に張りが 0 へ落ち（倒れきる）、倒れたら 1.6 秒待って意識 0.55 で「起き上がり」へ切り替えていた。境で見た目が飛ぶ。
- 体はいつも立とうとし、腰を上げられる高さ（`StandReach`）を意識から連続に決めた: 張りは意識 0.3 で 0.5 から `LimpConsciousness` 0.12 で 0 へなめらかに抜け、
  高さも 立つ → 腰が落ちる → 中腰 → 膝立ち・座り込み → 床 と連続に下がる。腰の目標（`Rise`）は下がるときはすぐ、上がるときは `RiseTime` 2.5 秒の速さで、
  倒れている間は今の腰より 0.15 先までしか行かない（床から一気に浮かない）。起き上がる途中の脚は腰の目標に合わせて膝を曲げる（脚が先に伸びて体を押し上げない）。
- 状態は姿勢から読む: 腰が立つ高さの 0.55 より下なら Down、上なら GettingUp、0.85 まで戻り上体が起きた姿勢を 0.3 秒保てば Standing。自分で沈んだ分（ダッキング）は数えない。
- 脳しんとうの戻りを指数（時定数 5 秒）から一定の速さ 0.07/秒へ: 指数では深く飛ぶほど速く戻り、意識 0.05 から 1.5 秒で膝立ちまで戻っていた。
  今は 0.95 飛ばされると、約 2 秒床に伸び → 2.5 秒で膝立ち → 3.5 秒で中腰 → 6.5 秒で立ち直り → 10 秒ではっきりする（`ConsciousnessProbe.RecoveryFromADeepConcussion`）。
- 投げ（`Knockdown`）は腰の目標を床へ: 意識がはっきりしていても床から立ち直す。
- 総当たり（[各組 4 × 60 秒](arena/down_continuous_league.md)）: champion-v1 81 %、champion 67 %、jabber 64 %、swarmer 36 %。奪ったダウンは計 352（数え方を「立っていた → 立っていない」に直した）。

## 足運び編で分かったこと

1. **足は「計画」と「実際」を分けて閉じる**: 計画の位置へ運べなかった足から計画し直さないと、計画だけが先へ行き、体が付いていって倒れる。
2. **脚は目標の姿勢から解く**: 今の姿勢から解く IK は、崩れた姿勢を支え直さない。支え直すのは、目標との差が力になるとき。
3. **しゃがみは時間で測る**: 1 回ごとの深さではなく、続けて沈んでいる時間と割合を測って初めて「ずっとしゃがんでいる」が数字になった。
