# CMA-ES 対 (1+λ)（守り、作業指示 18、2026-11-16）

問い 1: 雑音のあるドリルで、CMA-ES（`cmatune`）は今の (1+λ)（`drilltune`）より、同じ予算で良い値を見つけるか。
守り `Slip`（相手の拳: ストレート）と `Weave`（フック・ストレート）を、種 1 と種 2 で、2 方式ずつ（全部で 8 本）。測定は raytrek（16 コア）の 1 台で 1 本ずつ。数字はすべて実測（推定は「推定」と書いた）。

  - `cmatune` の探索の予算は状態ファイルの `BudgetCalls`（最後の比べ直しの前）。
- 採否の確認は両方とも**使わなかった種**（`seed + 1000 × (500000 + k)`、k = 0..191、n = 192、20 秒）で、**始めの値と対にした固定の n**（`PairedEvaluation.Confirm`、95 % 区間・符号検定）。`drilltune` の結果は、作業 18 で足した小さなコマンド `defconfirm`（`games/MiniRing.Arena/DefConfirm.cs`）で、`cmatune` の最後の比べ直しと同じ点・同じ種・同じ n で測った。`cmatune` の結果は分布の平均 m（最良の個体ではない）。

## 答え（問い 1）

- **CMA-ES は 4 本中 3 本で、始めの値より有意に高い点の値を見つけた**（Slip 2 本と Weave 種 2。区間の下限が 0 より上）。(1+λ) は 4 本中 0 本（2 本は出発点に戻し、2 本は差なしか低下）。
- 差の平均は、CMA-ES − (1+λ) で Slip 種 1: +3.2、Slip 種 2: +2.9、Weave 種 1: +1.8、Weave 種 2: +5.6（それぞれ 0 との比較で、2 方式の差を直接検定してはいない。種ごと・技ごとに 1 本ずつで、4 本の中で同じ向きに揃ったのは事実）。
- 言えること: 同じくらいの予算（CMA-ES は 1 割ほど少ない）で、この雑音（20 秒 × 16 標本）の下では、CMA-ES のほうが良い値に動けた。言えないこと: 2 方式の差の有意性（本数が 4 本）、他の技・長い評価での差、**点が良いことが見た目・試合で良いこと**（下の拳の記録と動画で別に見る）。

## 注意（この比べの弱い所）

1. **最適化する点が同じではない**: `drilltune` は被ダメージ減の比（`DefenseTuner.Evaluate`）を、`cmatune` は確認と同じ `SeedPoints`（差）を最適化する。確認の点は `SeedPoints` なので、`cmatune` に有利。`drilltune` の点は比で、基準のダメージが小さい組で膨らみ（`evo_noise.md` 末尾）、勝者の呪いの影響も受ける。公平にするには `drilltune` の点も `SeedPoints` に替える（コードの変更。今回はしていない）。
2. **確認の点の水準が技で違う**: Slip（ストレートだけ）は 1 標本の点が 0 に近く（champion の Slip はストレートへの被ダメージ減が 0〜2 %）、Weave（フック・ストレート）は大きい。差の大きさ（+3 と +5）の単位は同じ点（被ダメージの差の合計）だが、技の間で比べられない。
3. Slip の CMA-ES の 2 本はどちらも「足の前後 `Move`」を −0.2 から +0.6〜+0.9 へ動かした（足を前へ出す側）。ドリルの点が出ていても、スリップの見た目が変わる可能性がある（動画で確認する。`docs/arena/cma_summary.md`）。
4. 標本が 16、評価が 20 秒と `evo_noise.md` の推奨（48・40 秒）より小さい。結果は「この設定で」。`drilltune` も同じ設定で測ったが、`drilltune` を 40 秒・48 本で回していれば結果は変わるかもしれない。
5. 8 本 × 1 回ずつ。種 1 と 2 の違いと、2 方式の違いは分けられない（種は両方式で同じ値を使った）。
