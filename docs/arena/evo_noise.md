# 評価の雑音（P0b、作業指示 15、2026-11-16）

`noiselab`（`games/MiniRing.Arena/NoiseLab.cs`）で、評価がどれだけ揺れるか・揺れの中で差を言うのに何標本要るか・1 標本を何秒にするかを測った。
試合は種と値で完全に決定的（§1.6）なので、同じ値を同じ種で測り直しても差は必ず 0 で雑音は測れない。雑音は **(a) 種を変えたときの揺れ**と **(b) ごく小さく値を変えたときの揺れ**の 2 つで測る。
測定は 12 コアの 1 台（RAM の空きが少なく、別の作業も同じ PC で動いていたので、壁時計は負荷で 1.5 倍ほど揺れる）。数字はすべて実測（推定は「計算」と書いた）。

## 結論（CMA-ES への推奨）

| | 試合（6 相手 × 両コーナー = 12 試合 / 標本） | ドリル（Slip・右ストレート・合図 0.04 s・1 本 / 標本） |
|---|---|---|
| 標本の点の標準偏差（種による揺れ） | 2.3〜3.0（約 2.7、45 秒） | 0.24〜0.33（約 0.28、20 秒） |
| 値を 0.001 動かしたときの d_i の標準偏差 | 4.0（独立なら 4.26） | 0.37〜0.38（独立なら 0.37〜0.47） |
| ρ（champion と champion′ の点の相関） | **0.13** | **0.34 と −0.02**（2 回測った） |
| 1 標本の壁時計（12 コア、片方の値） | 約 5 秒（静かな時 4.3 秒） | 20 秒で約 0.3〜0.5 秒 |
| 推奨する 1 標本の長さ | **45 秒**（30 秒は同じ壁時計あたり 3 割ほど検出力が低い） | **40 秒**（10 秒・20 秒より d_i の揺れが小さい。同じ壁時計あたりは 10 秒と同等で、差は 2 回の測定のばらつきの中） |
| 1 候補を測る標本の数 n（世代ごと） | **16**（標準誤差 2.7 / √16 = 0.68、約 80 秒 / 候補） | **48**（標準誤差 0.28 / √48 = 0.04、40 秒なら約 0.5〜1 分 / 候補） |
| 集団の大きさ λ | **12**（9 個の値の既定 4 + ⌊3 ln 9⌋ = 10 を、雑音のぶん 2 割増やす。μ = 6 の重み付き平均で雑音も平均される） | 12 |
| 世代数 | 約 30（12 候補 × 80 秒 × 30 = 約 8 時間） | 約 30（12 候補 × 1 分 × 30 = 約 6 時間） |
| 採否の確認 | **使わなかった種で n = 40 の固定 n**（`PairedEvaluation.Confirm`）。95 % 区間が 0 を含まず、符号検定も p < 0.05 | **n = 96 以上**の固定 n |

要点:

1. **同じ種で対にしても分散はほとんど減らない**（ρ = 0.13 と、ドリルで 0.34 / −0.02）。値を 1 mm・0.001 動かしただけで、体の動きはカオス的に別の軌道になり、新しい種で測ったのとほぼ同じだけ揺れる。共通の乱数に頼らず、**標本の数 n と集団 λ で雑音を平均する**。対にした評価の利点は、種の運を揃えられることではなく、2 つの値を同じ条件で比べる手続きが決まること。
2. **(1+λ) の「一番の候補を拾う」は勝者の呪いで膨らむ**。標準誤差 σ の評価を λ = 12 候補に行うと、真の差が 0 でも一番の候補は平均 1.63 σ ほど高く見える（標準正規 12 個の最大の期待値、計算）。n = 16 の試合なら約 +1.1 点、n = 48 のドリルなら約 +0.07 点で、ドリルで測った本当の差（champion 対 v1: 0.03〜0.10）と同じ大きさ。動作例（下の「逐次と固定 n」）でも、逐次の目安は n = 32 で「+0.225、99.4 % 区間が 0 を含まない」と止まったが、使わなかった種の n = 96 では +0.033（区間は 0 を含み、差なし）に縮んだ。**逐次は予算の配分にだけ使い、採否は使わなかった種の固定 n で言う**。
3. 本当の差を言うのに要る n は、差の大きさで桁が変わる（計算: n = (2.5 × SD(d) / 差)²。試合 SD(d) = 4.2（45 秒）、ドリル SD(d) = 0.34〜0.38 から）。
   | 試合の差（点 / 標本。12 試合の勝ち − 負け + ダメージの項） | 要る n | | ドリルの差（点 / 標本） | 要る n（20 秒） | 要る n（40 秒） |
   |---:|---:|---|---:|---:|---:|
   | 3 | 13 | | 0.2 | 23 | 19 |
   | 2 | 28 | | 0.1 | 91 | 73 |
   | 1 | 111 | | 0.05 | 361 | 289 |
   | 0.5 | 441 | | 0.03 | 1003 | 803 |

   測れた本当の差は、試合の champion 対 champion-v1 が約 10 点（n = 2 で足りる）と大きく、ドリルは 0.03〜0.10 と小さい。**ドリルの小さな改善（0.05 以下）を採否まで言うには n が数百要る**。CMA-ES の世代の選択は順位でよい（雑音に強い）が、最終の採否は大きな n で確認する。
4. 1 標本の長さ（(d)）: 試合は 45 秒が最良（t ÷ √壁時計 の大きさ: 30 秒 0.44、45 秒 0.65、60 秒 0.57）。30 秒は短すぎて決着が付かず効果が小さい。60 秒は効果の大きさは同程度で費用が増える。ドリルは 10 秒・40 秒が同程度（2 回の平均 0.26 と 0.24）で 20 秒が低く出たが、2 回の測定のばらつき（0.09〜0.33）の中なので、20 秒に特別な理由は無い。10 秒は近づくまでの前置きの割合が大きく（割合は測っていない）、d_i の揺れも大きい（0.42〜0.52）。40 秒は d_i の揺れが最も小さい（0.34）。点の尺度が秒数で変わる（長いほど差が開く）ので、信頼区間の幅でなく t ÷ √壁時計（検出力）で比べた。

## 予想外だったこと

- **champion（2 代目）は、今の物理（スタミナの予算、PhysicsVersion 32 以降）では 6 相手に負け越している**（点 −5.8、champion-v1 は +4.3。40 種中 40 種で v1 が上、符号検定 p < 1e−10）。`docs/arena/attack_league.md` にも champion が 19-0-13 で champion-v1 に 0-0-4 とある。`league --bots champion,champion-v1,boxer,jabber --bouts 4 --seconds 45` でも champion 5-0-7、v1 8-1-3 で、`noiselab` の数字は league と合う（サンプラーの符号の取り違えではない）。CLAUDE.md の「champion は総当たり 70-0-0」は今は成り立たない。この測定は「本当の差の例」として champion 対 v1 を使ったので、差が大きすぎて n の下限（要る n = 1〜4）にしかならない。小さな差の検出力は上の表（3）で計算した。
- **champion の `Slip.HeadX` は 0.8 だが、範囲の上限は 0.6**（`DefenseRanges.HeadX`）。+0.001 しても `Validated()` で 0.6 に収め直されて同じ値になり、最初の測定で全標本の差が 0 になった。champion′ は、収めた後の値から範囲の内側へ（−0.001）動かして作る。champion.json の値が範囲外な理由は調べていない（`champion.json` は今回変えていない。範囲の外の値は `Validated()` が黙って収めるので、調整や比較では収めた後の値を基準にする）。

## 点の尺度

試合の標本の点は「1 つの種 × 相手 6 人 × 両コーナー（12 試合）の合計」に `MatchScore.Of(勝ち, 負け, 与えた, 受けた)` = 勝ち − 負け + 0.9 tanh((与えた − 受けた) / 400) をかけたもの。全体（相手 × 試合）の合計にかける `MatchTrainer` の点とは尺度が違う（標本 1 つが 12 試合ぶんなので、勝ち − 負けは ±12 の範囲。`MatchTrainer` は 全試合の合計に 1 回かけるので、同じ式でも tanh の頭打ちのかかり方が違う）。比べるときは同じ標本の定義の中だけで比べる。

ドリルの標本の点（`noiselab`）は `DefenseDrill.Punch` の `PunchDrillResult.Score` = きれいに外した割合 − 頭に当たった割合 − ガードに当たった割合（種ごと = 1 本）。`DefenseTuner` の点（合計からの比）は変えていない。`DefenseTuner` のドリルで種ごとに集めるときの点は比でなく差にした（`DefenseTuner.SeedPoint` = （守らない受け手の被ダメージ − 被ダメージ）+ 0.25 × 打ち返しのダメージ。比は、基準のダメージが 0 に近い組で膨らみ、裾が重くなって検定の前提が崩れるため）。P1b がドリルに CMA-ES をつなぐときは、この `SeedPoint`（打ち返しあり）か `Punch` の点を目的関数に選ぶ。

## 測定の条件

- コマンド: `dotnet run --project games/MiniRing.Arena -c Release --no-build -- noiselab --only match --match-n 40 --out ...`（試合 35.0 分）、`... --only drill --drill-n 96 [--seed 2] --out ...`（ドリル 5.7 分と 9.0 分。1 回目は静かな時、2 回目は別の作業と同時）。
- 試合の相手は boxer・outboxer・swarmer・counter・slugger・jabber。champion と champion-v1 は `Contender.Of`（`Validated()` を通した値）。champion′ は `Cross.Duration` に +0.001 s。
- 標本の種は `seed + 1000 k`（相手 i との試合は `+ 101 i`）。(a) の 2 つの組は k = 0..n−1 と k = n..2n−1（重ならない）。逐次の動作例は k = 3n.. から、固定 n の確認は k = 4n.. から（どちらも (a)〜(d) に使っていない種）。
- 試合は n = 40（予定の n = 12 では (a) の標準偏差の差が見えないので増やした。壁時計は 1 標本約 5 秒で、40 標本 × 8 通りで 35 分）。ドリルは n = 96 を 2 回（種 1 と種 2、別の種の組）。
- 試合の 1 標本の壁時計の表の値は champion と v1 の 2 つの値を測る費用の合計 ÷ n（片方の値の約 2 倍）。壁時計は別の作業との同時実行で揺れるので、桁（秒・分）として読む。
- 検出力の指標 t ÷ √壁時計: t = 平均の差 ÷ 標準誤差。標準誤差は 1 / √n、n は壁時計に比例するので、同じ壁時計で測ったときの t は t ÷ √(今の壁時計) に比例する。t 自体が 1 回の測定の乱数を含むので、符号以外の細かい差（10 〜 15 %）は意味が無い。
