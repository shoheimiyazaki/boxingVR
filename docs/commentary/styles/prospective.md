# 型: prospective（2 エージェントプロスペクティブ制）

実況（`announcer` 立花）と解説（`commentator` 佐伯）を、別々の 2 つの LLM（既定 Haiku）が受け持つ。台本を後から書くのではなく、試合の進行に合わせてその場で話す（2026-11-17、ユーザーの考えた方式）。道具は `tools/tvshow/prospective/run.js`、決まりの値は `tools/tvshow/prospective/config.json`。

## 決まり（アルゴリズム）

| ユーザーの考え | 手順での形 |
|---|---|
| Haiku は 2 エージェント並列 | 席ごとに別の会話（`claude -p --resume`）。互いの考えは見えず、見えるのは相手が声に出した言葉だけ |
| 試合の情報とキーフレームの画像を渡す | 選手の資料（`fighters.md`）と、その席に見える出来事（実況 = 画面で見えること、解説 = それに加えて体の中・狙い）。出来事の時刻の画面を切り出した画像（`frames/`）は、その時刻を過ぎたら「新しい画面」としてパスを渡し、LLM が Read で見る。まだ起きていない出来事は渡さない（`digest.md` は試合の全部を含むので渡さない） |
| 試合の進行に合わせて話す | 記録した試合の時計 T を進め、出来事・台詞の終わり・割り込み・無言のうち一番早いものを順に処理する |
| マイクは 1 本、同時に話せるのは 1 人 | 話している台詞は常に 1 つ（`cur`）。次の人が話し始めた時点で前の台詞は切れる |
| TV の時間は固定、時間を資源に話す | 毎回「いま T 秒・残り L − T 秒」を渡す。台詞の長さは、声入れと同じ声・速さで実際に読み上げて測る（`Synthesize.ps1`、同じ台詞は `tts.json` の記録を使う）ので、長く話せばそのぶん時間を使う。字数の見積もりは実際より中央値で 1.1〜1.2 倍、長い台詞で 1.4 倍短く、見積もりで進めた最初の版（v1）は声入れで台詞が 1〜3 秒ずつ遅れた |
| マイクを渡されたら履歴を渡して考えて話す。パスも可 | マイクの呼び出し: 前に聞いてから今までの出来事・2 人の台詞（切れた所も）・新しい画像を渡し、`speak`（`seconds`・`text`・`excited`・`handTo`）か `pass`（`wait`）を返させる |
| 考えている間は試合が止まる | 時計は呼び出しの間進まない（考えた時間は動画に入らない） |
| 話したい秒数を予約し、その間好きにしゃべる。秒数制限は無し | `seconds` は話し手の目安で、時間を使うのは言葉の長さ（長さの決まりは無い。予約で文を切ると言い切れない文が並んだので切らない）。言い出してすぐ切れた 3 字未満の切れ端は声に出さない（`minSaid`） |
| 出来事が起きたら、発話中でもその瞬間にマイクを渡し直す | 話している人に見える出来事（`config.triggers` の種類）が起きたら、どこまで言えたかと何が起きたかを渡して同じ人に聞く。話し手は、そのまま言い続ける（`continue`）、言い直す・別のことを言う（`speak`。今の言葉はそこで切れる）、黙る（`pass`）から選ぶ（言い続けを選べない最初の版は、打撃のたびに「ダイチの強」のような切れ端が並んだ）。誰も話していなければ、その出来事が見える席（実況に見えれば実況）へ。話している人には見えない出来事（解説だけに見える骨折など）は、見えた側に割り込むかを聞く |
| 無言が 1 秒続いたら実況へ | 台詞の終わりから 1 秒（`silenceSeconds`）誰も話さなければ実況を呼ぶ。実況がパスしたら、`wait` の秒数か、次の出来事まで呼ばない |
| 割り込み: 相方は発話の瞬間に内容を知り、割り込む・最後まで待って返す・何もしないを選ぶ | 台詞が始まった瞬間に、相方へ全文と長さを渡し、`interrupt`（`after` 秒後）・`reply`（言い終わって 0.15 秒後）・`none` を返させる。割り込まれた側は、次に呼ばれたときに「どこまで言ったところで割り込まれたか」を受け取る。言い終わる前に出来事が起きたら、予定の割り込み・返事は取り消す |

細かい出来事（カメラ・カウント・守り・狙い・体の中の様子）は履歴には入るが、マイクは動かさない（数が多く、呼び出しが増えすぎるため）。同じ 0.3 秒の中の出来事は 1 回の知らせにまとめる。

切れた台詞は、話し手にも相方にも「どこまで言ったところで切れたか」を次の呼び出しで伝える（相方には言い始めた瞬間に全文が届いているので、その先が声に出なかったことを伝え直す）。

## 情報の非対称

- 出来事: 実況は画面で見えること（`for: 実況`）だけ、解説はそれに加えて体の中と選手の狙い（`for: 解説`）。
- 資料の索引: 実況は `docs/commentary/kb/index-announcer.md`（ルール・選手・これまでの中継の結果）、解説は `docs/commentary/kb/index-analyst.md`（ルール・選手・武器の歴史と働き・現実のボクシング・現実の武術）。どちらも開くかどうかは LLM が決める。

## 再現

呼び出しの問いと答えは `<out>/prospective/bN/calls.jsonl` に残る。もう一度動かすと、問いが同じ間は記録の答えを使う（同じ台本になる）。問いが変わった所（資料・決まりを直した）から先だけ LLM に聞き直す。`--fresh` で全部聞き直す。マイクの動きと台詞は `transcript.md`。

## 書き出すもの

`bN.extras.json`（`"style": "prospective"`・`"placed": true`。時刻は話した時刻のまま `tvmerge` が動かさない）。声入れは今までと同じ（`tvshow.ps1 -Stage dub`）。点検は言わない言葉とずれだけ（長さ・コールなどの決まりは無い）。

## 動かし方

```bash
node tools/tvshow/prospective/run.js --card tools/tvshow/cards/wvc-rematch-prospective.json --bout b1
```

`--driver mock` は決まった答えで仕組みだけを確かめる。`--driver relay` は呼び出しをファイルに書いて止まる（CLI が使えないとき、エージェントが答えを置いて続ける）。
