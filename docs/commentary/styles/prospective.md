# 型: prospective（2 エージェントプロスペクティブ制）

実況（`announcer` 立花）と解説（`commentator` 佐伯）を、別々の 2 つの LLM（既定 Haiku）が受け持つ。台本を後から書くのではなく、試合の進行に合わせてその場で話す（2026-11-17、ユーザーの考えた方式）。道具は `tools/tvshow/prospective/run.js`、決まりの値は `tools/tvshow/prospective/config.json`。

## 決まり（アルゴリズム）

| ユーザーの考え | 手順での形 |
|---|---|
| Haiku は 2 エージェント並列 | 席ごとに別の会話（`claude -p --resume`）。互いの考えは見えず、見えるのは相手が声に出した言葉だけ |
| 試合の情報とキーフレームの画像を渡す | 選手の資料（`fighters.md`。両者のプロフィールの前に「本日のプログラムとこの試合に懸かるもの」: 懸かるもの・王座・勝者が得るもの・済んだ試合。中継の記録の `programBriefing`、無い前の記録は札の `stake`・`next`・`belt` から。`stakes.js`）と、その席に見える出来事（実況 = 画面で見えること、解説 = それに加えて体の中・狙い）。出来事の時刻の画面を切り出した画像（`frames/`）は、その時刻を過ぎたら「新しい画面」としてパスを渡し、LLM が Read で見る。まだ起きていない出来事は渡さない（`digest.md` は試合の全部を含むので渡さない） |
| 試合の進行に合わせて話す | 記録した試合の時計 T を進め、出来事・台詞の終わり・割り込み・無言のうち一番早いものを順に処理する |
| マイクは 1 本、同時に話せるのは 1 人 | 話している台詞は常に 1 つ（`cur`）。次の人が話し始めた時点で前の台詞は切れる |
| TV の時間は固定、時間を資源に話す | 毎回「いま T 秒・残り L − T 秒」を渡す。終わりまで `closingSeconds`（10 秒）を切ったら「番組はあと N 秒で終わり、その先は声に出ません」を添え、番組の終わりで切れた台詞は言い切れる文（。！？）までにする（1 文も入らなければ声に出さない。終わりの台詞が「ありがとうござ」で切れた、2026-11-24）。台詞の長さは、声入れと同じ声・速さで実際に読み上げて測る（`Synthesize.ps1`、同じ台詞は `tts.json` の記録を使う）ので、長く話せばそのぶん時間を使う。字数の見積もりは実際より中央値で 1.1〜1.2 倍、長い台詞で 1.4 倍短く、見積もりで進めた最初の版（v1）は声入れで台詞が 1〜3 秒ずつ遅れた |
| マイクを渡されたら履歴を渡して考えて話す。パスも可 | マイクの呼び出し: 前に聞いてから今までの出来事・2 人の台詞（切れた所も）・新しい画像を渡し、`speak`（`seconds`・`text`・`excited`・`handTo`）か `pass`（`wait`）を返させる |
| 考えている間は試合が止まる | 時計は呼び出しの間進まない（考えた時間は動画に入らない） |
| 話したい秒数を予約し、その間好きにしゃべる。秒数制限は無し | `seconds` は話し手の目安で、時間を使うのは言葉の長さ（長さの決まりは無い。予約で文を切ると言い切れない文が並んだので切らない）。言い出してすぐ切れた 3 字未満の切れ端は声に出さない（`minSaid`） |
| 出来事が起きたら、発話中でもその瞬間にマイクを渡し直す | 話している人に見える出来事（`config.triggers` の種類）が起きたら、どこまで言えたかと何が起きたかを渡して同じ人に聞く。話し手は、そのまま言い続ける（`continue`）、言い直す・別のことを言う（`speak`。今の言葉はそこで切れる）、黙る（`pass`）から選ぶ（言い続けを選べない最初の版は、打撃のたびに「ダイチの強」のような切れ端が並んだ）。誰も話していなければ、その出来事が見える席（実況に見えれば実況）へ。話している人には見えない出来事（解説だけに見える骨折など）は、見えた側に割り込むかを聞く。ただし実況がコールする出来事（`config.calls`: ダウン・決着）が解説の話している途中に起きたら、解説の言葉をそこで切って実況にマイクを渡す（同じ人に聞くと、解説は打撃の説明を続けて「ダウン」を誰も言わなかった。2026-11-24、物理 90 の WVC メインで 2 か所。何を言うかは渡さない: マイクの持ち手を役で決めるだけ） |
| 場面の役目だけを添える | `cues`（出来事の種類 → 席 → 一文と、終わりの出来事 `until`）の場面が続く間、その席への毎回の問いに「場面の役目」として添える（届いた 1 回だけでは、話の途中でパスした後に消え、入場の動作の説明だけになった）。何を言うか・どう言うかは書かない。試合の始め（`intro_scene`、入場からゴングまで）は実況に「会場の空気を盛り上げるアナウンスをしてください」（2026-11-25、ユーザーの指定） |
| 無言が 1 秒続いたら実況へ、2 秒に近づいたら警告 | 台詞の終わりから 1 秒（`silenceSeconds`）誰も話さなければ実況を呼ぶ（「N 秒、誰も話していません」とだけ伝える）。パスしても、無音が `maxSilenceSeconds`（1.8 秒）に達したら、席を交互に「ここで N 秒の無音があります」と警告して埋める台詞を書かせる（下の「無音を作らない」） |
| 割り込み: 相方は発話の瞬間に内容を知り、割り込む・最後まで待って返す・何もしないを選ぶ | 台詞が始まった瞬間に、相方へ全文と長さを渡し、`interrupt`（`after` 秒後）・`reply`（言い終わって 0.15 秒後）・`none` を返させる。割り込まれた側は、次に呼ばれたときに「どこまで言ったところで割り込まれたか」を受け取る。言い終わる前に出来事が起きたら、予定の割り込み・返事は取り消す |

休み中の傷のアップ（wound_cam）は、寄り切った時刻（カットの頭から 3.3 秒）にも画面の出来事 wound_zoom を置き、そこで寄った画像を渡してマイクを動かす（寄り始めの画像では傷が小さい）。

細かい出来事（カメラ・カウント・守り・狙い・体の中の様子）は履歴には入るが、マイクは動かさない（数が多く、呼び出しが増えすぎるため）。同じ 0.3 秒の中の出来事は 1 回の知らせにまとめる。

切れた台詞は、話し手にも相方にも「どこまで言ったところで切れたか」を次の呼び出しで伝える（相方には言い始めた瞬間に全文が届いているので、その先が声に出なかったことを伝え直す）。

## 映像とのずれを減らす（2026-11-17、ユーザーの指摘: ワンテンポ遅れた内容を話す）

記録を数えると、台詞が長い（中央値 3.5 秒・最長 13 秒）・出来事のたびに切られて直前の出来事を言い直す（台詞の 3〜5 割）・相方の「話し終わってから返す」が数秒遅れて流れる（1 試合 6〜20 本）、の 3 つでずれていた。

- **いまの様子を渡す**: マイクを渡すたびに、その瞬間のコマ（`frames/now_t*.jpg`）と、その席に見えている記録から作った今の状態（試合の段階・倒れている選手・映っているカメラ・直近 3 秒の打撃の数）を渡す。点の出来事だけでなく今の画面で話せるように。未来は入れない。
- **2 段の発話**: 話す言葉を、今この瞬間に画面で起きていることの一言（`now`）と続き（`then`）に分けて答えさせ、つなげて 1 つの台詞にする（一言が先に声になる）。
- **古い返事を聞き直す**: 話し終わってから返す返事は、決めてから声に出すまでに、その席に見える出来事があったか `replyFreshSeconds`（2.5 秒）より古ければ、言う前にもう一度聞く（決めたとおり言う `continue`・言い直す・やめる）。

## 言葉の終え方・重ねる感嘆・番組の予定（2026-11-17、ユーザーの指定）

- 言葉の途中で切れると聞き苦しいので、話している途中に出来事が来たとき、話し手に今の言葉を終えられる所の候補を、それぞれの「あと何秒」付きで渡す（いま止める・次の区切り（、。！？）・文の終わり・最後まで）。話し手は終える所（stop）と締めの短い言葉（close）と、その後に新しく言うことを選ぶ。どう選ぶかの決まり・例は渡さない（今の話の大事さ・新しく伝えることの大事さと急ぎ・途中で切れる聞き苦しさを比べて、LLM 自身が決める）。言い切ると決めた間に来た出来事はマイクを動かさず、次に話すときの記録として渡す。
- 割り込む側には、相方の言葉の中の区切りが話し始めから何秒目にあるかを渡す（どこで入るかを自分で決める）。
- 思わず出る短い感嘆（exclaim）は、マイク 1 本の順番の外: どの答えにも付けられ、相方の声に重ねて鳴らす（台本の overlap、声入れ Synthesize.ps1 が押し出さずに重ねる）。
- 番組の予定: その時点で決まっている場面（いまの場面があと何秒続くか、この先 40 秒のタイトル・選手の比較・リプレイ・傷のアップ・次のラウンド・勝敗の画面）を毎回渡す。試合の前の場面は始めから、休みの場面はラウンドの終わりから、勝敗の画面は決着から決まっているものとして扱う。
- 実況の人柄として「試合の熱をそのまま声に乗せる人」、解説に「見えたものの理由を語る人」を一文だけ添える（言い方の例は書かない）。

## 同じ言い回しが重ならないように（2026-11-17、ユーザーの指摘: 似た表現・同じ表現が何度も重なる）

言い回しを禁じる指示や言い換えの例は書かない。重なりの出どころを 2 つ取り除いた:

- **出来事の文が台詞の形だった**: 出来事（events.json の text）は、もとは決まり文句で読み上げる中継（`Broadcast`）のための文で、「X のいい左が、Y のこめかみに入った」と強さの形容（`Broadcast.Strength`: いい・重い・強烈な）まで付いていた。2 人はこれをそのまま言い換えて読むので、同じ形の台詞が並んだ。いまは当たりを「当たり: X の左拳 → Y の右前腕（ガードの上）」という事実だけにし（強さは生の情報の速さ・エネルギー・削れで分かる）、ほかの出来事の文からも強さの形容を外す。解説だけに届いていた体の中を一文で言い切った解釈（`condition`・`body_hurt`・`effect`・ダウンの訳）は、生の情報（意識・スタミナ・臓器の打撲）があるときは渡さない。
- **自分が何を言ったかを忘れていた**: 会話を作り直すとき（`turnsPerSession`）に付ける流れが直近 8 行の台詞だけで、前に使った言い回しが見えなかった。いまは、ここまでの 2 人の台詞を全部付ける（1 試合で数千字）。

## 何を言うかは話し手が決める（2026-11-19、ユーザーの指定）

- 席の説明には「中継の時間は限られている。何が大事か・何が面白いか・何を言って何を言わないかは、あなたが判断する」だけを書く。話題の例・大事さの順位・出来事の大事さの札は渡さない（2026-11-18 に足した順位の表と札・小さい出来事でマイクを戻さない仕組みは、誘導なので外した。docs/LLM_CONTENT.md §1）。

## 無音を作らない（2026-11-18、ユーザーの指定: 誰も喋らない間が長く続かない）

- 前は実況がパスすると次の出来事まで誰も呼ばれず、入場・休みに 5〜10 秒の無音ができた。今はパスしても、次に呼ぶ時刻は「`wait` か 1 秒」と「無音が `maxSilenceSeconds` に達する時刻」の早い方。
- 無音が `maxSilenceSeconds` に達したら、席を交互に `pacing.silenceWarning` の警告（「ここで N 秒の無音があります」と事実だけ・pass はしない。話題は挙げない）を渡す。同じ無音への警告は 2 回まで。
- 台本の後にもう一度: 切れた台詞を枠に縮めた・短すぎて捨てたぶん、声に出る台本には無音が残ることがある。声に出る長さで `pacing.findSilences` を探し、残った無音ごとに同じ警告で埋める台詞を書かせる。それでも残った 2 秒以上の無音は標準エラーと `transcript.md` の「無音の警告」に出る。
- 確かめ方: `node --test tools/tvshow/prospective/pacing.test.js`（2 秒以上の無音を見つけて警告が出る・警告と説明に話題の例が無い）。仕上がった動画は声の音声の無音区間を測る（`TV_BROADCAST.md`）。

## 情報の非対称

- 出来事: 実況は画面で見えること（`for: 実況`）だけ、解説はそれに加えて体の中と選手の狙い（`for: 解説`）。
- 資料の索引: 実況は `docs/commentary/kb/index-announcer.md`（ルール・選手・これまでの中継の結果）、解説は `docs/commentary/kb/index-analyst.md`（ルール・選手・武器の歴史と働き・現実のボクシング・現実の武術）。どちらも開くかどうかは LLM が決める。

## 生の情報（2026-11-17、ユーザーの指定: 言葉だけで情景をほぼ思い描けるように）

撮影のとき、描画・音と同じく試合に触れずに生の記録 bN.telemetry.json を書く（games/MiniRing.Arena/TvTelemetry.cs）: 0.1 秒ごとの 2 人の姿勢（頭・両拳の位置、腰の高さ、前傾・横の傾き、相手への向き、相手との距離、スタミナ・意識・ダウン、いまの技と守り）、当たりごとの中身（打った側・技・手足・打たれた場所の細かい呼び名・急所・速さ・運動量・エネルギー・その歩で削れたセルの場所と材質・打たれた側の積み上げた損傷と臓器の打撲）、骨折・切断。長さは選手の身長に合わせた人の大きさの cm。

細かい場所の呼び名は辞書 TvBodyWords（頭: おでこ・目・眉間・鼻・頬・口・あご・こめかみ・耳・後頭部・頭のてっぺん、胸: 鎖骨の下・胸・胸の真ん中・みぞおち・脇腹・わき・背中、腰: へその上・下腹・腰、手足は部位の名前）。部位の箱の中の点（+X が本人の左・+Y が上・+Z が前）から引く。

マイクを渡すたびに「生の情報」として、前に聞いてから今までの当たり・骨折・切断と、直近 1 秒の 2 人の動き（頭の動き・拳の高さと伸び・腰の沈み・傾き・向き・距離）、これまでに削れた所を、言葉と数字で渡す。解説には体の中（意識・臓器の打撲・運動量とエネルギー・臓器の削れ）も渡し、実況には外から見える損傷だけ渡す。

## 読む量とセッションの数

呼び出しのたびに claude -p を起動していた最初の作りは、起動 1 回が 1 セッションに数えられ（1 日 2,000 回）、毎回 Claude Code の既定の指示・CLAUDE.md・会話の全部を読み直して 1 回 8 万トークンを読んでいた（今日のプロスペクティブ制だけでキャッシュ読み込み 2.6 億トークン）。いまは席ごとに claude を 1 つ起動したまま問いを流し込み（--input-format stream-json）、指示を席の説明だけに差し替え（--system-prompt-file）、設定・MCP を読まず（--setting-sources ""・--strict-mcp-config）、turnsPerSession（12）回ごとに会話を作り直して、作り直した最初の問いにそれまでの流れを付ける。第1試合で 1 回 1.2 万トークン・6 セッション。

## 再現

呼び出しの問いと答えは `<out>/prospective/bN/calls.jsonl` に残る。もう一度動かすと、問いが同じ間は記録の答えを使う（同じ台本になる）。問いが変わった所（資料・決まりを直した）から先だけ LLM に聞き直す。`--fresh` で全部聞き直す。マイクの動きと台詞は `transcript.md`。

## 書き出すもの

`bN.extras.json`（`"style": "prospective"`・`"placed": true`。時刻は話した時刻のまま `tvmerge` が動かさない）。声入れは今までと同じ（`tvshow.ps1 -Stage dub`）。点検は言わない言葉とずれだけ（長さ・コールなどの決まりは無い）。

## 動かし方

札 1 枚・コマンド 1 回で、種選び → 撮影（生の記録・傷のアップ・皮膚のあざ）→ 実況・解説（Haiku だけ）→ 声入れ → 結合まで（札の `"commentary": { "writer": "prospective", "model": "haiku", "parallel": 2 }`。例: `tools/tvshow/cards/wvc-oneshot.json`）:

```bash
powershell -ExecutionPolicy Bypass -File tools/tvshow/tvshow.ps1 -Card tools/tvshow/cards/wvc-oneshot.json
```

実況・解説は台本の無い試合を `parallel` 本ずつ並べて動かし、止まった試合は 1 回だけやり直す（記録 calls.jsonl の答えを使うので、止まった所から先だけ聞く）。記録は `<out>/prospective-bN.log`。1 試合だけ動かすなら:

```bash
node tools/tvshow/prospective/run.js --card tools/tvshow/cards/wvc-rematch-prospective.json --bout b1
```

`--driver mock` は決まった答えで仕組みだけを確かめる。`--driver relay` は呼び出しをファイルに書いて止まる（CLI が使えないとき、エージェントが答えを置いて続ける）。
