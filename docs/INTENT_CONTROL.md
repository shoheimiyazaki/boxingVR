# 意図で動かす操作

## 計画（2026-11-13）

作業 A の後に作業 B を進める。体の位置・姿勢には触らず、意図 → 技の選択 → `FighterCommand` の経路という三段を保つ。

| キー | 意図 |
|---|---|
| 矢印 / WASD | カメラ基準の前後左右への移動（向きは相手のまま） |
| J / 右クリック | 弱攻撃（前の手） |
| K / 左クリック | 強攻撃（後ろの手） |
| Space | 回避。方向なしはガード |
| R | ラウンドをやり直す |

既定は意図操作にし、`--control classic` で従来の操作を残す。

| 意図と状況 | 選択 |
|---|---|
| 弱 / 強 | ジャブ / ストレート |
| 横＋攻撃 | 同じ手のフック |
| 近距離＋攻撃 | ボディ、横方向ならボディフック |
| 後ろ＋攻撃 | アッパー |
| 前＋強 / 遠距離 | ストレートと踏み込み |
| 後ろ＋回避 | スウェー |
| 横＋回避 | 押した方向へサイドステップ |
| 前＋回避 | `OpponentRead` と拳速度で読み、`DefenseBook` の効き目から選択 |
| 回避直後＋攻撃 | 回避の表のカウンターを優先 |

`TechniqueExecution` を共有の純粋な経路計算とし、拳の溜め・頭の移動・胴のひねり・バネ伝達・防御経路を `BoxerBot` から移す。判断と乱数の呼び順は変えない。リファクタ前の同種試合のチェックサム列を保存し、変更後と全件比較する。一致すれば LogicVersion 16 を維持する。

`IntentControl : IFighterControl` はキーに依存しない `FighterIntent` を受け取る。押下でその歩から予備動作を始め、保持中に深くし、離すと打つ。技途中の押下は一つだけ保持し、`Combo` の接続と経路進行から受付を決める。回避は攻撃と先行入力を中断する。調整量は `IntentTuning` に置く。

記録は解釈後の指令を保存する。形式を v4 にし、従来保存されなかった `Spring` と `TwistBias` も保存する。v3 の読み込みを維持する。台本の操作は Arena の `intentvideo` で同じ解釈部へ流す。

デスクトップの移動入力はカメラのヨーからワールド方向に変換して指令へ入れる。記録には変換後の方向が保存されるため、再生時にカメラの状態は不要。技選択に使う方向はキーの方向をそのまま使う。

## 実装と使い方

- `IntentKeyboardControl`: キーとマウスを `FighterIntent` へ写す。ラウンドが変われば操作の状態を作り直す。
- `IntentControl`: 押下・保持・解放・一つの先行入力を管理する。攻撃と回避の選択はここで行う。保持時間はゲームの dt だけで進める。
- `TechniqueExecution` / `PunchAction`: ボットと共有する実行部。構え、拳、頭、逆ひねり、体のバネを拳へ渡す期間、防御の拳と頭を評価する。
- `CounterResponse`: ボットと共有する既定の返し。回避の表に候補があれば優先し、押した攻撃の手がない場合は通常の技へ戻る。
- `IntentScript`: 時刻順の押下状態を検証して読み込む。未知の JSON 項目、逆順・重複時刻、有限でない時刻、範囲外の方向は拒否する。

```powershell
dotnet run --project games/MiniRing.Desktop -c Release
dotnet run --project games/MiniRing.Desktop -c Release -- --control classic
dotnet run --project games/MiniRing.Arena -c Release -- intentvideo --script docs/arena/intent_demo.json --blue docs/arena/intent_opponent.json --out docs/video/gen10_intent_demonstration.mp4
```

台本は `at` 秒以降の状態の配列。`x` は右、`y` は前、行動は `light` / `heavy` / `evade`。省略した方向・行動は 0 / false（離す）。動画は速度 1、30fps、1/60 秒のホスト歩で意図を評価し、デスクトップと同じ解釈部を呼ぶ。`.mrrep` も出し、動画生成後に自動照合する。画面には押下状態と選ばれた技を表示する。

## 検証結果と制約

物理の版は 18、ボットの判断の版は 16 のまま。swarmer 対 champion（種 3/17）各 20 秒の全 2,400 ホスト歩で、切り出し前と同じチェックサムになる fixture を残した。意図操作の記録は別に全 480 歩のチェックサムを照合する。

固定値は同じ CPU／ランタイム環境での抽出検証専用。通常テストでは同じ環境で 2 回実行して比較する。今回の生成環境は Windows 10.0.26200、win-x64、.NET 10.0.11（SDK 10.0.400）、AMD64 Family 23 Model 96 Stepping 1。今回の固定値と明示比較する場合:

```powershell
$env:MINIRING_VERIFY_EXTRACTION = '1'
dotnet test tests/MiniRing.Tests -c Release --filter FullyQualifiedName~BotExecutionBaseline
```

18 歩保持した右手のピークは 2.015 m/s、1 歩の短押しは 1.897 m/s。前へ歩きながら保持すると 2.284 m/s（種 43、1 秒構えた後、解放後 18 歩で測定）。物理モデルへの加算倍率はない。

動画は通常 champion 相手と、操作を見るための低頻度ジャブ相手を作成。後者でワンツー・溜め・フック・スウェー・沈む回避・ガードを目視した。両動画の記録は各 14/14 チェックサム一致。検証記録は [arena/codex_2026-11-13.md](arena/codex_2026-11-13.md)。

## 第 6 回の改善（2026-11-14、実際に触ったユーザーの感想から）

感想の原文: 「カメラが自分を追ってほしい」「ラジコンのような相手基準でなく、カメラ基準で動きたい」「スリップ・ダッキングが遅い。頭を思い切り落として、重力も使って」「ジャブの引きが遅い。連打したい。短押しは軽く速く、少し長いと体重の乗った押し出し」「ジャブ・ジャブ・ストレートのように押した順に出したい」「ダッキングからは胴、スリップからは逆の手のフック。回避で沈んだ・ひねったバネを使って」「横＋回避で素早く横へ」。

| キー（意図操作） | 意図 |
|---|---|
| 矢印 / WASD | **カメラ基準**の移動。体は相手を向いたまま、足の運びで歩く |
| J / 右クリック | 弱（前の手）。短押しは軽くはたく速いジャブ、押して離すと溜めて体重の乗った押し出し |
| K / 左クリック | 強（後ろの手）。同様 |
| Space | 回避。方向なしはガード。前＝スリップ／ダッキング／ウィービング、後ろ＝スウェー、**横＝素早い横ステップ** |
| 回避を押している間の J / K | その回避の姿勢からの打ち返し（ダッキング＝ボディフック、スリップ＝逆の手のフック） |
| R | ラウンドをやり直す |

（`run-keyboard.cmd` はこのブランチに無いので、キーの説明は `run.cmd` の冒頭コメントとデスクトップのウィンドウのヘルプ文に書いた。）

### 1. 追従カメラ（描画だけ）

`CameraFollow`（ゲーム側の純関数）と `FollowCameraRig`（Desktop）。注視点はプレイヤーから相手へ 3 割寄せた点、向きは「相手からプレイヤーを結ぶ線の外側」へ、どちらも減衰のバネ `1 - exp(-rate·dt)`（rate 3.2/s、時定数 0.3 秒、フレーム間隔に依らない）で追う。実時間の dt で動かすので試合の計算には入らない。中ボタンで回した分は「後ろからのずれ」として保つ。

### 2. カメラ基準の移動

ホストが入力の段階で、キー（カメラの右・奥）を `CameraFollow.ToWorld` でワールドの水平方向へ直し、`FighterIntent.World` に入れる。`IntentControl` は移動をそのままワールドの向きの指令にし、技の選択（前後・横）だけ体が相手へ向いた座標へ直して読む。向き（`FaceDirection`）は常に相手。記録は指令（`MoveWorld`）を持つのでカメラの状態は記録に入らず、再生は一致する（テストで全チェックサム照合）。台本（`IntentScript`）は従来どおり相手基準の `x`/`y`。

### 3. 速いスリップ・ダッキング（重力を使う）

原因を測ると、頭を下げる量の 6 割を腰のヒンジ（上体を前へ倒す）で受け持ち、膝・股は 4 割だった。しかも腰を落とす力は「脚が下向きに引かない・落ちる速さに粘りのブレーキが掛かる」ので、腰の沈みは自由落下よりずっと遅かった。

- 体: 目標の腰が今より低いとき、脚が伸ばす力を抜き（ブレーキの粘り `HoverKd` を `DropBrakeKeep` まで減らす）、股・腹が腰を下へ引く（`DropPull`）。効きは目標との差に連続（`DropReleaseDepth`・`DropReleaseDeadband`）。`HipHingeShare` 0.6 → 0.4（膝を折る分を増やす）、`MaxCrouch` 0.28 → 0.3。0.2 まで下げると 0.2 秒で 8.4 cm 沈んだが、ボットの「しゃがんでいる時間の割合」が 29.6 %（テストの上限 28 %）になったので、ボットを変えすぎない 0.4 にした。`PhysicsVersion` 20。
- （試して外した案）脚の IK の目標を「目標の高さにある腰」から解く案は、沈みが速くならなかった（0.2 秒 4.7 cm）ので戻した。効いたのはヒンジと膝の配分（0.2 秒で 5.3 → 8.4 cm）。
- 操作: 守りの表の頭の沈み・横ずれに `IntentTuning.DropDepth`（1.3）・`SlipReach`（1.3）を掛ける。回避を押し続けても、守りの時間を過ぎたら頭を構えへ戻す（`RecoverSeconds`。深い姿勢を保ち続けると上体が倒れ、0.9 秒でダウンになったため）。倍率 1.6 では直立度の最小が 0.50（ダウン判定は 0.4 を 0.15 秒）で余裕が無いので 1.45 にした。脚の力を抜く不感帯は 0.8 cm だと剣の守りのドリルが自分の腿を斬る量を増やしたので 1.2 cm（`DropReleaseDepth` 2 cm）にした。
- 守りの表（`DefenseBook`）は変えていない。ボットは体の変更（ホバー・ヒンジ）だけを共有する。

### 4. 連打（ジャブの戻りと先行入力）

- 技の時間は溜め（保持時間）に応じて連続に変わる: 溜めなしの短押しは `TapDurationScale`（0.62）倍で速く出て速く戻り、`FullLoadSeconds`（0.2 秒）溜めると 1 倍。分岐ではなく溜めの量の補間で、威力の倍率は掛けない（重さは体のバネの溜め・打ち出しで物理が決める）。
- 同じ手の次の技は、前の拳が戻り始めたら（`PunchSpec.OutboundShare`）受け付ける。反対の手は前の技の半分で始められる（`AlternateGap`）。
- 先行入力は 1 個から、押した順に並ぶ最大 4 個（`BufferCapacity`）の待ち行列にし、0.5 秒（`BufferSeconds`）で捨てる。J・J・K は `Jab, Jab, Cross` の順に出る（`StartedTechniques`）。`LastCombination` は打ち出した列の末尾が名前のある型（`Combo.All`）と一致した最長のもの。型の一覧自体は増やしていない（ボットの選択肢に影響させないため）。

### 5. 回避の姿勢からの打ち返し

回避を押している間（と離してから `CounterSeconds`）の攻撃は、その回避の姿勢から選ぶ（選択だけ。経路はボットと共有）。

- ダッキング: ボディフック（弱＝前の手、強＝後ろの手）。沈んだ脚のバネ（屈んだ分）が `TransferBodyMotion` で拳へ移る。
- スリップ・インサイドスリップ: 頭を寄せた側と反対の手のフック。回避の間、胴を反対の手側へ `CoilRadians`（22°）巻き込み（`TwistBias`）、打つときに解く。巻き込みの満ち具合が打ち返しの `Load` になり、胴のひねりの戻りが拳へ乗る。
- それ以外の回避は従来どおり、回避の表のカウンター、なければ `CounterResponse`。

### 6. 横ステップ

横＋回避は `Defense.SideStep`（守りの表の足の横 1・後ろ 0.2、0.35 秒）。足の運びの目標が横へ動き、押した側へ素早く出る。体は相手を向いたまま。

### 検証（数値は `IntentFeelTests`。シード固定）

| ウィービング 0.2 秒の頭の沈み | 2.3 cm | 4.3 cm |
| スリップ 0.2 秒の頭の横ずれ | （未測定。沈みは 2.0 cm） | 6.7 cm |
