# WVC テレビ中継の動画（作り方と決まり）

ボット同士の試合を、作中の世界のテレビ中継として動画にする。撮影・カメラ・リプレイ・実況の骨組みの下書き・声入れ・点検・結合は道具が決まった手順で行い、**人（エージェント）が書くのは下書きに足す台詞（打ち合いの実況・問いと答え・解説の理由）だけ**。足す台詞なしでも下書きだけで動画にできる。

## 1. 位置づけ（名前）

| 名前 | 何か | 動画に出すか |
|---|---|---|
| **Voxing** | スポーツの名前（voxel と boxing） | 出す（角の札・実況） |
| **WVC**（Wonderful Voxing Council） | 団体の名前。動画は「WVC の大会のテレビ中継」 | 出す（ロゴ・題字・大会名） |
| **VGV**（Very Good Voxing） | このゲームの名前 | **出さない**（野球中継にゲームの名前が出ないのと同じ） |

動画は作中のテレビ番組なので、「ボット」「物理」「ダメージの数値」のようなゲームの裏側の言葉も出さない。

### 1.1 団体（WVC と VFC、2026-11-18）

中継の道具（画面・紋章・音・照明の雰囲気・下見の点数・台本の資料と下書き・LLM のプロンプト・札）は、**団体のファイル**（`games/MiniRing.Arena/Orgs/<id>.json`）で作り分ける。コードに団体名の分岐は無く、値で切り替わる（CLAUDE.md §1.3 と同じ考え方）。体・物理・材料は団体によらず同じで、違うのは中継の見せ方（と、試合の決まり・場の形は別の仕組み: `MatchRules`・`RingLayout`、計画は `docs/plans/VFC_PLAN.md`）。`Organizations`（読み込みと検査）・`Organization`（値）。

| | WVC（Wonderful Voxing Council） | VFC（Voxel Fighting Championship） |
|---|---|---|
| 競技 | Voxing | Voxel Fighting |
| 紋章 | 金の王冠・赤い盾・月桂樹の「WVC」（`WvcEmblem`） | 赤いボクセルの六角形の枠・灰の金網・クリームの「VFC」・黒帯（`VfcEmblem`。手本 `docs/images/vfc_logo_reference.png`） |
| 画面の色 | 金・白・濃紺 | クリーム `#F3E9D6` 前後・黒（赤 `#E8231F` は紋章と罫の飾り） |
| 合図の音 | ゴング（`GongSound`） | 低く太いホーン（`HornSound`） |
| 会場の雰囲気 | 明るい昼の部屋（今のまま） | 暗い会場、檻の真上に強いスポット（`ArenaMood`） |
| 歓声 | 今の音 | 反応 1.2 倍・ざわめき 0.6 倍 |
| 決着の言い方 | K.O.・判定・ダウンとカウント | 「決着」（死だけ）・両者生還の引き分け・ダウンは言わない・数えない |
| 下見の点数 | ダウンの応酬・逆転・K.O. | 長く持つ・後半の死・逆転・両者が深く傷む。序盤の即死・両者生還は低い |
| 語り | 品のある実況と、理由を言う解説 | 熱く荒い実況と、「どこが壊れたか・何が残っているか」の解説 |

団体のファイルの欄: `id`・`name`・`logoText`・`sport`・`emblem`（紋章の id）・`colors`（`accent`・`accentLight`・`accentDeep`・`text`・`muted`・`ink`・`voxelTop/Bottom/Side`）・`arenaMood`（`ambient`・`key`・`lamp`・`window`・`cageSpotIntensity`・`cageSpotColor`・`vignette`・`exposure`）・`bell`（`gong`|`horn`）・`crowd`（`reactionGain`・`ambienceGain`）・`countsDowns`・`text`（冒頭の決まりの帯・決着の大きな文字・判定の行）・`rulesSheet`（台本の資料の「決まり」）・`draft`（下書きの言い回し）・`lint.callWords`（点検が決着・倒れのコールと見なす言葉）・`drama`（下見の点数の重み。式は `TvShowRules.Drama`）・`commentary`（プロンプトの団体の紹介・語り口・コールの言い方）・`show`（番組の型の id。§1.2）・`cast`（放送席。§1.2）・`text.liveTag`・`text.strapline`（試合中の札の言葉。省略可）。足りない欄・型違い・範囲外は、どのファイルのどの欄かを書いた例外で止まる。

- `--org <id>`（既定 wvc）: `video`・`tvscout`・`tvdraft`・`tvdigest`・`tvlint` が受け取る。`video` は events.json に `org` を書き、`tvdraft`・`tvdigest`・`tvlint` は `--org` が無ければ events.json の `org`（無ければ wvc）を使う。
- 札の `"org"`（既定 `"wvc"`）: `tvshow.ps1` がすべての arena の呼び出しに `--org` を渡し、`write-commentary.ps1` がプロンプトの `{{org}}`・`{{orgName}}`・`{{sport}}`・`{{orgIntro}}`・`{{announcerTone}}`・`{{analystTone}}`・`{{callThing}}`・`{{callExamples}}` を団体のファイルで埋める。`event` を省くと団体の略称（WVC・VFC）。例 `tools/tvshow/cards/vfc-test.json`。
- 選手の所属: 名簿のキャラクターのファイルの `"org"`（既定 wvc）。武器・グローブ以外のはめる物の選手（daichi・edgar・gaston・jin・joao・konrad・sean・tsuyoshi・vikram）は vfc。
- 近道（見せ方だけ。物理・材料には響かない）: 下見の点数の重み・歓声の倍率・照明の倍率とスポットの強さ・色は、見て決めた値で測った物ではない。VFC のホーンは合成で、実物の録音から測っていない（ゴングと違う）。VFC の紋章は手本の絵の描き写し（ボクセルの格子へ丸めた近似。字の斜めは 1 行 0.05 マスのずらし）。照明は `ArenaLook.Lighting(center, size, surface, mood)` と `ScreenFinishFor(mood)` を作ってあるが、`BoxingGame`（`_lighting`・`BuildPostProcess`）はまだ雰囲気を渡さない（`--org vfc` でも試合の画は WVC の明るい部屋）。
- 試合の決まり（ダウンを数えない・死だけが決着・体は治らない）と六角形の檻、暗い会場の照明の呼び出し（`BoxingGame` が `ArenaLook.Lighting(..., mood)`・`ScreenFinishFor(mood)` を呼ぶ）は、この仕組みの外（別の作業）。`--org vfc` が変えるのは見せ方（画面・音・語り・点数）だけ。

### 1.2 番組の型（団体ごとに別の番組、2026-11-18）

> 「中継中の UI や選手紹介や対戦カード表示、その他の構成自体を各団体で全く違うものにして、完全に別系統の大会・テレビ番組であることを強調してください。」（ユーザー）

番組の構成（試合の前の場面の並び・試合中の画面・休み・リプレイの出入り・決着の画面・放送席）は、団体のファイルの `"show"`（番組の型の id）で差し替える。型は `ITvShow`（`games/MiniRing.Arena/Shows/TvShow.cs`）で、`ShowFormats` が id から作る。`VideoMaker` は型が返す**場面の並び**（`ShowScene`: id・記録の出来事の種類・秒数・説明・背景のカメラ・ホーンの時刻）を順に流し、各場面の絵は型が描く。コードに団体名の分岐は無い。描画と音の合図だけで、試合には響かない。

| | WVC（`WvcShow`。描画は `TvShowGraphics`、今までの中継そのまま） | VFC（`VfcShow`） |

| 位置づけ | 格式のある地上波のボクシング中継 | 深夜の有料配信（PPV）のケージファイト |
| 作り | 金の細い罫・菱形の飾り・中央揃え・角丸の板・表 | 黒・クリーム・赤、角張ったボクセルの字（`BlockFont`）、斜めの切り口（平行四辺形）、赤い斜線 |

| 放送席 | 実況 立花・解説 佐伯 | 実況 久世（深夜の格闘配信を 15 年）・解説 鷹宮（元救命救急医のケージドクター） |

- **VFC の試合の前**（`VfcShow`）:
  - コールドオープン: 暗い檻を外から回って映し（`ShowBackdrop.CageOrbit`）、字幕「レフェリーなし」「ダウンなし」「どちらかが死ぬまで」が 1 行ずつ。3.4 秒に紋章が揺れながら大きく入り、ホーン（`HornSound`、大きさは試合の始まりと同じ）が同時に鳴る。
  - ファイトポスター: 全身の絵（`CharacterPortraits.Build`。試合の体のボクセルから写す）を左右に大きく、間を赤い斜めの切り口で割る。名前・武器・大会名・何試合目・「今夜のメインイベント」。WVC の比較の表は使わない。
  - 入場: 低いカメラ（`TvDirector.Ringside`）で選手を映し、左下の斜めの帯に名前・本名と国・武器・身長・体重・戦績・口癖（名簿の資料の `quote`）。リーチは名簿に無いので出さない。
  - フェイスオフ: 2 人の顔の窓（`FaceCam` の別の置き場。`ArrangeFaceOff`）を画面いっぱいに左右へ、中央に FACE OFF。終わりのホーンは、そのまま始まる第 1 ラウンドの合図（試合のホーン）が担う。
- **WVC の部品**（`Shows/Wvc/WvcShowParts.cs`、作業 D・E。入力 → 2D の重ね絵の純粋な関数）:
  - リングアナウンサーのコール（`RingAnnouncerCall`、赤 → 青の各 6 秒、選手の比較の表の後）: 下は、そのコーナーを低い所から映す生の絵（両者は自分のコーナーで構えて立つ）、画面の下 1/3 に金の縁の板。「赤（青）コーナー」・流派と拠点・戦績・体重・本名・呼び名が順に出る。記録には `call`（`prefight` 付き）の出来事「リングアナウンサーが赤コーナーの〇〇をコール」。
  - ラウンドの採点の札（`RoundScoreCard`、休みの最初の 7 秒）: ラウンドごとの「与えたダメージ」（判定と同じ `Condition.TotalDamage` の差分）と、そのラウンドに当てた打撃の数（`RecentHits`・`WeaponHits` の全部。閾値なし）、合計。置き場は右の顔の窓の上（窓・窓の下の名札・字幕に重ならない）。記録には休みの頭に `board` の出来事（第 N ラウンドまでの数字）。
  - 王座のベルト（`ChampionBelt`）: 札の試合に `"belt": true`（既定 false）があり、勝者がいる（引き分けでない）とき、勝敗の画面で勝者の名前の上、勝者の帯の上に出る。ベルトのために決まり手の大きな字（K.O.）を 0.7 倍にして少し上げる。`tvshow.ps1` が `--belt on` を arena に渡す。
- **試合の前の生の絵は影の試合で描く**（2026-11-18）: 生成直後の体は腕を真横に広げた姿勢（`Fighter.Spawn`）で、本番の試合は試合の前に進められない（チェックサム・記録の再生を壊す）ので、試合の前の場面（コールドオープン・入場・フェイスオフ・WVC の冒頭とコール）の 3D の背景は、同じ種・両コーナー・決まり・雰囲気の別の `BoxingGame`（影の試合、`BoxingGame.StepStage`）で描く。影の試合はボットも入力も読まず、構えて立つ指令（`FighterCommand`: 相手の方を向き、いつものガードの位置に両手を置く。体はバネで追う。姿勢は書き込まない）だけを出し、映し始める前に 1.5 秒進めておく。入場とコールの場面（`ShowScene.Stage` = `Corners`）では両者は自分のコーナー（休みと同じ `RestCorner`）へ歩いて構える。試合の前の場面が終わったら影の試合は捨てる。本番の試合の最初の数コマは（生成直後の姿勢から始まるので）腕が構えへ向かう途中が映る。
- **窓の外の空は団体の雰囲気を受ける**: 窓の光る面（`LivingRoom.SkyColor`）は `ArenaMood.Window` で昼の空と夜の空（ほぼ黒の紺）を混ぜる（1 以上は昼の空のまま = WVC の部屋は今まで通り、VFC の 0.1 は夜）。描画だけ。
- **体の図**（`ShowBodies`・`BodyFigure`）は見えている欠損だけ（CLAUDE.md §1.7）: 削れた肉の割合（`BoxerBody.Muscle`）で赤み、骨折はひびの入った暗い赤、切断は輪郭だけ（先も無い）、潰れた目は赤い点、死んだ敗者は灰に沈める。折れた・切れた部位は `Broadcast` が出来事から覚えている物を読む（`LimbOf`）。意識・臓器・スタミナは出さない。休みの看板の傷の言葉と、記録の `board` の出来事は同じ物から作る（実況が見えている物と矛盾しない）。決着の画面の図（`VfcShow.ResultFigure`）は、死で決まった試合の負けた側を決着の結果（`DeathPhrase`）からも「死んだ側」と見なして全体を灰色に沈め、死因が首なら頭を輪郭だけにする（体の図の読み手が頭の離断を知らなくても、決着の言葉と図がずれない）。
- **記録（events.json）**: 試合の前の場面の出来事には `"prefight": true` が付く（`Broadcast.NoteScene`）。WVC の `program`・`opening`・`tape` も同じ。台本を作る道具は場面の名前を知らなくても「試合の前の場面」と分かる（`run.js` の画面の予定・マイクを渡す出来事・切り出す画像・「最初から決まっている場面」、`TvDigest` の区間、`TvDraft` の選手紹介の時刻（入場があれば入場の頭））。休みの看板が出る型は、休みの頭に `board` の出来事（看板の中身）を書く。`outcome.deathPhrase` は死で決着した試合の言葉で、プログラムの済んだ試合の行（`cause`）に使われる。
- **放送席**（団体のファイルの `cast`）: 席（`announcer`・`commentator`）ごとに名前・席の役の 1 文（`role`）・人物の説明のファイル（`persona`。経歴と役割と場だけ: `docs/LLM_CONTENT.md` §1）・声（`Synthesize.ps1` の `speakers` と同じ形）。`run.js` は席の名前・役・人物（「人物」「場」の節だけ）・声を団体のファイルから読み、読み上げの長さも団体の声で測り、台本の `speakers` に書く。`write-commentary.ps1` は `{{announcerName}}`・`{{analystName}}`・`{{announcerPersona}}`・`{{analystPersona}}` を埋め、台本に `speakers` を足す。WVC の声は今までの既定（立花 Ichiro +30% +5%、佐伯 Ayumi +15% -2%）と同じ値。VFC は実況が Ichiro の低い声（+22% -12%）、解説は Haruka（+8% -8%）で、WVC の 2 人と聞き分けられる（この PC に入っている声は Ayumi・Haruka・Ichiro だけ）。
- **WVC の変更（作業 E、2026-11-18、意図した変化）**: 冒頭にリングアナウンサーのコール 12 秒・休みに採点の札・（札の `belt`）勝敗の画面のベルトが足され、試合の前の絵は影の試合になった。試合そのもの・試合の記録の再生は変わらない（影の試合は別の `BoxingGame`）。以下は作業 C の時点（これらを足す前）の確かめ方: 変更の前と後で、`video --tv on --facecam on --render off` の全コマ（冒頭・表・試合中・休み・リプレイ・決着）の「カメラ行列＋文字＋図形」のハッシュを並べて比べた（プログラムあり・なしの 2 試合、3328 コマ全部一致）。events.json は `prefight` の印を除いて同じ。音は WVC の場面にホーンを足さないので同じ。`ShowFormatTests.Wvc_PreFight_IsTheLegacyOpening` は WVC の型が `TvShowGraphics` と同じ図形を返すことを確かめる。
- 近道: 体の図は 11 の四角（頭・胸・腰・腕 2×2・脚 2×2）で、手足の太さ・長さは体格を写していない。入場の帯の行の位置・場面の秒数・ポスターの斜線の傾きは見て決めた値。VFC のフェイスオフの窓は正方形のまま（台形ではない）で、窓の上下の黒い帯の間に置く。字幕（コンビネーション・守りの名前）の高さは型が決める（`CaptionY`）。VFC の休みの看板は休みの頭から 8 秒の間だけで、リプレイの最中は出ない（リプレイは別の画面。看板を出す間のカメラの切り替えは `TvDirector` のまま）。

## 2. 作り方

```powershell
# 1. 撮影と台本の資料（種の選び・撮影・要約）。台本が無ければここで止まり、書く場所を知らせる。
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\wvc-ishu.json
# 2. 台詞を書く。札に "commentary": { "writer": "llm", "model": "haiku" } があれば、台本の無い試合は LLM が全部の台詞を書く（§4.4。
#    1 回 = 1 テイク。-Stage write で全試合の新しいテイク）。無ければ <out>\bN.digest.md と bN.draft.json を読み、<out>\bN.extras.json を書く（スキル tv-commentary、§4.3）。
#    エージェントなしで作るなら、札に "autoCommentary": true（下書きだけを台本にする。下書きは実況と解説の 2 人）。
# 3. もう一度 1 を回す: 台本（下書き＋足す台詞 → bN.script.json）→ 声入れ（bN_live.mp4）→ 点検 → 結合（broadcast_full.mp4）→ 送れる大きさの部分（broadcast_partN.mp4）。
```

段だけを回すときは `-Stage scout | render | digest | write | dub | package`。撮り直しは `-Force`。生の中継は `-Stage liveprep | live`（§8）。

### 札（card JSON）

```json
{
  "event": "WVC 異種格闘技王者決定戦",
  "rounds": 3,
  "break": 20,
  "out": "docs/video/wvc-ishu",
  "scoutSeeds": [1, 2, 3, 4, 5, 6, 7, 8],
  "partLimitMiB": 29,
  "bouts": [
    { "red": "marcus", "blue": "akira", "seed": "auto", "bout": "第1試合" }
  ]
}
```

- `red` / `blue`: 名簿のキャラクターの id（`games/MiniRing/Characters/roster/<id>.json`）。武器・はめる物・体格・顔・名前はキャラクターの値。
- `seed`: 数字か `"auto"`。`"auto"` は下見（`scoutSeeds` の種を全部回す）で一番見ごたえのある種を選び、`<out>\card.resolved.json` に**選んだときの物理・ボットの版と一緒に**残す。版（`Fighter.PhysicsVersion`・`BoxerBot.LogicVersion`）が変わると同じ種でも別の試合になるので、版が違えば選び直す（撮った動画は `-Force` で撮り直す）。
- `belt`（試合ごと、既定 false）: true なら、WVC の勝敗の画面で勝者の名前の上に王座のベルトを出す（引き分けでは出ない。VFC は使わない）。例 `tools/tvshow/cards/wvc-title.json`。
- `rounds`・`break`: 30 秒のラウンドの数と、間の休み [s]（既定 25。解説の問いと答えが入る長さ）。休みを延ばしても休みの間に治る量は標準（10 秒 × 150 個/秒）と同じ（`VideoMaker.TvRules`）。

### 大会のプログラムとトーナメント（`tools/tvshow/cards/wvc-boxing-tournament.json`）

札の `bouts` の順がその日のプログラム。試合は札の順に 1 つずつ「顔ぶれを決める → 下見 → 撮る」と進む。

```json
{ "event": "WVC ボクシングトーナメント", "program": "WVC ボクシングトーナメント",
  "bouts": [
    { "red": "marcus", "blue": "ramon", "bout": "準決勝第1試合", "stake": "勝者は決勝へ", "next": "決勝進出" },
    { "red": "yoandry", "blue": "dmitri", "bout": "準決勝第2試合", "stake": "勝者は決勝へ", "next": "決勝進出" },
    { "red": "winner:1", "blue": "winner:2", "bout": "決勝", "stake": "勝てば優勝", "next": "優勝" } ] }
```

- `red` / `blue` に `"winner:N"` と書くと、N 試合目の勝者（`bN.events.json` の `outcome`）がそのコーナーに立つ。N 試合目を撮るまで決まらない。引き分けは与えたダメージの多い側（`outcome.lead`）が勝ち上がる（大会の決まり）。
- `program`: 「本日のプログラム」の表の見出し（無ければ `event`）。`stake`: この試合に懸かるもの（表の下の帯と実況）。`next`: 勝った人が得るもの（勝者のコールの後に「〇〇、決勝進出！」）。
- 道具は試合ごとに `bN.program.json`（その試合の時点の表: 済んだ試合の勝者と決まり手・この試合・まだの試合）を書き、`video --program` に渡す。前の試合を撮り直して表が変わったら、その試合も撮り直す。顔ぶれが変わった試合は種を選び直す（`card.resolved.json` に種と顔ぶれを残す）。
- 冒頭: 表（`TvProgram.Seconds`。見出しの台詞 約 2.6 秒＋済んだ試合ごと・懸かるもので 1 行 4 秒（声の実測）、最短 6 秒）→ いつものタイトル（7 秒）。実況の下書きが表の間に「本日のプログラムです」・済んだ試合の結果・懸かるものを言い（大会名は見出しに出ているので言わない）、選手紹介は両コーナーの板が出てから。

- **冒頭（7 秒。プログラムがあればその前に「本日のプログラム」の表、両者にプロフィールがあればその後に「選手の比較の表」14 秒: 年齢・身長・体重・戦績・出身・拠点・構え）**: ボクセルを積んだ金の WVC ロゴ、WONDERFUL VOXING COUNCIL、大会名 → 何試合目 → 両コーナーの紹介の板（本名・流派・肩書きと出身）→ VS → 決まりの帯。

- **休み**（2026-11-18 に組み直し。`TvDirector.PlanBreak`）: 休みの始めと終わりをいつものカメラ（休みの 12 %、最大 2.5 秒）で挟み、間は**選手を映すカットを優先**する（選手の体が大きく映るカット = 手持ち・コーナー・リング脇・傷のアップ・リプレイが休みの 6 割以上）。カメラは、リングの中のカメラマン（コーナー: 正面、手持ち `Handheld`: 斜め前から胸から上を撮り、狙いの点は選手の動きに時定数 0.35 秒で遅れて追い、周期の違う正弦の揺れと寄り引き・ズームの呼吸が付く）、リング脇（低い所から）、**リング全体 `Wide`**（手前の角の上から 2 人が入る引きの絵をゆっくり横へ流す）、天井。リング全体と天井は差し込みで、3 カットに 1 つ・休みの 15 % まで（1 カット 3.0〜3.5 秒）。選手を映すカットは 4.5〜7.0 秒で揺らし（2026-11-18、2.0〜4.0 秒ではパカパカ入れ替わって見えた。最後に 4 秒より短い端は作らず前のカットに足す）（休みの数から決まる揺らぎ。乱数なし）、2 人を交互に、同じ種類を続けない。**リプレイは 1〜2 本**（重い順に最大 2、休みが 18 秒未満なら 1 本。時刻の順、当たった所へ回り込むカメラで 1 歩 1 コマのスロー、出入りは金の帯のワイプ）で、手持ちの 1 カットの後に続けて流す。**傷のアップは休み 1 回に多くて 1 カット**で毎回ではない（傷の重さ — 打撃・削れたセル・骨折・切断の和、30 未満は入れない — で入れるかが決まり、重いほど入りやすい）: まだ映していない傷は休みのすぐ後（削れたセルがまだ残るうちに）、前の休みに映した傷でまだ削れたセルが残っているもの（`TvWound.Healing`）は休みの後ろの半分で映し、再生（`Regenerate`）で戻っていくセルを見せる。傷のアップは、リングの中のカメラマンが手持ちで寄る 4.2 秒の 1 カット（切り替えない。体全体 → 傷へ振り、ズームで画角 46° → 12°、寄るほど手の揺れが目立つ）。傷の点は、打たれた点に一番近いボクセルの部位の格子の中の点として覚える（重さで重み付けした平均）ので、倒れていても腕が動いていても今の位置を追う。出来事は wound_cam（「手持ちカメラが 〇〇 の右すねの傷にズームで寄る」。治りかけは「治りかけ: 休みの間に削れた所が戻っていく」と付く）。あざは休みの間に引く（`MatchRules.BruiseHalfLifeSeconds` 20 秒で半分。ラウンド中は引かない）。
- **決着**: K.O. なら勝敗の画面の前に、倒した一撃の決着のリプレイ。勝敗の画面は決まり手（K.O.／判定）・勝者の帯・決着の時刻・ラウンドごとの与えたダメージ。

## 4. 台本の決まり

語りの型（一人実況・選手の心の声など）と話し手の個性の組み合わせは、LLM 向けの説明書 [docs/commentary/README.md](commentary/README.md)。この節は既定の型（tv-duo: 実況 ＋ 解説）の決まり。

**ラジオで聞いても試合が追えること**が基準（画面を見ていない人に、誰が・何を・どうなったかが伝わる）。実際の格闘技・スポーツ中継の慣習（実況 = 見えることを短く・速く、解説 = なぜそうなったか・次に何が起きるか）を調べて決めた。PDCA の記録と出典は [TV_COMMENTARY_PDCA.md](TV_COMMENTARY_PDCA.md)。

### 4.1 役割

| | 実況（Ichiro） | 解説（サエキ、Ayumi） |
|---|---|---|
| 言うこと | 画面で見えること: 誰の何がどこに入った・ダウン・カウント・立った・ラウンド・時間・リプレイに変わった・勝敗 | 体の中で起きていること・理由・狙い・次の見どころ（「肝臓が効いて足が止まった」「心臓が3割失われている」） |
| 話す時 | 打ち合いの最中（短く、興奮して） | 間（ラウンドの間・ダウンの後・リプレイ・打ち合いが途切れた所） |
| 掛け合い | 「サエキさん、〇〇選手の××は？」と**選手の名前を入れて**問いを振る | 問いに理由を添えて答える（「〜です」で終わらせず、なぜかを一言） |

### 4.2 決まり（`tvlint` が見る）

| 決まり | 中身 |
|---|---|
| （主語） | やめた（2026-11-17: すべての台詞に名前を求めると喋り方が不自然になった。誰の話か文脈で分かればよい） |
| 長さ | 1 台詞 60 字まで（1 息で言える長さ。2026-11-17 に 28 字から改めた: 28 字では体言止め・電報のような文になった） |
| 言わない言葉 | ダメージ＋数字・打撲・％・VGV・ボット・物理・セル。割合は「3割」「半分」のように言う |
| 呼びかけ | 「サエキさん！」だけで終わらせない（何を聞くかを添える） |
| （型） | やめた（2026-11-17: 文の形の繰り返しは書き手の判断に任せる） |
| 言い直し | ラウンドの頭 6 秒以内に「第Nラウンド」と言う（途中から聞いた人のため。ダウンの数の整理も下書きが入れる） |
| 掛け合い | 休みごとに、実況の問い → 解説の答えの組を 1 つ以上 |
| コール | ダウン・決着を 1 秒以内に実況が言う（「ダウン」「倒れる」「止めた」「テン」「ノックアウト」「リングアウト」「KO」「判定」） |
| カウント中 | ダウンから立つ・決着・ラウンドの終わりまでは解説に問いを振らない（立てるかを追う時間。解説は自分から理由を言うのは良い） |
| リプレイ | 映像がリプレイに変わったら 2 秒以内に「リプレイ」「スロー」「決着の場面」と言い、どの場面か（誰の何で誰が倒れた）を添える |
| ずれ | 声を入れた後、頼んだ時刻より 1 秒より遅れた台詞（前の台詞が長い） |

### 4.3 作り方（下書き → 足す台詞 → 重ねる → 点検）

1. **下書き**（`tvdraft`、道具）: ラジオで要る骨組みを決まった型で抜けなく置く。選手紹介（赤・青・流派）・ラウンドの頭（ダウンの数・倒れたままの選手）・ダウンのコール（**倒した側と倒れた側の両方の名前**と何が入ったか、何度目か）・カウントの後半（セブン〜ナイン）・立った（何カウントで）・骨折と切断・残り 10 秒・ラウンドの終わり（ゴングに救われた）・リプレイの入り（どの場面か）・決着（コール → 勝者 → 理由）・勝者のコール。言い回しは決まった順に回す（乱数なし: 同じ記録なら同じ下書き）。**標準は実況と解説の 2 人**: 下書きには解説の台詞も入る（`TvAnalyst`。中継の記録の「解説」向けの出来事から）: 休みごとに実況の問い「サエキさん、〇〇の様子は？」→ 解説の答え（傷か疲れと、その理由。傷のある方・疲れのひどい方の選手を聞く）、リプレイの後に当たった所がなぜ効くか、ダウンの後に倒れた理由、ラウンドに 1 回まで疲れの見立て、問いと答えの後に空いていれば優勢の見立て。置き場所は骨組みの空き（`TvDraft.Merge`）で、入らない台詞は落とす。休みの台詞は「2 本目のリプレイの場面 → なぜ効くか → 問いと答え」の順で、休み 25 秒（映像 33 秒）で入る（札の `break` の既定は 25）。下書きだけでも動画にできる（札の `"autoCommentary": true`）。
2. **足す台詞**（`bN.extras.json`、エージェント。スキル `.claude/skills/tv-commentary`）: 打ち合いの実況、問いと答え、解説の理由・見どころ。下書きの思い違いは `"drop"` に台詞を書いて消す。
3. **重ねる**（`tvmerge`）: 下書きは時刻どおりに残し、足す台詞を空きへ入れる。打ち合いの実況（`excited`）は 1 秒まで遅らせて先に、問いと答えの組は前 2 秒〜後ろ 6 秒で続けて、ほかは前 1.5 秒〜後ろ 2.5 秒。**入らない台詞は時刻をずらさず落とす**（遅れた台詞は画面と合わず、ラジオではもっと混乱する）。落ちた台詞は表示される。
4. **点検**（`tvlint`）: §4.2。声入れの後は manifest を渡して遅れも見る。

```json
// bN.extras.json
{ "drop": ["下書きの台詞（そのままの文）"],
  "lines": [ { "at": 13.6, "speaker": "announcer", "text": "サエキさん、アキラ選手の作戦は？", "excited": false },
             { "at": 16.4, "speaker": "commentator", "text": "蹴りで足を止めて、それから腹です。", "excited": false } ] }
```

### 4.4 LLM の台本（テイク。2026-11-17）

LLM（既定 Haiku）が、下書きを使わずに実況と解説の**全部の台詞**を書く（`"useDraft": false`）。決まった台詞を言わせるのでなく、プロフィールと試合から自由に見立てを語らせるため。道具は `tools/tvshow/write-commentary.ps1`。

- **型**（札の `commentary.style`、または `-Style`）: `open`（既定）は役（実況・解説）だけ与えて話す中身は自由、`free` は役も無い 2 人（声 `a`・`b`）に話せる時間だけ与えるフリートーク、`duo` は前の誘導つきの書き方（下の味付け・例・掛け合いの決まり）。2026-11-17、ユーザーの指摘（毎回身長・体重の話で単調）で open を既定にした。open・free で渡すのは資料と、守ること（記録と違えない・作中の言葉・1 台詞 60 字と声の長さ。open は実況の入りのコール: 第Nラウンド・ダウン・決着・リプレイ）だけ。点検（`tvlint`）は型ごとに見る決まりを減らす（open は掛け合い・カウント中・呼びかけを見ない、free は長さ・言わない言葉・ずれだけ）。
- **2 エージェントプロスペクティブ制**（札の `"commentary": { "writer": "prospective" }`）: 台本を後から書くのでなく、実況と解説の 2 つの LLM が試合の進行に合わせてマイク 1 本を取り合って話す（`tools/tvshow/prospective/run.js`、決まりは `docs/commentary/styles/prospective.md`）。2 人は参照用の文書（`docs/commentary/kb/`）を、席ごとに違う索引から必要なときに開く。
- **固めるもの（再現の土台）**: プロンプトの本体（`tools/tvshow/prompts/` の `tv-duo-open.md`・`free-talk.md`・`tv-duo-free.md`）と、資料（`bN.digest.md`・`events.json`・`draft.json`。試合の記録から決まる）。守らせる決まりは点検（`tvlint`）が見るものと事実だけで、ほかは目安。
- **ばらつかせるもの**（duo だけ）: テイクごとの「味付け」。`tools/tvshow/prompts/angles.json` から種で、二人の空気を 1 つ・触れるとよい話題を 3 つ選んで渡す（提案であって決まりではない）。前のテイクがあれば、それを読ませて同じ言い回し・話題の並びを避けさせる。札の試合ごとの `notes` があれば一言添える。種は味付けだけを決め、LLM の出力は同じ種でも毎回違う。
- **再現**: 採ったテイクの台本（`bN.extras.json`）があれば、声入れ・点検・結合は同じ結果になる（試合も種と版で同じ）。テイクは `<out>/takes/bN/<時刻>-s<種>/` に `prompt.md`・`extras.json`・`take.json`（種・味付け・モデル・プロンプトのハッシュ・点検の結果・実況と解説の台詞の数）として全部残る。今の台本がどのテイクにも無ければ、上書きの前に `<時刻>-kept` として残す。前のテイクへ戻すには `-Use <テイクのフォルダ>`。
- **書き手**: `-Mode cli`（既定。`claude -p --model haiku` を子として動かし、点検が OK になるまで最大 2 回直させる。CLI のログインが要る）。エージェントの中からは `-Mode prepare`（`PROMPT: <path>` を出す）→ Haiku のサブエージェントに「そのファイルを読んで、その通りにする」と頼む → `-Mode finish`（点検して記録。だめなら `FIX: <path>` と終了コード 2 → その直しの頼みを同じ LLM に渡して、もう一度 finish）。スキル `tv-commentary` の手順。

```powershell
# 札 1 枚で（台本の無い試合だけ LLM が書く）
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\wvc-boxing-tournament.json
# 全試合の新しいテイク → 聞き比べて、良い方を -Use で戻す
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\wvc-boxing-tournament.json -Stage write
powershell -ExecutionPolicy Bypass -File tools\tvshow\write-commentary.ps1 -Card tools\tvshow\cards\wvc-boxing-tournament.json -Bout b1 -Use docs\video\wvc-boxing-tournament\takes\b1\<テイク>
```

味付けの候補を足すときは、選手・試合を選ばない書き方で `angles.json` へ。方針そのものを変えるときは `tv-duo-free.md` と `docs/commentary/README.md` §2 を一緒に直す（プロンプトのハッシュが変わるので、どのテイクがどの版で書かれたかは `take.json` で分かる）。

## 5. 中継の記録（events.json）

## 7. リアルタイム配信に向けた測定（2026-11-16、GrandeDesktop: RTX 3060 Ti・12 スレッド）

実況付きの中継を撮りながら配信できるかを、今の道具（`video`・`Synthesize.ps1`）で測った。配信の仕組みは §8 で作った。

**読み戻しの直し**: 最初の測定では描画 1 コマが 720p で 28 ms・1080p で 69 ms かかり、影・後処理・ボクセル・文字を全部切っても 1080p で 63 ms のままだった。原因は描画ではなく、GPU から画素を読み戻す置き場がキャッシュの無いメモリ（CPU が読むと約 140 MB/s）だったこと。デスクトップの遊びは画面へ出すだけで読み戻さないので、この遅さは出ない。`HeadlessRenderer` の読み戻しをキャッシュのあるメモリ（HostCached）にして、720p 7 ms・1080p 22 ms（コマの画素は直す前とビット単位で同じ）。

| 部分 | 測った値（直した後） | 実時間に対して |
|---|---|---|
| 物理だけ（ボクシング、`league` 60 秒） | 11.9 秒 | 約 5 倍速 |
| 物理（剣、テレビ中継 34 秒＋リプレイの再計算） | 約 21〜24 秒 | 約 1.5〜2 倍速 |
| 描画 1 コマ（本番の画面、720p / 1080p） | 約 6〜7 ms / 10〜22 ms | |
| 書き出し（x264 medium・veryfast・NVENC） | 30 秒の 720p を 3.9〜5.7 秒 | 5 倍速以上 |
| 声の合成（OneCore、44 台詞 711 字） | 3.4 秒（PowerShell の起動込み） | 1 台詞 約 70 ms |
| **テレビ中継（剣・顔の窓・リプレイ、720p）** | 50 秒を 40 秒（直す前 68〜73 秒） | 1.25 倍 |
| **テレビ中継（同じ、1080p）** | 50 秒を 52 秒 | 0.96 倍 |

- 今のループは物理・描画・書き出しが 1 本の糸に並んでいる。1080p を実時間に乗せるには、物理を別の糸で先に進める（配信の遅延の分だけ先に試合を計算する。決定的なので結果は同じ）か、描画を数コマ重ねて流す。
- 実況は下書き（`tvdraft` の規則）なら即座に作れる。LLM の台詞は遅延の数秒の間に書ければ足り、声の合成は間に合う。

## 8. 生配信（2026-11-16、`video --live`・`tvshow.ps1 -Stage live`）

テレビ中継を実時間で描きながら、ffmpeg から OBS（や RTMP の配信先）へ流す。実況の声は前もって作る: 試合は種で決まる（決定的、CLAUDE.md §1.6）ので、**描かずに試合を先に回して出来事（events.json）を作り → 台本 → 声（manifest.json）→ 本番を実時間で描きながら声を混ぜて流す**。この「先に回した分」が配信の遅延にあたる。

> 決めた経緯・確かめた範囲・未確認のこと（OBS 実機・実配信・1080p）・はまった所は `docs/plans/LIVE_STREAM_HANDOFF_2026-11-17.md`。続きの作業はそこから始める。

### 使い方

```powershell
# 札 1 枚で（準備だけ: 種 → 下回し → 資料・下書き → 台本 → 声。流す前に確かめられる）
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\live-test.json -Stage liveprep
# 準備のあと、試合を順に流す（OBS を先に待たせておく。下の「OBS の受け方」）
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\live-test.json -Stage live
```

札の `"live": { "url": "...", "width": 1280, "height": 720, "encoder": "nvenc", "bitrate": "6M", "wait": 120, "delay": 15 }`（どれも省略可。既定はこの値。`url` の既定は `srt://127.0.0.1:9000?mode=listener&pkt_size=1316`）。台本は、足す台詞（`bN.extras.json`）があれば下書きに重ね、無ければ下書きだけ（生配信は `autoCommentary` を問わない）。`liveprep` は出来事を毎回作り直す（描かないので 1 試合 20 秒ほど。前の `bN.events.json` を使い回すと、物理・ボットの版が変わったとき流す試合と台本がずれる）。声は `<out>\bN_live_voices\manifest.json`、本番の出来事は `<out>\bN.live.events.json`（下回しの `bN.events.json` と同じ内容でなければ警告）。

道具を直に使うなら:

| 目的 | コマンド |
|---|---|
| 描かずに出来事だけ（下回し） | `miniring-arena video --tv on --facecam on ... --render off --out bN.mp4`（`bN.events.json` だけ書く。mp4・wav は書かない。物理の速さで終わる） |
| 生配信 | `miniring-arena video --tv on --facecam on ... --live <url \| on> [--voices manifest.json] [--encoder nvenc\|x264] [--bitrate 6M] [--wait 120] [--delay 15] [--out videos\live.ts]`（`--live` と `--render off` は一緒に使えない。`--out` は出来事の記録（`*.events.json`）の置き場所を決めるだけ） |

`--live` の出口は URL で決まる: `srt://`・`udp://` は mpegts、`rtmp://`・`rtmps://` は flv、それ以外はファイルのパスで拡張子 `.ts`（mpegts）・`.flv`・`.mkv`（matroska）。`srt://` に `pkt_size=` が無ければ `pkt_size=1316` を足す。`--live on` は既定の URL。**配信の鍵（YouTube・Twitch の stream key）は札にもコードにも書かない**。ログ・例外・ffmpeg の標準エラーに出る URL は伏せる（srt・udp は `?…` 以降、rtmp は app の先を `…` に: `LiveOutput.Describe` / `Redact`。`tvshow.ps1` も失敗の文の `--live` の値を伏せる）。RTMP へ直接流すときは、使う人が URL ごと `--live rtmp://…/<鍵>` と渡す（ログには鍵の手前までしか出さない）。NVENC の無い PC は `--encoder x264`（`libx264 -preset veryfast -tune zerolatency`）。

### OBS の受け方

1. シーンにソース「メディアソース」を足す。
2. 「ローカルファイル」のチェックを**外す**。入力に `srt://127.0.0.1:9000`、入力フォーマットに `mpegts`。
3. 「再生が終了したときにメディアを再起動」と「接続が切れたら再接続」の相当（ネットワーク入力の「再接続」）を入れる。**試合と試合の間で接続は切れる**（`video` は 1 試合ごとに 1 回流して終わる）ので、OBS が繋ぎ直す。こちらは SRT の待ち側（`mode=listener`）なので、`video` を先に起動してから（または同時に）OBS が繋ぐ。受け手が繋ぐまで「受け手を待っています: …」と出て待つ（10 秒ごとに繰り返す。`tvshow.ps1 -Stage live` もこれをその場で画面に流す）。**受け手（OBS・ffmpeg）は、この「受け手を待っています」が出てから繋ぐ**（先に繋ぐと、繋がらずに失敗する）。`--wait <秒>`（既定 120、札なら `live.wait`）を過ぎても繋がなければ ffmpeg を止めて「受け手が繋ぎませんでした」で失敗する（黙って待ち続けない）。
4. 配信の鍵は **OBS の配信設定に入れる**（この道具には渡さない）。OBS が YouTube・Twitch へ流す。
5. 遅延: 受け手は `--delay`（既定 15 秒）＋ SRT・OBS の緩衝だけ遅れるが、途切れない流れを見る（下の「仕組み」）。OBS のメディアソースの「ネットワークバッファ」を小さくすると遅延は縮むが、緩衝の残りが減ったとき途切れやすい。

ffmpeg で受けて確かめるなら: `ffmpeg -y -i "srt://127.0.0.1:9000?mode=caller" -c copy recv.ts`（OBS が無くても受けられる。`video --live` が先に待っているところへ繋ぐ）。

### 仕組み（遅延の緩衝）

当初はコマごとに実時間の歩調を取っていたが、リプレイの追いつき（影の試合を 1 コマの間に数百歩進める）や他の作業との CPU の取り合いで 1 コマが数秒かかり、受け手が途切れた（遅れたコマ 285〜380 / 1844、最大 4〜5 秒）。そこで**配信の遅延の緩衝**に変えた: 作る側は作れる速さで進め、送り側だけが実時間で流す。受け手は遅延（既定 15 秒）だけ遅れるが、なめらかな実時間の流れを見る。

```
作る側（描画・物理・音）→ エンコード A（ffmpeg: rawvideo + 音の TCP → mpegts を標準出力）
  → 中継（C# の糸）→ 緩衝（バイト数で上限 64 MB。いっぱいなら A も作る側も止まる。落とさない）
  → 送り B（ffmpeg -re -f mpegts -i pipe:0 -c copy → srt / flv / ファイル）
```

- **遅延 `--delay`**（既定 15 秒、札の `live.delay`）: 作ったコマが `delay` 秒ぶんに達してから B を始める（遅延に達する前に緩衝が 75 % 埋まったら、そこで始める。始めないと中継 → A → 作る側が止まって詰まる。`--delay` が緩衝に収まらない — ビットレート × 遅延が緩衝の半分を超える — 指定は、起動時にはねる）。既定の 15 秒は、測ったリプレイの追いつきの最大（4〜5 秒）に他の作業との CPU の取り合いが重なっても途切れない長さ（8 秒では CPU 80 % 前後の負荷の下で、緩衝の残りが 0.5 秒まで減った）。B が始まって約 1.5 秒後（SRT の待ち受けが実際に始まる目安）に「受け手を待っています」が出る（**受け手はこの表示のあとに繋ぐ**。待ち受けの開始と表示は前後しうるので、受け手は繋ぎに失敗したら数秒おいて繋ぎ直す: OBS のメディアソースは再接続の遅延で自動、ffmpeg で受けるなら繰り返し起動）。作る側は B より先に進むので、1 試合は緩衝（6 Mb/s で約 85 秒ぶん）に収まり、作り終えたあとも B が実時間で流し切るまで `video` は終わらない。ファイル出力（`.ts` など）も同じ道（B）を通す（挙動をそろえるため。ファイルは実時間で書かれる）。
- **受け手の待ち**: B が `-progress pipe:1` の `total_size` > 0（出力が開いて最初の書き込みが済んだ = 受け手が繋いだ）になるまで待つ。「受け手を待っています: <伏せた URL>」を 10 秒ごとに繰り返し、`--wait`（既定 120 秒、B を始めてから数える）を過ぎたら全部止めて「受け手が繋ぎませんでした」で失敗する。待つ間に緩衝がいっぱいになれば作る側が止まる（落とさない）。
- **失敗**: A・B・中継・書き手・音の接続のどれが失敗しても、最初の原因を記録して全部の ffmpeg を止め、作る側の次の書き込みが「原因 + 伏せた URL + A・B の標準エラーの終わり」の例外で失敗する（ハングしない）。`Dispose` は全部を止めてから片付ける。ffmpeg の標準エラーは A・B どちらも伏せてから出す。
- **統計**: 「緩衝の残り」= A へ実際に渡したコマの時間（溜めている 0.5 秒は数えない）− B が出した時間（B の `out_time_us`）。受け手が繋いでから作り終えるまでの最小値（`min lead`）と、残りが 0.5 秒を下回った回数（`underruns` = 受け手が途切れる回数）を終わりに出す。
- **A の出口**（`games/MiniRing.Arena/LiveOutput.cs`）: 映像 = 標準入力の rawvideo RGBA、音 = TCP の s16le（ffmpeg が `tcp://127.0.0.1:<空きポート>?listen=1` で聞き、こちらが繋ぐ）。映像は `h264_nvenc -preset p4 -tune ll -rc cbr`（GOP 2 秒・B フレーム無し）、音は AAC 160 kb/s（`-ac 2`。モノラル → ステレオの変換で −3 dB になるのは、ファイルの道の `Mix.ps1` の `aformat` と同じなので、大きさが揃う）。音の接続の期限（10 秒）は、映像の最初のコマを A に渡してから数える（A は最初のコマを読むまで音を聞き始めない）。短い配信（溜めるコマ数に満たない）は、終わりに先に映像を渡してから音を書く。flv の B の ffmpeg ログは、鍵を単独の語で書く詳細ログを避けるため常に warning にする。入力の形は引数で全部渡し、`-probesize 32 -analyzeduration 0` で中身を調べさせない（調べさせると ffmpeg が音を数秒ぶん待ち、映像の書き込みが詰まって待ち合った）。flv（rtmp）の B は `-bsf:a aac_adtstoasc` を付ける。
- **音の置き方**: 今までどおり `audio`（float の配列）へ置き、コマを作るたびに `f / fps − AudioDelaySeconds`（0.25 秒）までの標本を s16 にして TCP へ書く（`audio` の長さを超えた分は無音: 決着のリプレイは試合の時間を進めずにコマを足す）。会場の歓声は、地の歓声（`Broadcast.MixAmbience`）を始めに混ぜ、反応（`Broadcast.MixCues`）は増えた分だけ書く前に混ぜる（`MixInto` は両方を呼ぶので、ファイルの道は変わらない）。
- **A への映像を 0.5 秒溜める**（`VideoHoldSeconds`）: ffmpeg は映像のコマの時刻より先の音が届くまで映像をエンコーダへ送らず、入力の緩衝は数コマ（0.3 秒ほど）しかないので、音をコマの時刻より遅れて書くと映像の標準入力が詰まって待ち合う。そこで映像を 15 コマ溜めてから古い順に渡し、音はその渡す映像より先まで書く。
- **実況の声**（`LiveAudioMixer`、`--voices manifest.json`）: 台詞の wav を始めに読み（標本の速さはヘッダから。16 kHz → 44.1 kHz は直線補間）、声の線に置く。ゲームの音は声の間だけ −6 dB、声の 0.15 秒前から下げ始め、声が終わって 0.4 秒で戻す（`tools\commentary\Mix.ps1` と同じ値と形）。出力 = ゲームの音 × 下げ ＋ 声 を `tanh` で柔らかく頭打ち（声なしの mp4 の道と同じ）。ファイルの道（`dub.ps1` → `Mix.ps1`）は `alimiter`（−1 dBFS）なので、声のある所の数値は完全には一致しない。
- **下回し**（`--render off`）: `HeadlessRenderer`・ffmpeg・音を作らず、`Emit` はコマを数えるだけ。試合・演出（`TvDirector`・リプレイの影の試合・`Broadcast`）は同じに回すので `events.json` はバイト単位で同じ。
- **診断**: 環境変数 `LIVE_TIMING=1` で、終わりに「全体 = 描画 + コマを渡す所 [A の標準入力で止まった時間] + 物理・その他」を出す。

### 測定（2026-11-16、GrandeDesktop、RTX 3060 Ti、他の作業が動いている間: CPU 平均 55〜73 %）

| 測ったもの | 結果 |
