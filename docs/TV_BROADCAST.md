# WVC テレビ中継の動画（作り方と決まり）

ボット同士の試合を、作中の世界のテレビ中継として動画にする。撮影・カメラ・リプレイ・実況の骨組みの下書き・声入れ・点検・結合は道具が決まった手順で行い、**人（エージェント）が書くのは下書きに足す台詞（打ち合いの実況・問いと答え・解説の理由）だけ**。足す台詞なしでも下書きだけで動画にできる。

## 1. 位置づけ（名前）

| 名前 | 何か | 動画に出すか |
|---|---|---|
| **Voxing** | スポーツの名前（voxel と boxing） | 出す（角の札・実況） |
| **WVC**（Wonderful Voxing Council） | 団体の名前。動画は「WVC の大会のテレビ中継」 | 出す（ロゴ・題字・大会名） |
| **VGV**（Very Good Voxing） | このゲームの名前 | **出さない**（野球中継にゲームの名前が出ないのと同じ） |

動画は作中のテレビ番組なので、「ボット」「物理」「ダメージの数値」のようなゲームの裏側の言葉も出さない。

## 2. 作り方

```powershell
# 1. 撮影と台本の資料（種の選び・撮影・要約）。台本が無ければここで止まり、書く場所を知らせる。
powershell -ExecutionPolicy Bypass -File tools\tvshow\tvshow.ps1 -Card tools\tvshow\cards\wvc-ishu.json
# 2. 足す台詞を書く: <out>\bN.digest.md と bN.draft.json（実況の骨組みの下書き）を読み、<out>\bN.extras.json を書く（エージェントはスキル tv-commentary、§4.3）。
#    エージェントなしで作るなら、札に "autoCommentary": true（下書きだけを台本にする）。
# 3. もう一度 1 を回す: 台本（下書き＋足す台詞 → bN.script.json）→ 声入れ（bN_live.mp4）→ 点検 → 結合（broadcast_full.mp4）→ 送れる大きさの部分（broadcast_partN.mp4）。
```

段だけを回すときは `-Stage scout | render | digest | dub | package`。撮り直しは `-Force`。

### 札（card JSON）

```json
{
  "event": "WVC 異種格闘技王者決定戦",
  "rounds": 3,
  "break": 20,
  "out": "docs/video/wvc-ishu",
  "scoutSeeds": [1, 2, 3, 4, 5, 6, 7, 8],
  "partLimitMiB": 29,
  "bouts": [
    { "red": "marcus", "blue": "akira", "seed": "auto", "bout": "第1試合" }
  ]
}
```

- `red` / `blue`: 名簿のキャラクターの id（`games/MiniRing/Characters/roster/<id>.json`）。武器・はめる物・体格・顔・名前はキャラクターの値。
- `seed`: 数字か `"auto"`。`"auto"` は下見（`scoutSeeds` の種を全部回す）で一番見ごたえのある種を選び、`<out>\card.resolved.json` に**選んだときの物理・ボットの版と一緒に**残す。版（`Fighter.PhysicsVersion`・`BoxerBot.LogicVersion`）が変わると同じ種でも別の試合になるので、版が違えば選び直す（撮った動画は `-Force` で撮り直す）。
- `rounds`・`break`: 30 秒のラウンドの数と、間の休み [s]。休みを延ばしても休みの間に治る量は標準（10 秒 × 150 個/秒）と同じ（`VideoMaker.TvRules`）。

### 段の中身

| 段 | 道具 | 出力 |
|---|---|---|
| 下見 | `miniring-arena tvscout --red-char A --blue-char B --rounds 3 --break 20 --seeds 1,2,...` | 種ごとの決着・ダウン・与えたダメージと見ごたえの点（`TvScout.Drama`）、最後の 2 行が版と `best seed N` |
| 撮影 | `miniring-arena video --tv on --facecam on --rounds 3 --break 20 --event ... --bout ... --red-char A --blue-char B --seed N --out bN.mp4` | `bN.mp4`（声なし）と `bN.events.json`（中継の記録） |
| 資料 | `miniring-arena tvdigest --events bN.events.json` | `bN.digest.md`（区間の表と、区間ごとの実況用・解説用の出来事） |
| 下書き | `miniring-arena tvdraft --events bN.events.json --out bN.draft.json` | 実況の骨組み（§4.3） |
| 重ねる | `miniring-arena tvmerge --draft bN.draft.json --extras bN.extras.json --out bN.script.json` | 台本。入らなかった台詞を表示 |
| 声入れ | `tools\commentary\dub.ps1`（`tools/commentary/README.md`） | `bN_live.mp4` |
| 点検 | `miniring-arena tvlint --script bN.script.json --events bN.events.json [--manifest bN_live_voices\manifest.json]` | 決まりに合わない台詞と 1 秒より遅れた台詞（§4.2） |
| 結合 | ffmpeg | `broadcast_full.mp4`、試合の切れ目で分けた `broadcast_partN.mp4`（各 29 MiB 未満、音つき） |

見ごたえの点（`TvScout.Drama`）は、長く続く（最終ラウンドまで）・ダウンの数・両者がダウンを奪い合う・K.O. で決着・ダメージで負けていた側の逆転、で上がり、第 1 ラウンドの 15 秒より前に終わると下がる。

## 3. 映像の演出（道具が決める）

- **冒頭（7 秒）**: ボクセルを積んだ金の WVC ロゴ、WONDERFUL VOXING COUNCIL、大会名 → 何試合目 → 両コーナーの紹介の板（本名・流派・肩書きと出身）→ VS → 決まりの帯。
- **試合中**: 上の真ん中に時計、右上に LIVE、左上に WVC / VOXING の札、左下・右下に両者の顔の窓（画面の高さの 18%）とその下の名札・スタミナ。
- **ダウン中**: 倒れる瞬間はいつものカメラ、0.8 秒後から天井のカメラ（真上）とリング脇のカメラマン（床の高さ、相手から遠い側）を 2.6 秒ずつ交互に。
- **休み**: いつものカメラ → リングの中のカメラマン（多く打たれた側のコーナー）→ リプレイ → 反対のコーナー → リプレイ → コーナー → いつものカメラ。リプレイはそのラウンドの重い場面（ダウン・骨折・切断・重い当たり）を 2 つ、時刻の順に、当たった所へ回り込むカメラで 1 歩 1 コマのスロー（実時間の約 0.4 倍）。リプレイの出入りは金の帯のワイプ。
- **決着**: K.O. なら勝敗の画面の前に、倒した一撃の決着のリプレイ。勝敗の画面は決まり手（K.O.／判定）・勝者の帯・決着の時刻・ラウンドごとの与えたダメージ。
- リプレイは同じ種・同じ歩で試合をもう一度回した「影の試合」を描く。本番と胸の位置がずれていないかを毎回測り、ログに出す（決定的なら 0.000 mm）。

## 4. 台本の決まり

語りの型（一人実況・選手の心の声など）と話し手の個性の組み合わせは、LLM 向けの説明書 [docs/commentary/README.md](commentary/README.md)。この節は既定の型（tv-duo: 実況 ＋ 解説）の決まり。

**ラジオで聞いても試合が追えること**が基準（画面を見ていない人に、誰が・何を・どうなったかが伝わる）。実際の格闘技・スポーツ中継の慣習（実況 = 見えることを短く・速く、解説 = なぜそうなったか・次に何が起きるか）を調べて決めた。PDCA の記録と出典は [TV_COMMENTARY_PDCA.md](TV_COMMENTARY_PDCA.md)。

### 4.1 役割

| | 実況（Ichiro） | 解説（サエキ、Ayumi） |
|---|---|---|
| 言うこと | 画面で見えること: 誰の何がどこに入った・ダウン・カウント・立った・ラウンド・時間・リプレイに変わった・勝敗 | 体の中で起きていること・理由・狙い・次の見どころ（「肝臓が効いて足が止まった」「心臓が3割失われている」） |
| 話す時 | 打ち合いの最中（短く、興奮して） | 間（ラウンドの間・ダウンの後・リプレイ・打ち合いが途切れた所） |
| 掛け合い | 「サエキさん、〇〇選手の××は？」と**選手の名前を入れて**問いを振る | 問いに理由を添えて答える（「〜です」で終わらせず、なぜかを一言） |

### 4.2 決まり（`tvlint` が見る）

| 決まり | 中身 |
|---|---|
| 主語 | 動き・体の状態を言う台詞には選手の名前を入れる。続きの短い台詞（3 秒以内・12 字まで）と、名前を出した問いへの答えは省いてよい |
| 長さ | 1 台詞 28 字まで（息継ぎ 1 回で言える長さ） |
| 言わない言葉 | ダメージ＋数字・打撲・％・VGV・ボット・物理・セル。割合は「3割」「半分」のように言う |
| 呼びかけ | 「サエキさん！」だけで終わらせない（何を聞くかを添える） |
| 型 | 「〜の…が、〜の…に」を 3 回続けない（「入った！」「打ち返す！」のような短い声を混ぜる） |
| 言い直し | ラウンドの頭 6 秒以内に「第Nラウンド」と言う（途中から聞いた人のため。ダウンの数の整理も下書きが入れる） |
| 掛け合い | 休みごとに、実況の問い → 解説の答えの組を 1 つ以上 |
| コール | ダウン・決着を 1 秒以内に実況が言う（「ダウン」「倒れる」「止めた」「テン」「ノックアウト」「リングアウト」「KO」「判定」） |
| カウント中 | ダウンから立つ・決着・ラウンドの終わりまでは解説に問いを振らない（立てるかを追う時間。解説は自分から理由を言うのは良い） |
| リプレイ | 映像がリプレイに変わったら 2 秒以内に「リプレイ」「スロー」「決着の場面」と言い、どの場面か（誰の何で誰が倒れた）を添える |
| ずれ | 声を入れた後、頼んだ時刻より 1 秒より遅れた台詞（前の台詞が長い） |

### 4.3 作り方（下書き → 足す台詞 → 重ねる → 点検）

1. **下書き**（`tvdraft`、道具）: ラジオで要る骨組みを決まった型で抜けなく置く。選手紹介（赤・青・流派）・ラウンドの頭（ダウンの数・倒れたままの選手）・ダウンのコール（**倒した側と倒れた側の両方の名前**と何が入ったか、何度目か）・カウントの後半（セブン〜ナイン）・立った（何カウントで）・骨折と切断・残り 10 秒・ラウンドの終わり（ゴングに救われた）・リプレイの入り（どの場面か）・決着（コール → 勝者 → 理由）・勝者のコール。言い回しは決まった順に回す（乱数なし: 同じ記録なら同じ下書き）。下書きだけでも動画にできる（札の `"autoCommentary": true`）。
2. **足す台詞**（`bN.extras.json`、エージェント。スキル `.claude/skills/tv-commentary`）: 打ち合いの実況、問いと答え、解説の理由・見どころ。下書きの思い違いは `"drop"` に台詞を書いて消す。
3. **重ねる**（`tvmerge`）: 下書きは時刻どおりに残し、足す台詞を空きへ入れる。打ち合いの実況（`excited`）は 1 秒まで遅らせて先に、問いと答えの組は前 2 秒〜後ろ 6 秒で続けて、ほかは前 1.5 秒〜後ろ 2.5 秒。**入らない台詞は時刻をずらさず落とす**（遅れた台詞は画面と合わず、ラジオではもっと混乱する）。落ちた台詞は表示される。
4. **点検**（`tvlint`）: §4.2。声入れの後は manifest を渡して遅れも見る。

```json
// bN.extras.json
{ "drop": ["下書きの台詞（そのままの文）"],
  "lines": [ { "at": 13.6, "speaker": "announcer", "text": "サエキさん、アキラ選手の作戦は？", "excited": false },
             { "at": 16.4, "speaker": "commentator", "text": "蹴りで足を止めて、それから腹です。", "excited": false } ] }
```

## 5. 中継の記録（events.json）

`MiniRing.Audio.Broadcast` が書く。出来事ごとに `for` が **実況**（画面で見えること: 誰が何でどこを打った・ダウン・カウント・ラウンド・カメラ・リプレイ）か **解説**（体の中で起きていること・狙い: どこが壊れた・何割失われた・何が効いている・疲れ・狙っている技）。言葉はゲームを知らない人が一言で分かるもの（内部の数値は書かない）。ほかに `opening`（冒頭）・`result`（勝敗の画面の始まり）・`end`（動画の終わり）の印と、両者の紹介（`redProfile`・`blueProfile`）・大会名（`event`）・何試合目（`bout`）。

## 6. 限界

- 版が変わると同じ種でも別の試合になる（§2）。古い動画の台本は新しい撮影には使えない。
- 声は Windows の OneCore の日本語の声（実況 Ichiro・解説 Ayumi）。抑揚は 2 段（普通・興奮）だけ。

## 7. リアルタイム配信に向けた測定（2026-11-16、GrandeDesktop: RTX 3060 Ti・12 スレッド）

実況付きの中継を撮りながら配信できるかを、今の道具（`video`・`Synthesize.ps1`）で測った。まだ配信の仕組みは無い。

| 部分 | 測った値 | 実時間に対して |
|---|---|---|
| 物理だけ（ボクシング、`league` 60 秒） | 11.9 秒 | 約 5 倍速 |
| 物理（剣、テレビ中継 34 秒＋リプレイの再計算） | 約 21〜24 秒 | 約 1.5〜2 倍速 |
| 描画 1 コマ（本番の画面、720p） | 約 28〜30 ms | 30 fps に足りない（33 ms の大半） |
| 描画 1 コマ（本番の画面、540p） | 約 17 ms | |
| 顔の窓 2 つ | 約 5 ms / コマ | |
| 書き出し（x264 medium・veryfast・NVENC） | 30 秒の 720p を 3.9〜5.7 秒 | 5 倍速以上（詰まりではない） |
| 声の合成（OneCore、44 台詞 711 字） | 3.4 秒（PowerShell の起動込み） | 1 台詞 約 70 ms |
| **通しの動画（ボクシング、720p）** | 28.6 秒を 30 秒 | 0.95 倍 |
| **テレビ中継（剣・顔の窓・リプレイ、720p）** | 50 秒を 68〜73 秒 | 0.7 倍 |
| **テレビ中継（同じ、540p）** | 50 秒を 55 秒 | 0.9 倍 |

- 描画の時間は画素数にほぼ比例する（GPU の仕事）。`HeadlessRenderer` は 1 コマごとに提出 → フェンスで待つ → 読み戻しを直列に行い、その間 CPU（物理）は止まっている。
- 今のループは物理・描画・書き出しが 1 本の糸に並んでいる。実時間に乗せる順番: (1) 物理を別の糸で先に進め（配信の遅延 5〜10 秒の分だけ先に試合を計算する。決定的なので結果は同じ）、描画は体の姿勢のスナップショットだけを受け取る → 540p の中継で約 1.4 倍の見込み。(2) 描画を 2〜3 コマ重ねて流す（読み戻しの置き場を複数にしてフェンスを待たない）。(3) 720p で 30 ms かかる GPU の中身をタイムスタンプで測る。
- 実況は下書き（`tvdraft` の規則）なら即座に作れる。LLM の台詞は遅延の数秒の間に書ければ足り、声の合成は間に合う。
