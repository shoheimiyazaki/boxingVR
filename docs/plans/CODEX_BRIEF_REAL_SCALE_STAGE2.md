# 指示書: 実物大の物理へ 段 2（相似の換算）— 2026-11-20

計画の全体は `docs/plans/REAL_SCALE_PLAN.md`（§2.1 の表・§5 段 2）。段 1（表示の空間を分ける、`games/MiniRing/DisplaySpace.cs`）は済んでいる。
この指示書は、段 2 の**機械的な換算**を、触るファイルが重ならない塊に分けて並列に進めるための共通の決まり。

## 目的

物理（試合の計算）を、今の 60 cm の人形の単位から**実物大の人の単位**へ移す。**挙動は変えない**（統計で同じ）: 人形の動きを、長さ × L・時間 × T・質量 × M の
相似（フルードの相似、重力 9.81 のまま）で拡大した世界にする。表示（VR・デスクトップ・動画）は `DisplaySpace.WorldScale = 0.355` で今の人形の大きさに縮めて見せる
（統合役がこの定数と `FighterTuning.Scale`・`MassScale` を変える。**あなたの塊で触らない**）。

迷ったら、その値の式の中での使われ方（何と足す・比べる・掛けるか）から次元を決める。`MathF.Max(1e-6f, x)` の割り算のよけのような「0 を避けるだけ」の
小さい値は変えない。距離・速さ・時間の**閾値**（`if (speed > 0.3f)`・`distance < 0.02f`）は換算する（挙動に効く）。

## 空間（どの値を換算しないか）

- **物理の空間**（換算する）: 体・武器・破片・リング・ボットの判断・ドリル・試合の決まり（ラウンドの秒数・休み・数える秒・再生の速さ）・カメラが物理の位置から
  足す距離（`eye = mid + side * 0.9f` の 0.9）・物理の空間の描画の大きさ（破片・目の玉・手の目標の玉・傷・息の粒の大きさと速さ）・音の元になる物理量
  （エネルギー・速さ・大きさの基準。同じ打撃が同じ音になるように）。
- **表示の空間**（換算しない）: 部屋 `LivingRoom`（`GroundAt` の 2 cm の余白だけは物理）・会場の照明と飾り `ArenaLook`・カメラの近い面・遠い面・
  `TvDirector.CameraMargin`・`OrbitCamera` の距離・画面の画素・HUD。
- **VR の空間**（換算しない）: プレイヤーの実物の体（HMD の高さ・コントローラの位置・`PuppetMapping` の人の寸法・`VrRawFrame` の値）。
- **人の単位で書いて縮めている値**（換算しない。`FighterTuning.Scale`・`MassScale`・`TorqueScale` を 1 にすれば自動で実物になる）:
  `HumanoidRagdoll` の既定の寸法・質量、`HipMaxTorque` などの「TorqueScale 倍する前」の値、`x * tuning.Scale` で縮めている人の値。
- **他の値から出る量**（換算しない）: `ArmReach`・`FighterTuning` の値・体の寸法から計算している式。換算するのは**数の直書き**だけ（二重に掛けない）。
- **音そのもの**（換算しない）: 音の高さ [Hz]・音の長さ・サンプル数・音量。換算するのは、物理量を音へ写す基準（「この J で最大の音量」「この m/s で風切り」「この
  大きさならこの高さ」）だけ。
- **画面の時間**（換算しない）: 字幕・テロップの表示秒数、動画のフレームレート、ffmpeg の設定、HUD の点滅。試合の中の時刻に合わせて出すもの（「打った 0.5 秒後に
  スロー」）は試合の時間なので換算する。

## 書き方

1. 直書きの数を、換算した値に書き換える（有効数字 3〜4 桁。例 `0.16f` → `0.451f`）。式で書かない（`0.16f * 2.8169f` にしない）。`const` はそのまま `const`。
2. その値を説明するコメントの数字・単位も今の値に直す（「約 0.19 m」→「約 0.53 m」、「60 cm の体で」→「人の大きさの体で」程度）。日付のついた経緯の記録
   （「2026-11-18 まで 1.2 m」）は書き換えず、必要なら「（人形の単位）」と添える。
3. 人の単位の値を人形へ縮めるためだけの式（`* 0.355f`・`/ 0.355f`・`√0.32` など）は、実物大では不要になる: 縮めていた値を人の値のまま使うように直す
   （`5.3f * 0.355f` → `5.3f`）。ただし挙動を保つこと（縮めた値が人形の単位として使われていたなら、結果が ×L になる = 正しい）。
4. 決められない・換算すると明らかに変な値になる・相似に乗らない（例: Bepu の中の絶対の値、テクスチャの解像度）ものは**変えずに**報告に書く。
5. **ビルド・テストを走らせない**（同じ作業木で他の作業者が並列に書いている。統合役がまとめてビルドする）。読むだけの `grep` は自由。
6. 自分の塊のファイル以外を書き換えない。git の操作（add・commit・stash・checkout）をしない。

## テストの換算（tests/MiniRing.Tests）

- 期待値・閾値・場面の組み立て（体・武器・箱を置く位置、相手との間、押す力、打つ速さ、待つ秒数・歩の数）で、人形の単位で書いた数 → 上の表で換算する。
  例: `Assert.IsGreaterThan(0.15f, step)`（踏み込み 15 cm）→ `0.4225f`、`for (var i = 0; i < 480; i++)`（2 秒）→ `806`、`new Vector3(0f, 0.6f, 0.44f)` → ×2.8169。
- 比・順序・保存の不変量（「A は B より大きい」「割合 0.8 以上」）はそのまま。**緩めない**: 換算した値より甘くしない。
- 期待値がコードの値から計算されている（`RingLayout.DrillBoxing.StartGap`・`tuning.StrideLength`・`ArmReach`）ならそのまま（コードの側が換算される）。
- 直書きの `0.355f`（`JoTests.PuppetScale`・`BojutsuTests`・`StepTests`）: 人形の縮尺で人の値を縮めていた所は、実物大では縮めない（1 にする。意味を読んで直す）。
- 描画のテスト（visual・Probe の動画・画像）で試合の場面を撮るものは、カメラの目・注視点を物理の空間で決めてから `game.Display.Camera(eye, target, up, fov, aspect, near, far)`
  で表示の空間へ移す（`DisplaySpace.cs`）。物理の位置に足す距離は換算する。部屋（`LivingRoom`）の座標・近い面・遠い面は表示の空間なので変えない。
- `[TestCategory]`・テストの名前・説明文の数字（「15 cm」）は、値を換算したら説明も合わせる。
