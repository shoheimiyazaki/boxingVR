## 決めたこと（作り）
1. **名簿はデータ**: 新しい型（例: `games/MiniRing/Characters/FighterCharacter.cs` と組み込みの `characters.json`）に、id・表示名・国（名前と旗の色の帯）・はめる物（`HandWear`）・武器（`WeaponKind?`）・ボットのスタイルの名前・体格（`BodyBuild`）・顔（`FaceLook` の肌・髪・瞳・髪型・眉・ひげ、`FaceParts`）・一言。読み込みで値を検証（体格の範囲・色 0..1・スタイル名が `BotCatalog` にある）、壊れていれば分かるメッセージで止める。スタイル JSON（`champion.json` など）には触らない（別の作業がボットの JSON を変える）。
2. **試合へ渡す**: `MatchSelection` は 2 人のキャラクターを持ち、`BoxingCorners` の名前・体格・顔・はめる物・武器・`Referee` を埋める。顔の色（肌・髪・瞳・髪型・眉・ひげ）は今はリングネームから決まる（`FaceLook.For`）ので、キャラクターの顔をそのまま使えるよう `BoxingCorners` に顔（`FaceLook?`）を足し、記録の見出し（`ReplayMatchSettings`）にも入れる（再生で同じ顔。古い記録は今までどおり名前から）。`BoxingCorners`・`ReplayMatchSettings` の引数は**末尾に足す**（別の作業が `Referee` を記録へ足すので、取り込みでぶつかりにくくする）。空手の判定（`LocalVersusControl.IsKarate` が名前で見ている）は、キャラクターのスタイルで決まるように直す。HUD・実況に出る名前はキャラクターの表示名。
3. **メニュー（`games/MiniRing.Desktop`）**:
   - 最初の画面: 大きなボタン（シングルプレイ・対戦・観戦・リプレイ・設定・終了）に、それぞれ図形で描いたアイコン（`UiShapeDraw` の組み合わせ。外部の画像・フォントのライセンスを持ち込まない）。
   - 設定: 「レフェリー あり／なし」。値はファイル（リプレイと同じアプリのデータの場所に JSON）に残し、読むときに検証して、壊れていれば既定（あり）へ戻してログに出す。
   - キャラ選択（格闘ゲーム風）: 12 人の顔を格子に並べ、赤（1P）と青（2P・CPU）のカーソル。左右に選んだキャラの大きな絵・名前・国旗・武器のアイコンと名前・身長と体格（体の寸法そのもの。§1.7）・一言。シングル・観戦は赤 → 青の順に選ぶ。対戦は 2 つ目のパッドで青を同時に動かせると良い（キーボードは順でよい）。決定で試合へ、戻るで 1 段戻る（一番上で戻っても終了しない今の決まりは保つ）。
   - **顔の絵は本物のボクセルから作る**: 試合で使う頭のボクセル（`BoxerAnatomy` の頭の格子とキャラの色の表）を正面から見た、いちばん手前のセルの色を 2D の格子に写して、四角の並び（ドット絵）として描く。大きな絵は全身の正面の写しを体格の寸法で描き、背の高さ・太さが見て分かるように。別の絵を描き起こさない（見えている体 = 試合の体）。
   - 国旗は色の帯と丸で簡略に（回転できない図形で近いもの）。武器のアイコンも図形で。
   - 操作: キーボード・マウス・パッド（スティックの上下は今の向きを保つ）。画面の下に操作の案内。
4. **試しやすく**: メニューの状態の遷移を、`InputSnapshot` に依らない小さな入力（上下左右・決定・戻る・指す位置）を受ける純粋な部分に分け、単体テストを書く（キャラを選ぶ・戻る・一番上で戻っても終わらない・設定の切り替え・選んだキャラの武器が試合へ渡る）。
5. （できれば）Arena の `video` に `--red-char <id> --blue-char <id>` を足し、名簿のキャラで撮れるように。
