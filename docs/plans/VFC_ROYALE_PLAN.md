# VFC のバトルロイヤル（6 人）の設計

2026-11-25、ユーザーの依頼「VFC にバトルロイヤルを入れて、6 人で戦うモードを追加して」。枝 `claude/vfc-royale-c1e767`。結果と測定は文末の「記録」。

## 軸との関係

- **§1.5 一つの現象には一つのモデル**: 6 人でも体・物理・当たり・材料は 2 人の試合と同じ道を通る。新しい当たりの式は作らない。`BoxingGame` を「2 人 + 追加の席」に広げ、2 人の試合の計算順・乱数・結果は 1 ビットも変えない（テストで同じビルドの中の比べ）。
- **§1.3 場合分けをしない**: 誰を狙うかは、相手の見える特徴から出す連続の量の重み付きの和の最大（下の「狙う相手の選び方」）。「弱っている相手なら」「背中を向けているなら」の分岐を書かない。
- **§1.6 決定的であること**: 席の順は固定（赤 = 0、青 = 1、追加 = 2..）。狙いの選び直しは毎サブステップ、同点は席の番号の小さい方。乱数は席ごとの種。
- **§1.7 見た目が脅威を伝える / §1.8 教育**: 狙いの選び方の重みは `BotStyle.Rival`（教科書・教育の値）。体の強さは変えない。

## 2 人前提をどこまで広げるか

| 所 | 今（2 人） | 6 人 |
|---|---|---|
| 席 | `Player`（赤）・`Cpu`（青） | そのまま。追加の席は `BoxingCorners.Others`（`RoyaleEntrant` の並び: 名前・表示名・スタイル・武器・はめる物・体格・顔）。`BoxingGame.Fighters`（読むだけ）で全員 |
| 操作元 | `_playerControl`・`_cpuControl` | 追加の席もボット（武器のボット or `BoxerBot`、レフェリーなしなら `GroundStriker` を重ねる）。種は席ごと |
| 相手 | もう一人 | `TargetOf(fighter)` = その人が今狙っている相手。2 人ならもう一人（同じ） |
| 見え方（`FighterSense`） | 相手 1 人 | 狙っている相手 1 人（契約は変えない）。狙っていない相手は見えない = 背中を取られる |
| 当たり（拳の古い道・蹴り・肘・武器・はめる物） | 相手の部位 | 自分以外の全員の部位（武器・はめる物の掃きは元から全員）。古い拳の接触は持ち主を引いて、2 人の試合と同じ順に呼ぶ |
| 決着 | 死・リングアウト・ダウン | 生き残り（死んでいない・場から落ちていない）が 1 人以下になったら終わり。最後の 1 人の勝ち。死・リングアウトの順と、とどめを刺した人（最後に当てた人）を `Eliminations` に残す |
| 時間切れ | VFC: 5R を終えて両者生還なら `DRAW — BOTH SURVIVE` | 生き残りが 2 人以上なら `DRAW — N SURVIVE`（VFC の決まりそのまま） |
| 休み | 赤 240°・青 60° の頂点 | 席 k は 240° + k·360°/N の頂点（N = 2 なら今と同じ 240°・60°）。立つ所は同じ `CornerFor`（体と持ち物の輪郭が金網に触れない頂点にいちばん近い所） |
| 両者ダウンの再生 | 両者が倒れて立てない間 | 1 人ずつ: 倒れて立てない人は、自分を狙っている人が誰も立っていない間だけ（`RegrowUnattended`。2 人の試合は今の決まりのまま） |
| 描画・顔の窓・名前 | 2 人 | 描画は全員。動画は `royale` の道具（下）で、頭の上の名前の札と、生き残りの一覧。顔の窓（`FaceCam`）は 2 人のまま |

ダウンの数え（レフェリー・10 カウント）は 2 人の決まりなので、バトルロイヤルは VFC（ダウンを取らない・レフェリーなし）だけで回す。

## 檻と始めの立ち位置

- 檻: `RingLayout.RoyaleCage` = 向かい合う辺の距離 8.97 m の六角形。1 人あたりの面積を、素手の檻（3.66 m、2 人で 11.6 m² → 1 人 5.8 m²）と武器の檻（7.32 m、1 人 23.2 m²）の幾何平均 11.6 m² にし、6 人で 69.7 m²。`Validated` の上限（10.14 m）の内。
- 始め: 席 k を頂点 240° + 60°·k に置く（6 人なら 6 つの頂点すべて）。指示は「辺ごと」だったが、頂点は中心から R（辺までの距離の 1.15 倍）で、隣との間がいちばん広い。2 人の試合の始めの立ち位置（頂点）と同じ式・同じ `CornerFor` を使えるので、辺の中点という別の決まりを作らない（§1.5）。顔は檻の中心へ向ける。

## 狙う相手の選び方（`Bots.RivalChoice`、値は `BotStyle.Rival`）

自分 i から見た相手 j の点:

```
score = − Near · (胸と胸の距離 / 自分の腕の長さ)
        + Facing · (相手の向き · 相手から自分への向き)        // 相手がこちらを向いている = 脅威（負なら背中を向けた相手を好む）
        + Weak · 相手の見える傷み（Injury(felt:false)、0..1）     // 漁夫の利
        + Low · 相手の頭の低さ（1 − 頭の高さ / 立ったときの頭の高さ、0..1） // 倒れている・崩れている
        + Revenge · Σ 相手から受けた打撃の重み（半減期 RevengeHalfLife で減る、0..1 に丸める） // 打ってきた相手へ向き直る
        + Stick · (今の狙いなら 1)                                // 選び直しの揺れを抑える
```

生きている相手のうち最大の点の人を狙う（同点は席の番号の小さい方）。すべて連続の量で、種類の分岐は無い。既定値は教科書の値で、キャラの教育で変えられる。狙いを替えると読み（`OpponentRead`）の履歴が新しい相手で始まり直すのは、人が目を移したときと同じ遅れとして残す（下の近道）。

## 記録と再生

- 追加の席はすべてボットなので、記録の入力は今と同じ（赤の指令・青の外の指令）。追加の席の中身（解決済みのスタイル・武器のスタイル・武器・はめる物・体格・顔）は `ReplayMatchSettings.Others`（JSON）に入れ、再生は同じ席を作る。古い記録は `Others` が無い = 2 人。
- `LogicVersion` を 72 へ（狙いの選び方を足した。2 人の判断は変わらない）。`PhysicsVersion` は上げない（体・当たり・静的な形は 2 人で同じ。檻の大きさは記録の `Ring` に入る）。

### 計算の重さ

| 人数 | この PC（1 本だけ） | tower32（1 本だけ） |
|---|---|---|
| 3 人 | 0.62 s / 試合の 1 s | 0.83 s |
| 6 人 | 0.97〜1.27 s | 1.80 s |

- 人数にほぼ比例（体のボクセルの接触・ボットの判断・Bepu の剛体の数がどれも人数に比例）。6 人で実時間とほぼ同じか少し遅い。刻み（240 Hz）・ボクセルは変えていない。
- 対策の候補（まだしない）: (1) 離れた人どうしの体の格子の接触を調べる前に、人ごとの外接球で振り分ける（`MayTouch` は部位ごと）。(2) 狙いの選び直し・見え方の更新を毎サブステップ（240 Hz）から 60 Hz へ（判断の側の値。`LogicVersion`）。(3) 死んだ体を眠らせる（Bepu の sleep。物理の版が変わる）。
- 動画（960×540・30 fps・音つき）は描画を含めて 6 人で約 3.6 s / 試合の 1 s（この PC）。
