# キャンペーンモードと減量・増量の計画（2026-11-26）

ユーザーの依頼: 今のモードを「フリーバトル」として独立させ、キャンペーンモードを作る。自分でボクサーを何人でも作り、新人戦を勝ち抜いてランキング上位を目指す。体格で出られる大会が限られ、武器は大会ごとに入れ替えられる。将来は試合ごとの減量・増量を入れたいので、その土台も進める。

## 軸との関係

- **§1.7 見た目が強さ**: ボクサーの強さは体（寸法）だけから出る。キャンペーンに能力値・経験値の倍率は無い。減量・増量は筋肉の太さ（`BodyBuild.Muscle`）を変えるだけで、力は断面（`SectionRatio`）から同じ式で変わる。
- **§1.8 体 ＋ 教育の 1 ファイル**: ボクサーは名簿と同じ形のキャラクターのファイル（`CharacterFile`）に、戦績の欄 `"career"` を 1 つ足したもの。1 人 1 ファイル。
- **§1.6 決定的**: 戦績・体重が変わるのは試合と試合の間だけ（メニューへ戻ったとき）。試合の中ではキャラクターは固定で、記録（.mrrep）は試合の開始時の体を持つ。
- **§1.3 場合分けをしない**: 出られるかは、体重（計量の階級）と戦績と団体のファイル（出場の条件・階級・計量の有無）と大会の表の値だけ。条件の種類（戦績の上限・勝ち数の下限・順位・階級・計量）はどの大会も同じ式（`CampaignLadder.Check`）で見る。コードに大会名・団体名の分岐は無い。大会の格（rookie・ranking・title）は相手の選び方と席の動き（試合の決まり）で、物理・判断には響かない。

### 画面の段（2026-11-26 作り直し）

ユーザーの指摘「項目が一画面に多すぎる・わかりにくい」「新しい試合に挑戦できる・ランキングが上がる喜びを」に合わせ、21 の大会を 1 つの一覧に並べていたボクサーのページを段に分けた。1 画面の選べる項目は 5 つまで。

| 段 | 中身 | 操作 |
|---|---|---|
| 本拠地（`MenuPage.Boxer`） | 名前・体重・身長・教科書・戦績（大きく）・直近の勝敗、団体ごとの今の席（IVF は自分の階級）。**次の試合** を 1 つ大きく（大会・相手・武器）。下に「団体と大会」「体重を変える」「消す」「戻る」 | ↑↓ で次の試合 ⇔ 下の列、← → で武器 / 下の札、Enter で試合へ |
| 団体と大会（`MenuPage.Orgs`） | IVF・WVC・VFC の 3 枚（自分の階級・席・3 段の開き具合の印）と戻る | ↑↓、Enter で道へ |
| 団体の道（`MenuPage.Path`） | 自分の階級の 新人戦 ▶ ランキング戦 ▶ タイトル を左から右へ。開いた段は緑、閉じた段は暗く「あと 2 勝で開く」「5 位 → 1 位で挑戦」「新人の枠は卒業」と勝ち数のバー。「いまここ」（出られる一番先の段）と「次の目標」の札。下に選んだ段の相手・説明か、出られない理由 | ← → で段、↓ で戻る、Enter で「次の試合」にして本拠地へ |
| 減量・増量（`MenuPage.Weight`） | 目標体重・決める・戻る。IVF の階級の表（今の階級と目標の体重の入る階級に印）、力の変わり方、「この体重なら○○級」 | ← → で体重 |

- **次の試合の選び方**（`CampaignPlan.AutoNext`）: 出られる大会のうち、一番先の段（タイトル → ランキング戦 → 新人戦）、同じ段なら表の順（IVF の自分の階級が先）。新しく大会が開けばそちらへ移る。道で選んだ大会は、出られる間だけ次の試合として残る（試合の後・体重を変えた後は自動へ戻す）。
- **IVF の他の階級** は道に出さない（計量で入らない階級の大会は、減量・増量の画面の階級の表で見せる）。
- **あと何で開くか** は `CampaignLadder.Gate`: `Check` と同じ順（出場の条件 → 階級 → 戦績の数 → 席）でどこで止まったかと、数（持っている勝ち・要る勝ち・席）を返すだけで、新しい判定の式は持たない（`CampaignPlanTests` が「Gate が開いている ⇔ Check が通る」を全大会で確かめる）。

### 決着から本拠地まで（2026-11-26、「相手を KO してもそのままゲームが進行しません」）

原因: 団体の決まりのある試合（キャンペーンは全部）は、決着すると `BoxingGame.MatchOver` が立って試合の画面のまま止まり、メニューへ戻る道が Esc だけだった（決まりの無い練習試合は 5.9 秒で次のラウンドへ作り直し、終わりが無かった）。

| 段 | 中身 | 進め方 |
|---|---|---|
| 決着を読む（`MatchFinish.Settled`） | 新しい判定は作らない。決まりのある試合は `MatchOver`（K.O.・TKO・死・判定・引き分け）、決まりの無い練習試合は最初に決まったラウンド（`RoundOver`） | — |
| 決着の瞬間（`FinishGate`） | 試合の画面のまま（`K.O. — OUT COLD`・`DRAW` などの試合の言葉と FINAL の時計）。1.5 秒の後に「Enter / A / クリック: 結果へ」の 1 行 | 1.5 秒は押しても進まない（決着の一撃の勢いで見逃さない）。Enter・A・左クリック・Esc で結果へ、5 秒で自動（練習試合の作り直し 5.874 秒より前） |
| 結果の画面（`MenuPage.Result`） | 勝者・決まり手（`BoxingGame.FinishReason`、判定・引き分け）・ラウンドと時刻・対戦の 2 人 | キャンペーン:「本拠地へ」1 つ。フリーバトル:「もう一度」（同じ組・同じ決まり）「キャラ選択へ」「メニューへ」。キー・パッド・クリック。Esc / B は一番控えめな行き先 |
| 本拠地と札 | 戦績は結果の画面を出す前に書く（結果の画面のまま閉じても残る）。札は本拠地に積んでおき、本拠地へ戻ると出る | 下の「試合の後の喜びの札」 |

決着の前に Esc で抜けた試合は今までどおり記録せず、結果の画面も出さずに本拠地へ戻る。決着の読み取りは画面の流れだけで、試合の計算・記録には入らない（版は変わらない）。テストは `MatchFlowTests`（門の段・キャンペーンの K.O. / 判定負け / 引き分け / 途中で抜ける・フリーバトルのクリック）、`MatchFinishTests`（実際の試合を判定まで回して読む）、`MatchFlowVisualTests`（`.visualcheck/flow_*.png`）。

### 試合の後の喜びの札

終わった試合を戦績に書いたとき（`MatchMenu.RecordBout`）、書く前と書いた後のボクサーの差から札を作って（`CampaignCard.Between`）本拠地の上に 1 枚ずつ見せる。ボクサーのファイルに「最後に見せた状態」は持たない（差は記録する瞬間にだけあり、途中で抜けた試合は記録しないので札も出ない）。Enter / A / クリックで次の札へ、最後の札で消える。札の間は本拠地の操作を受けない。

| 札 | 出るとき | 見せ方 |
|---|---|---|
| 勝敗（`Result`） | 毎回 | 勝ちは「勝利！」と光る帯・脈打つ縁、戦績「3勝0敗0分 ▶ 4勝0敗0分」の新しい方が点滅。負け・引き分けは落ち着いた灰青の札で、次の目標（`CampaignPlan.NextGoal`: 推す試合の団体の道で、まだ閉じていて勝ち・席で近づける段）を添える |
| 席が上がった（`RankUp`） | 席の数が小さくなった・ランキングに入った | 「ランキング上昇！」、前の席から今の席へ数字が動き、緑の ▲、「○○ を追い越した」（相手 = 一つ上の席の人） |
| 王座（`Title`） | タイトルに勝った | 金の札にベルト（帯・飾り板・中央の板が光る）、「新王者！」/「防衛成功！」 |
| 解放（`Unlocked`） | 前は出られず、後は出られる大会 | 赤い「NEW!」が点滅、「ランキング戦に挑戦できる！」と大会の名前 |

- 札が出るとき決定の音を鳴らす。動きは描画の時計（`MenuView.Clock`）だけで、試合の計算に入らない（§1.6）。画面写真は時計を止めて撮る。

### 置き場

`%LOCALAPPDATA%\MiniRing\campaign\<id>.json`（2026-11-26 から。`CampaignStore.DefaultDirectory`: `Environment.GetFolderPath(LocalApplicationData)` の下なので Linux は `~/.local/share/MiniRing/campaign`、macOS は `~/Library/Application Support/MiniRing/campaign`）。Roaming（%APPDATA%）でなく Local にしたのは、この PC のゲームの記録でドメインのプロファイルで同期させる物ではないから（キャラメイクの道具の保存 `MiniRing\characters` と同じ根）。前の版の置き場（作業フォルダーの `campaign/`）にファイルがあれば、起動のたびに新しい置き場に無い名前だけを写す（`CampaignStore.CopyLegacy`。古い方は消さない・新しい方を上書きしない）。テストは `MatchMenu` に一時フォルダーを渡す（`campaignDirectory`。null なら設定のファイルの隣で、実際の AppData に触れない）。名簿（組み込みの架空のキャラ）とは別で、id は `my-boxer-<n>`（名簿・置き場と重ならない番号）。

### 出られる条件（2026-11-26 作り直し、ユーザーの採った案）

最初の版は体格で入口を分けていた（IVF 新人王戦はライトヘビー級まで・WVC 60 kg 以上・VFC 70 kg / 140 cm 以上・新人戦はその団体で 3 戦まで・ランキング戦 2 勝）。これでは軽い・小さい体が詰み、身長という強さと関係の薄い線で弾いていた。作り直しで:

1. **出られるかは体重と階級だけ**。身長・体型の線は無い。計量の無い VFC の新人戦は誰でも出られるので、どんな体でも詰まない（`CampaignTests.NoBodyIsStuck_*` が 31〜159 kg を刻んで確かめる）。
2. **入口は戦績**（体格ではない）。大会の型ごとの `record`（数える範囲 `scope` = `career` プロ通算・`org` その団体・`division` その団体のその階級、`maxBouts` = この試合を含めた試合の数の上限、`minWins` = 勝ちの数の下限）を、どの大会も同じ式で見る。

| | IVF | WVC | VFC |
|---|---|---|---|
| 階級 | 5 階級。全階級に新人王戦・ランキング戦・タイトル（別の順位・別の王者） | 無差別 1 本 | 無差別 1 本 |
| 計量 | 前日計量（`entry.weighIn: true`）。大会の階級の上限を超えたら失格（理由を見せ、試合は組まれない） | なし（体重は発表だけ） | なし |
| 武器 | 素手だけ | 団体のファイルの値（持てる） | 何でも |
| 新人戦 | プロ通算 4 戦目まで | プロ通算 4 戦目まで | 戦績の条件なし |
| ランキング戦 | その階級で 3 勝 | プロ通算 3 勝 | VFC で 1 勝 |
| タイトル | その階級のランキング 1 位 | ランキング 1 位 | ランキング 1 位 |

- 判定の順（`CampaignLadder.Check`）: 団体の出場の条件（はめる物・武器・教科書）→ 階級（計量の体重で入る階級が大会の階級か。計量のある団体で上限を超えていれば「前日計量 … 失格」、軽ければ「計量 … はミドル級です」）→ 戦績 → 席。
- 階級を上げて出る（軽い体で上の階級の大会に出る）ことは今はできない: 試合を組むところ（`OrgBouts.Enter`）が同じ階級どうししか組まないので、出られるかの判定もそれに合わせた。上の階級に出たければ増量する。
- WVC の「通算 3 勝」はプロ通算（全団体）、VFC の「1 勝」は VFC での 1 勝と読んだ（`record.scope` を変えれば切り替わる）。

### 大会と席

- **新人戦**（`rookie`）: 相手は同じ階級のランキング外の人を、その階級での試合の数で順に。
- **ランキング戦**（`ranking`）: 相手は一つ上の席の人（ランキング外ならランキングの最下位）。勝てばその席を取る。
- **タイトル**（`title`）: 席が `maxSeat`（1 位）以内。相手は王者（自分が王者なら 1 位の挑戦者 = 防衛戦）。勝てば王者、王者が負ければ 1 位。
- 席は団体の記録（`Orgs/standings/<org>.json`）の順位の間に差し込んで数える（席 k = 記録の k 位の前）。記録そのもの（名簿のキャラの席）はキャンペーンでは書き換えない（ボクサーごとの物語）。
- 席は団体・階級ごと。減量・増量で階級が変われば、新しい階級ではランキング外から。

### 武器

大会ごと（試合の前）に本拠地の「次の試合」で ← → で選び直す。武器を持てるかは団体のファイルの `entry.weapons`（IVF は持てない）。選んだ武器はその試合のキャラクターにだけ付け、体のファイルには書かない（戦績の 1 試合に名前を残す）。

## 残り（将来の本実装）

1. **急な減量の消耗**: 短い間に大きく落とすと、筋肉の太さだけでなく水分・グリコーゲンが抜けて、スタミナ（`Fighter` の酸素・グリコーゲンの層）と意識の戻り（脳の水分）に響く。体の値（体液の量）として持ち、隠れた倍率にしない。
2. **水抜きと戻し**: 前日計量（今は「試合の前に量って上限を超えたら失格」まで）で水を抜いて軽く量り、試合日までに戻す（計量の体重と試合の体の重さが違う）。`OrgBouts.WeightOf` を「計量の時点の体」と「試合の体」に分け、団体のファイルに計量から試合までの時間（戻せる量）を持たせる。土台は `BodySizing.WithWeight`・`CampaignBoxer.ChangeWeight`（筋肉の太さを変える）で、水は体液の量として別に持つ（隠れた倍率にしない）。
9. **階級を上げて出る**: 軽い体で上の階級の大会に出る（実際のボクシングではできる）。`OrgBouts.Enter` が試合の階級を「大会の階級」で受け取るようにすれば、`CampaignLadder` の階級の式を「上限だけ」に緩められる。
10. **札の音**: 喜びの札は決定の音を鳴らすだけ。解放・王座の専用の音（ファンファーレ）はまだ無い。
11. **道の「今は出られない」**: 戦績・席は足りているのに相手がいない（記録の席に名簿の人がいない）段は、短い言葉が「今は出られない」だけ（下の板に理由は出る）。
3. **減量・増量の速さの上限**: 1 試合の間に変えられる量を、体の値（1 週間に作れる筋肉・落とせる脂肪）から出す。今は範囲（太さ 0.6〜1.5 倍）の中なら一度に変えられる。
4. **脂肪の層**: 今の体は筋肉の太さだけで重さが決まる。脂肪（力を出さない重さ）を足すと、同じ体重でも力の違う体が作れる（減量 = 脂肪から落とす）。ボクセルの材質と `TissuePhysiology` に脂肪を足す話になり、`PhysicsVersion` が上がる。
5. **教育（技の最適化）と試合の間の成長**: キャラメイクの新人を試合の合間に育てる（§1.8、`docs/plans/CHARACTER_EDUCATION_PLAN.md`）。今のボクサーは教科書のまま。
6. **キャラメイクの全部**: 今の「作る」は体型・身長・教科書だけ。名前・国・顔・腕と脚の長さは `maker`（ブラウザのキャラメイク）で作れるので、そのファイルをキャンペーンの置き場へ取り込む口を作る。
7. **ランキングの動き**: 名簿のキャラどうしの試合（裏の試合）で席が動く、王者の防衛戦の間隔、引退。今の席はボクサーの勝ち負けだけで動く。
8. **VR のメニュー**: キャンペーンはデスクトップのメニューだけ。
