# 指示書: 戦略の層（GamePlan）— 得意な間合い・相手の得意な間合い・脅威と得の判断（2026-11-18）

ユーザーの指定（原文の要約）:
- 間合いの調査結果（`docs/ROSTER_REPORT.md`・`docs/arena/maai_roster_ranges_bins.csv`・`maai_roster_ranges_summary.csv`）をもとに、**各キャラが自分の得意な間合いを好む**設定を入れる。
- **相手の得意な間合いも情報として持たせ**、戦略として総合的に判断させる。
- **自分と相手のスタミナ・ケガの状態**を認識させ、**脅威と得（メリット）**を判断させる。
- **性格・意識の深さ・経過時間（残り時間）**で変わる関数にし、**膠着しない**工夫を入れる。
- 最適化の優先: 1) 相手により多くのダメージを与える、2) 自分の被ダメージを減らす。ダメージは数字に加えて **K.O.・骨折・切断を取る（取られない）** ことに重きを置く。

先に CLAUDE.md §1（軸）・§1.8（キャラは体＋教育、教育は入力の側だけ）・§4（決まり）と `docs/BOTS.md`・`docs/CHARACTERS.md` を読むこと。

---

## 1. 軸との整合（守ること）

- 出力は今までどおり `FighterCommand` だけ（足運びの目標の距離・手数）。体の強さ・威力の倍率には触れない（§1.7・§1.8）。
- §1.3: 技の種類・状態の名前で分けない。すべて連続の関数（重み・なめらかな最大）で書く。閾値を足したくなったら物理量・測った量で説明できるか考える。
- §1.6: 乱数を足さない（使うなら既存の種付きの `_random`）。時計・壁時計を使わない。試合の時刻はゲームの歩から。
- §1.7: 相手の状態は **見えている手がかりだけ**から読む（相手の `Stamina`・`Consciousness` の値を直接読まない）。自分の体の状態は自分が感じる量として読んでよい（今の `SelfStamina`・`SelfFaintness` と同じ扱い）。
- 既定（教育で入れていないスタイル）の判断は **ビット単位で今と同じ**にする（`GamePlan.Weight` が 0 なら何もしない）。今の全テストのチェックサムが変わらないこと。

## 2. データ: 間合いの表（キャラの教育の値）

`BotStyle` に入れ子の値 `GamePlan`（null 可。null なら層なし）を足す:

```jsonc
"GamePlan": {
  "Weight": 1.0,        // 0..1: 足運びの目標の距離を、この層の距離へどれだけ寄せるか（0 で層なし）
  "Boldness": 1.0,      // 0..3: 得（自分が攻めやすい）を重く見る性格
  "Caution": 1.0,       // 0..3: 脅威（相手が攻めやすい）を重く見る性格
  "Patience": 8.0,      // [s] 打ち合いの無い時間がこれくらい続くと急ぎ始める（膠着を嫌う度合いの逆）
  "Pressure": 1.0,      // 0..3: 残り時間と点差で急ぐ度合い
  "Own": [ { "Cm": 17, "Dealt": 1.93, "Taken": 14.6 }, ... ], // 自分の距離ごとの 1 秒あたりの与えた・受けたダメージ（測定から）
  "Foe": [ ... ]        // 相手の表（試合の始めに相手のキャラの Own から入れる。§2.2）
}
```

### 2.1 Own の作り方
- `docs/arena/maai_roster_ranges_bins.csv` の各選手の行（`mid_cm`, `dealt_per_s`, `taken_per_s`, `seconds`）。**`seconds >= 30` の帯だけ**使う（短い帯は雑音）。
- 道具（スクリプトか `miniring-arena` の小さなコマンド）で、各キャラの `roster/<id>.json` の `education.style.GamePlan.Own` に書き込む。手で 17 人分を写さない。値は小数 2〜3 桁に丸める。
- 測定は PhysicsVersion 43・ドリルの 1.2 m のリング・中央から始める試合でとったもの（`docs/ROSTER_REPORT.md`）。その旨を表の出どころとして文書に書く。

### 2.2 Foe（相手の得意な間合いを情報として持つ）
- `FighterCharacter.Resolve(opponentId)` で相手のキャラが分かるとき、相手の `GamePlan.Own` を自分の `GamePlan.Foe` に入れる（`CharacterRoster.Get(opponentId)` から）。相手の表は「相手のキャラ id で引く値の差し替え」（§1.8 で許されている形）。
- 相手が名簿のキャラでない・表が無いときは Foe は空で、自分の表だけで判断する。
- 記録（リプレイ）は解決済みのスタイル JSON を持つので、Foe もそこに入る（再生は同じになる）ことを確かめる。

## 3. 入力: 見えている・感じている状態（FighterSense に足す）

`FighterSense` に足す（既定値は今の挙動と同じになるもの）。`BoxingGame` の `ArmedSense` / センス作りで埋める:

| 名前 | 中身 | 出どころ |
|---|---|---|
| `SelfInjury` 0..1 | 自分の体の傷み（腕・脚の筋の残り・骨の折れ・切断を合わせた「失った力」） | 自分の `Strength`・`LegCondition`・`BoxerBody` の残りなど、体が既に持っている量から 1 つの連続値に |
| `OpponentInjury` 0..1 | 相手の見えている傷み（削れて残った筋肉の断面・折れた腕・落ちた部位） | 相手の体の **見えている** 量（残ったボクセル・外れた部位）。意識・臓器は入れない |
| `OpponentWinded` 0..1 | 相手の息の上がり（見える手がかり） | `TiredLook` が描くのと同じ量（見た目の手がかり） |
| `Match` | 試合の時刻: このラウンドの経過 [s]・ラウンドの長さ [s]・残りのラウンド数・**点の差**（自分が与えたダメージ − 受けたダメージ、と取った・取られたダウンの差）・**打ち合いの無い時間** [s]（どちらかの打撃が最後に入ってからの時間） | `BoxingGame` が持っているラウンドの時刻・得点・ダウン |

## 4. 判断: GamePlan（新しいファイル `games/MiniRing/Bots/GamePlan.cs`）

毎歩、次を連続に計算する（すべて決定的）:

1. **得の重み** M = Boldness × (1 + 相手の開き `HurtRead.Opening` + OpponentWinded + OpponentInjury) × (0.4 + 0.6 × 自分のスタミナ) × (1 − 0.5 × 自分の意識の薄れ `SelfFaintness`)
2. **脅威の重み** T = Caution × (1 + SelfInjury + SelfFaintness + (1 − 自分のスタミナ)) × (0.5 + 0.5 × (1 − OpponentWinded))
3. **急ぐ度合い** U = Pressure × (負けている量 × ラウンドの進み + (1 − exp(−打ち合いの無い時間 / Patience)))。負けている量は点の差を 0..1 になめらかに直したもの（勝っていれば 0）。ラウンドの進みは経過 / 長さ。
   - M' = M × (1 + U)、T' = T / (1 + U)（膠着・負け・残り少ないほど攻めへ寄る）。
4. **距離ごとの見込み** S(d) = M' × 攻め(d) − T' × 守り(d)
   - 攻め(d) = 自分の Dealt(d) と 相手の Taken(d) の平均（片方しか無ければそれ）
   - 守り(d) = 相手の Dealt(d) と 自分の Taken(d) の平均
   - 表に無い距離は隣の帯から線形に補い、範囲の外は端の値。
5. **好む距離** d* = S を温度つきの重み（softmax、温度は S の幅の 1/4 ほど）で平均した距離 [m]（なめらかな最大。場合分けしない）。
6. **手数の倍率** = (1 + U) × 2M' / (M' + T')（0.5〜2 程度に丸める）。

`BoxerBot` への入れ方:
- `Footwork` の普段の立ち位置（`neutral` / `desired`）を、`Weight` の割合で d* / 腕の長さへ寄せる（打ちに入っている間の `AttackRangeNow` は変えない）。
- `UpdateAttack` の `_cooldown` の進みに手数の倍率を掛ける（`Weight` で 1 から寄せる）。
- 既存の層（危険度・休み・弱った相手を詰める・体格の読み）はそのまま残し、この層はその上に重ねる。

剣・棒・棍棒のボット（`SwordsmanBot`・`ClubBot`）は、この段では入れない（拳・蹴り・はめる物の 12 人だけ）。ただし相手が武器の選手でも Foe の表は使う。武器のボットへの入れ方は §7 に案だけ書く。

## 5. 最適化の物差し（測るとき）

試合ごとの点 = **与えた側の点 − 0.5 × 受けた側の点**。それぞれの点 = ダメージ + 40 × K.O.（取ったラウンド）+ 15 × 骨折（`BoneBreakEvent`）+ 30 × 切断（`SeverEvent`）。重みの根拠（ダウンが勝ちを決めている: 勝ち点率との相関 0.92、`docs/ROSTER_REPORT.md` の初回の考察）を文書に書く。

`miniring-arena` に、名簿の総当たり（`rosterleague` と同じ組み方）でこの物差しを選手ごとに出す出力を足す（既存の `--matrix` に骨折・切断の数の列を足すのでもよい）。

## 6. 確かめ方・完了の条件

1. 単体テスト（`tests/MiniRing.Tests/GamePlanTests.cs`）:
   - 表から d* が「得の山」の近くに来る。相手の得意な距離で脅威が大きいと、d* がそこから離れる。
   - 自分が傷む・意識が薄れる・疲れると d* が脅威から離れる向きへ動く。相手が傷む・息が上がる・開くと得の山へ寄る。
   - 打ち合いの無い時間・負け・ラウンドの終わりに近いほど、d* が得の山（攻め）へ寄り、手数の倍率が上がる（膠着しない）。
   - Weight 0 なら BoxerBot の出力が今と同じ（既存のチェックサムのテストが通る）。
   - 相手の表が Foe に入る（`FighterCharacter.Resolve`）・記録して再生すると一致する。
2. 速いテスト（`run.cmd test`）が通る。全テストは raytrek で（`bash tools/remote-test.sh`）。
3. 版: `BoxerBot.LogicVersion` を上げ、`docs/VERSIONS.md` に 1 行（既定のスタイルの判断は同じだが、キャラの教育で入る）。FighterSense の追加で物理は変わらない（PhysicsVersion はそのまま）。
4. 文書: `docs/BOTS.md` に節を足す（式・入力・出どころの表・近道）。近道は `docs/DEBT.md` に（例: 表は 1.2 m のリングの全員の平均で、相手ごとの表ではない・係数の形は手で決めた）。
