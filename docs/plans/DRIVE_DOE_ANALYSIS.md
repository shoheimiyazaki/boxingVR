## 2. 分かったこと（実測）

### 2.1 拳の速さは「肩の速さ + 肩に対する拳の速さ」の足し算で、本当にそのまま

当たる瞬間、拳の前方成分 = 肩の前方成分 + 肩に対する拳の前方成分が恒等的に成り立つ（全 911 点で差 4e-8）。ピーク同士の和も相関 0.98。足し算の項を別々に直す設計でよい。

| 量（自由、LHS 全点） | 平均 | p10 | p90 | 最大 |
|---|---:|---:|---:|---:|
| 拳の最高速 [m/s] | 5.19 | 4.26 | 6.21 | **7.43** |
| 肩に対する拳（腕の伸び）の最高速 | 4.23 | 3.46 | 5.09 | 6.14 |
| 肩の前進の最高速 | 0.92 | 0.49 | 1.38 | **1.89** |
| 胸の鉛直軸まわりの最大角速度 [rad/s] | 5.08 | 2.33 | 8.31 | 12.6 |

基準（水準が基準の点）では肩 0.43・腕 3.9〜4.05・胸 2.1 rad/s。**25 要素のうち 23 要素を、人の値の範囲を越える所まで同時に動かした 911 点の最良でも、当たる拳は 6.6 m/s、肩の前進は 1.9 m/s**。1 要素ずつ動かすのでは、どの要素も最高速を 5.4 m/s 以上にしない（最大は `ElbowMax` 80 rad/s の 5.37）。前の 2 回で「一つずつ変えても 9 m/s に届かなかった」ことの理由がこれ（つまり、変える値の組み合わせの問題ではなく、構造の問題）。

### 2.2 腕だけ（胸を固定）の速さは、筋の「力と速さの関係」と力の通り道で決まっていて、筋力ではない

- `MaxHandForce` は 350 N 以上で効かない（350 → 700 N で最高速 4.55 → 4.57）。力は **欲しい力（PD）× Hill の速さの関係** で決まり、最大の力は興奮の正規化にしか入らない（興奮 = 欲しい力 / 上限、活性化 × 上限 = 欲しい力）。基準の当たる直前の Hill の係数は **0.09**（`fvAtHit`、平均 0.15）。PD が 590 N を求めても掛かる力は最大 115 N。
- 効く要素は `ElbowMax`（20 → 80 rad/s で 3.7 → 5.4）、`Curvature`（0.12 → 0.5 で 4.2 → 4.9）、`ArmServoHz`（4 → 20 Hz で 4.2 → 4.65）、`HandKp`（200 → 1000 で 4.2 → 4.5、600 で飽和）。`ShoulderMax`・`ActTime`・`MinLeverDeg`・`LooseDamp` はほぼ効かない。
- **打ち出しの瞬間に目標を置く（`Instant`、経路の時間の制限を外す）と最高速は 4.2 m/s と、標準の経路（4.55）より遅い**。腕の速さの限界は経路の時間ではなく腕の筋・関節にある（`MaxTargetSpeed`・平滑化を外しても同じ、前の報告）。
- 縮約モデル（剛体 1 つを、実測の肩の動き・目標・力の上限を入力に、実物と同じ `HandAccel → Excitation → Activate → ArmMuscle.Force` で動かす）の当たり: 腕だけ（固定、250 点）で相関 0.70〜0.83、RMSE 0.85〜1.2 m/s。**質量の格子で最も合うのは 1.4〜2.0 kg**（1.3 kg の前腕に力を掛けるのに、上腕 2.0 kg が肘で引かれて付いてくる分）。上腕 + 前腕 3.3 kg だと実測より 1.0 m/s 遅く出る（腕に掛かる力と質量を同じ量で数えている近道: `desired = accel × 3.3 kg` を 1.3 kg の前腕に掛ける）。残差（実測 − モデル）は +0.5 m/s の偏りで、サーボ（肩 40 N·m・肘 30 N·m が IK の目標へ追う）が関節の外で押している分。つまり **腕の駆動は、Hill の関係で縮む筋 + サーボの二重**で、拳の最高速が 4〜5 m/s になる**以外は大きな外れが無い**（腕の速さ自体は人の 5〜6 m/s に近い）。
- 腕だけの最高速 4.77 m/s の平均は、人の腕の伸び（5〜6）と大きくは違わない。**足りないのは腕ではない**。

### 2.3 足りないのは胴（肩の前進）。胴の回旋が弱くて遅い

- 自由 − 固定の対の差: 拳の最高速 +0.42 m/s（平均）、肩の前進 +0.92 m/s、胸の角速度 +5 rad/s。胴は今ほぼ寄与していない（基準では +0.1 m/s）。
- 胸の角速度（実測）は `UprightKpRatio`（回すバネ）、`MaxTwistDeg`（可動域）、`Telegraph`、`Range`、`TwistBias` で決まる: `UprightKpRatio` 0.5 → 3 で 1.2 → 4.8 rad/s、`MaxTwistDeg` 20° → 70° で 1.4 → 3.75 rad/s。**ひねりのバネの強さ（Kp）が最も効く**。
- 胴のひねりの縮約モデル（胸の鉛直軸 1 自由度を `ApplyUprightImpulse` と同じ PD + 上限で、実測のひねりの目標の系列へ動かす）: 250 点で実測の胸の最大角速度と**相関 0.94**。有効慣性の補正 4（胸の慣性 0.217 kg·m² のほかに、腰・脚・両腕・頭が付いてくる分。骨盤は別の PD で目標を持ち、腕は胸にぶら下がるので、胸の鉛直軸の慣性は見た目の 4 倍）で偏り +0.4・RMSE 0.9 rad/s（実測の SD 2.2）。
- **根本の原因**（体のどの値か）: 胴のひねりは傾きと同じバネ（`UprightKp` = 213 /s²、`UprightKd` = 23.8）で回している。胸の鉛直軸まわりの慣性は 0.217 kg·m²、ひねりの可動域は 35°（0.611 rad）なので、**可動域の端で出せる最大のトルクは 213 × 0.217 × 0.611 = 28 N·m**（人の体幹の回旋は静的に 70〜120 N·m、パンチの動作で 150〜250 N·m 級。**約 1/5**）。加えて、位置のバネだけでは速さが止まる: 減衰 Kd = 23.8 は、目標が動くとき**終端速度を Kp·誤差/Kd に抑える**（誤差 0.6 rad で 5.4 rad/s）。拳を引く PD は目標の速度を先行に使う（`HandAccel` の `targetVelocity`）が、胴のバネには無い。さらに、腕が動く 0.12 秒より遅れてひねりが始まる（目標は拳の動きに従う）。実測: 当たる瞬間までに胸は目標の 25° のうち 2.6° しか回っていない。
- 本物の値との差: 胸の角速度 2 → 8〜12 rad/s（実測）、肩の前進 0.43 → 3〜4 m/s（本物）。足りない 2.6〜3.6 m/s の大半がここ。腕は 4.05 → 5〜6（足りない 1〜2 m/s、筋の最高速 `ElbowMax` 40 rad/s は 10 線維長/s の見積もりで、速筋の 12〜15 線維長/s なら 50〜60 rad/s）。

### 2.4 寄与の順位（拳の速さ、自由、LHS 911 点。2 次 + 相互作用の回帰、交差検証 R² 0.94 / 当たる速さ 0.73）

要素を含む項の分散の割合（最高速 / 当たる速さ）:

1. `Range`（0.23 / 0.34）: 当たる位置（打ち出しから当たるまでの時間）。技の入力ではなく**条件**。遠いほど当たるのが遅く、胴と腕の加速が長く効く。
2. `UprightKpRatio`（0.09 / **0.20**）: **胴を回すバネの強さ**。
3. `MaxHandForce`（0.10 / 0.03）、`Curvature`（0.07 / 0.02）、`ArmServoHz`（0.05 / 0.03）、`HandKp`（0.05）、`BodyDrive`（0.04 / 0.02）: 腕。
4. `ElbowMax`（0.04 / 0.04、線形の効きは最大: ±1 SD で +0.45 m/s）、`Telegraph`（0.02 / 0.04）、`MaxTwistDeg`（0.02 / 0.03）、`TwistBias`（0.03）: 腕の速さと胴。
5. 効かない: `BodyEff`・`BodyTime`・`LeadHz`・`BorrowSpeed`・`ReactShare`・`ShoulderMax`・`MinLeverDeg`・`StepInScale`（0.1 m/s）・`HipShare`。体から拳への移送（`TransferBodyMotion`）は、今は移す運動エネルギーが小さい（約 0.15 J）ので、効率・時定数を変えても結果が動かない（前の報告と同じ）。

乗る質量・エネルギーでは `Range`（0.35 / 0.24）、`MaxTwistDeg`（0.22 / 0.12）、`UprightKpRatio`（0.16 / 0.22）、`Telegraph`（0.11 / 0.09）。胴のひねりが強いと体の質量が拳へ乗る（`BodyCarry`）。

## 3. 結論: 足りない要素と、体のどの値から来るか

| 要素 | 今 | 本物 | 足りない量 | 体の値の由来 |
|---|---:|---:|---:|---|
| 肩の前進（拳の足し算の一項） | 0.43 m/s | 3〜4 | **−2.6〜−3.6** | 胴の回旋の力・速さ |
| 胸の鉛直軸まわりの角速度 | 2.1 rad/s | 8〜12 | −6〜−10 | 回旋筋のトルク（今 28 N·m、人 100〜250）、目標の速さの先行が無い、可動域 |
| 腕の伸び（肩に対する拳） | 3.9〜4.05 m/s | 5〜6 | −1〜−2 | 肘・肩の筋の最高速（線維長・てこ）、Hill の関係。腕だけは人に近い |
| 体から拳への移送 | 約 0.15 J | 数十 J | — | 移す運動エネルギーが胴の動きに比例して小さい。胴が回れば自然に増える |

**胴の回旋（肩の前進）が足りない量の 7〜8 割**。腕は 2 割で、腕の筋の値には人の範囲に近い値が既に入っている（`ElbowMax` を 80 rad/s にしても +0.8 m/s）。

## 4. 直し方の候補（縮約モデルで先に予測）と順位

胴のひねりの縮約モデルを、実測の係数（有効慣性の補正 4）に合わせ、基準の点（種 1、間合い 1.05 腕）で候補を動かして胸の最大角速度を予測した（実測の基準 2.08 rad/s、モデルの基準 1.59 × 較正 1.3）:

| 候補 | 変え方 | 予測の胸の最大角速度 [rad/s] |
|---|---|---:|
| 基準 | — | 2.1 |
| ff | ひねりの目標の速さを、回すバネの先行に入れる（拳の PD と同じ構成） | 4.3 |
| rom50 | 可動域 35° → 50° | 2.6 |
| kp2 | 回すバネ Kp × 2（トルク 28 → 56 N·m 相当） | 4.0 |
| ff + kp2 | 先行 + Kp × 2 | 6.8 |
| ff + rom50 + kp2 | + 可動域 50° | 8.7 |
| ff + rom50 + kp4（Kp × 4、トルク 113 N·m 相当） | | 12.9 |

（LHS 250 点の平均での予測も同じ順序: ff 7.1・kp2 7.8・ff+kp2 10.5・ff+rom50+kp2 11.5・ff+rom50+kp4 15.2 rad/s、基準 4.7。）

順位: (1) **回旋筋のトルクを人の値へ**（Kp を可動域の端で最大トルクになる式へ）+ **ひねりの速さの先行**、(2) 可動域（人の胸椎 + 腰椎の軸回旋は片側 35〜45°、骨盤は股で 40〜50° 加わる）、(3) 腕の筋の最高速（根拠が弱い）。

### 決める変更（実装は分析のあと）

体の値だけを変え、倍率・分岐・技の入力の書き換えは入れない（`FighterTuning` の人の体の値）:

1. **`TrunkRotatorTorque`（新、N·m）**: 胴の回旋筋が出せる最大トルク。ひねりのバネの Kp を `トルク / (胸の鉛直軸の慣性 × 可動域)`（可動域の端でちょうど最大のトルク）、減衰を傾きのバネと同じ減衰比、角加速度の上限を `トルク / その部位の慣性` にする。今の体は暗黙に 28 N·m だった（人の 1/5）。傾き（前後・左右）の `UprightKp` は変えない（立つ・ステップ・倒れる・起きるを守る）。値の候補は実測の掃引で決める（60〜150 N·m の範囲、人の体幹の回旋の静的な値 70〜120 N·m から）。
2. **`TrunkTwistFeedForward`（新、0..1）**: ひねりの目標の速さの先行。拳の PD の `targetVelocity` と同じ構成（1 = 目標と同じ速さで回そうとする）。速さの上限 `TrunkTwistMaxRate` = 15 rad/s（人の体幹の回旋の最高、先行の暴れの抑え）。
3. **可動域 `MaxTorsoTwistRadians`**（35° → 50°）と `HipTwistShare`（腰が受け持つ割合、0.45 → 0.55）: 人の体幹と骨盤の可動域（胸 + 腰椎 35〜45° ＋ 骨盤が股で追加 40〜50°）。ひねりの目標は `tanh` で飽和するので、50° は上限で、ストレートの目標は 0.72 × 50° = 36°。**この変更は実測で掃引して、採るかを決める**（立つ・足の運びのテストへの影響が大きい）。

予測: 胸の角速度 8〜10 rad/s、肩の前進 ≈ 胸の角速度 × 0.21 m = 1.7〜2.1 m/s、腕 4.0 を足して拳 **5.8〜6.2 m/s**（目標 7〜10 に届かない見込み）。届かない分の理由: (a) 打ち出しから当たるまで 0.128 秒で、胴の回旋が最高速に乗る前に当たる（技の入力の時間、変えない）、(b) 腕の筋の最高速（`ElbowMax`）、(c) 肩の前進のもう一つの源（肩甲骨の前方突出、10〜15 cm・1〜2 m/s）は剛体の肩に無い。いずれも倍率や水増しでは補わない。

## 6. 実装後の追記（掃引・ホールドアウト。上の 1〜5 は変更前に書いたまま）

### 6.1 水準の選び方（実測の掃引 `doe_trunk_grid.csv`、基準の点、288 本）

胴の回旋筋のトルク {28.2, 60, 90, 120, 150, 200} N·m × 先行 {0, 1} × 可動域 {35, 45, 50, 60}° × 腰の割合 {0.45, 0.55, 0.7} × 間合い {1.05, 1.3 腕} の完全格子。

- 胸の最大角速度（実測）: 基準 2.2 → トルク 120 + 先行 5.9（可動域 35°）。縮約モデル（有効慣性の補正 4）の予測 5.3〜6.7（基準の点での較正前後）と同じ桁で、順序（先行 + トルクが最大）も一致。
- **肩の前進は胸の角速度 1 rad/s あたり 0.11 m/s しか増えない**（分析 §4 の「0.21 m」は基準の値で、その中の並進分を回転のてこと取り違えた誤り。胸の軸から肩までの横の距離は 0.11〜0.15 m）。そのため、胸の角速度を予測どおり 8〜10 rad/s にしても、肩は 1.1〜1.3 m/s、拳は 5.0〜5.6 m/s で、§4 の予測（5.8〜6.2 m/s）は約 0.5 m/s 楽観的だった。
- 可動域 35 → 60°・腰の割合 0.45 → 0.7 の効きは小さい（トルク 120・先行 1 で拳の最高速 +0.07 m/s、胸の角速度 +1.8 rad/s、エネルギー +35 J）。腰の割合は ±0.02 m/s 以内。立つ・足の運びへの影響が読めないので可動域・腰の割合は前のまま。
- トルク: 28 → 60 → 90 → 120 → 150 → 200 N·m で拳の最高速（先行 1・可動域 35°）4.70 → 4.90 → 4.99 → 4.97 → 5.09 → 5.19 m/s。効きは 90 N·m 以上でなだらかになる。**120 N·m を採る**（人の静的な最大 70〜120 N·m の上の端。150 以上は人の動的な値の範囲だが、根拠がなく、拳の最高速は +0.1 m/s ずつにしか増えない）。
- 質量: 基準 6.34 kg が 8.6〜10 kg になる（胴が回ると体の質量が拳へ乗る `BodyCarry`）。目標の 2〜5 kg からは離れる。これは腕の質量 3.3 kg を全部加える近道と体の運びの式（DEBT「拳に乗る体の質量」）の問題で、この変更の範囲外。エネルギー 63.6 → 105 J は目標（60〜200 J）の中。

### 6.4 届かない分の内訳（物理の理由。倍率で埋めない）

- 拳 = 肩の前進 0.94 + 腕の伸び 3.9。目標 9 m/s には肩 3〜4 が要り、残りの足りない量は −2〜−3 m/s。
- 肩の前進の源は 3 つ: (1) 胴の回旋（今回直した。胸 5.9 rad/s で +0.7 m/s。肩が胸の軸から 0.11〜0.15 m しか離れず、人の 0.19 m より狭い）、(2) 体の前進（基準で 0.07 m/s。技の `StepIn` 0.35 × `WalkSpeed` 0.92 m/s = 0.32 m/s の目標しか無く、`StepInScale` を 3 倍にしても拳 +0.1 m/s。技の入力）、(3) 肩甲骨の前方突出（人で 10〜15 cm・1〜2 m/s。剛体の肩に無い）。人は (2)(3) と、後ろ足を軸に体全体が回る動き（今は胸・腰がそれぞれの重心まわりに回る）が合わさって肩 3〜4 m/s になる。
- 腕の伸び（肩に対する拳）3.9〜4.1 m/s は、人の 4〜5.5 に近い（肘の角速度は当たる直前で 24 rad/s: 人のパンチの 17〜26 rad/s の範囲）。
- 当たる 0.128 秒は技の経路の時間（`ArrivalShare` 0.18 × 0.67 s = 0.121 s）で、体幹の回旋が最高速に乗る前に当たる（胸の角速度は当たる瞬間に増加中）。技の入力は変えない。
