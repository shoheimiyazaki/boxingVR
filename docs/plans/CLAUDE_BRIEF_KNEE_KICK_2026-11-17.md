# 指示書: 膝を制御点にした蹴り（2026-11-17）

先に `CLAUDE.md`（§1・§4・§8 の空手 (2)・テコンドー）、`docs/KARATE.md`、`docs/TAEKWONDO.md` を読むこと。日本語でコメント・文書を書く。

## ユーザーの指定（そのまま）

- キックは**膝の位置にバネの制御点**を置く。膝の制御点は**位置**と**ねじり方向の回転**を目標とする。
- その先のスネは、膝が伸びる・曲げるの **1 次元の動きだけ**を入力できる。
- したがって、キックは **膝の位置・ねじり角・膝の曲げ伸ばし** の 3 つでコントロールする。
- 回し蹴りの基本: 1. 横に膝を上げる（ねじり角・膝の曲げ伸ばしはフリー）。2. 前方に膝を回す。同時にねじり角はスネが目標に向くように。膝は伸ばす。
- 距離ごとにフォームは変わる。**足首とスネの中間辺り**が目標に当たるように調整しつつ、**威力が最大になる間合い**も覚えさせる。

## いまの仕組み（調べた所）

- `LegCommand(TargetLocal = 足首の目標, KneeTargetLocal = 膝を向ける向き, Orientation, Spring)`。`Fighter.ApplyLegs` が `LegIk.Solve` で股のサーボ（3 軸の角度のサーボ）と膝のサーボ（蝶番）の目標を出し、`DriveFoot` が足首を PD 力で引く（蹴りは `KickFootForceGain` 4 倍、反作用は骨盤）。
- 蹴りの技は `Bots/KickSpec.cs`（足首の経路 ＋ `FaceYaw`・`TorsoTwist`）、選び方は `BotStyle.KickRangeFit`・`KickWeights`、テコンドーは `Bots/taekwondo.json`。

## 決めたこと（設計）

1. **入力の契約**: `LegCommand` に膝の制御を足す（足首の目標の型は残すが、蹴りはすべて膝の制御へ移す: §1.5 一つの現象には一つのモデル）。
   - `Vector3? KneeLocal` — 膝（腿の先の点）の位置の目標（体フレームのローカル [m]）。
   - `float? KneeTwist` — 腿の軸（股 → 膝）まわりのねじり [rad]（0 = 足の向きの立った形）。null = フリー。
   - `float? KneeBend` — 膝の曲げ [rad]（0 = 伸ばしきり、`LegIk.MaxKnee` まで）。null = フリー。
   - 契約の形（record のメンバーにするか別の record にするか）は任せる。`ReplayFile` の版を上げて記録する。
2. **体の側（物理）**:
   - 膝の点を PD 力で目標へ引く（反作用は骨盤。拳・足首と同じ `FighterMath.HandAccel`）。力の上限は今の `KickFootForceGain` の考え方を膝へ移した値（新しい名前の調整値にし、根拠を書く）。
   - 股のサーボの目標 = 「立った形の腿の向き → 股から膝の目標への向き」へ振る回転 × 腿の軸まわりの `KneeTwist`。フリーのときは、今の腿のねじり（今の腿の回転を振りとねじりに分けたねじりの分）を目標にして、ねじりにはトルクを掛けない。
   - 膝のサーボの目標 = `KneeBend`。フリーのときは今の膝の角度を目標にする（バネは効かずダンパだけ）。
   - 蹴りの間、足首を直接引く力は使わない（スネの先は膝の曲げ伸ばしと慣性で振られる。足首の角度の目標は今まで通りでよい）。
   - `Fighter.PhysicsVersion` を上げる。
3. **回し蹴りの経路**（`KickSpec` を膝・ねじり・曲げの経路に書き換える。技の分岐は書かず、目標の時間変化として）:
   - 段 1（抱え）: 膝を蹴る側の横・腰の高さほどへ上げる。ねじり・曲げはフリー。
   - 段 2（回し）: 膝を前（目標の方）へ回す。ねじりはスネが目標を向くように（膝の曲げの平面が目標を含むようにする角を幾何で出す）。膝は伸ばす。
   - 体の向き・胴のひねりの経路（`FaceYaw`・`TorsoTwist`）は今の回し蹴りのものを出発点に。
   - **距離でフォームが変わる**: 当たる瞬間に、スネの「膝から長さの f の点」（f は足首とスネの中間 = 0.75 前後、`KickSpec` の値にする）が目標に来るように、膝の目標の位置（と伸ばしの量）を目標までの距離から連続に出す。遠すぎて膝が届かないときは届く所まで（踏み込みは今の蹴りの足の運びのまま）。
4. **他の蹴り**（前蹴り・横蹴り・後ろ蹴り・かかと落とし・空手の 5 種の蹴り）も膝・ねじり・曲げの経路へ移す。まず回し蹴りを完成させ、残りは順に。時間が足りなければ、移せた物・移せなかった物を報告し、移せなかった物は古い足首の経路のまま動くようにして §8 に書く。
5. **間合いを覚える**（§1.8: 学ぶのは試合と試合の間だけ・使っていない種で比べ直す）:
   - Arena に `kicklab` を作る: 蹴る人（テコンドーのキャラ）と立っているだけの相手で、間合い（距離）を刻んで回し蹴りを蹴り、蹴りごとに「当たったか・当たったスネの点（膝から足首までの割合）・相手へ渡した運動量／エネルギー（`ApplyHit` の値）」を表にする。種は複数。
   - 威力（渡したエネルギーの平均）が最大の間合いを、ボットが使う値（`KickSpec` の届く間合い `Standoff` か、テコンドーの教科書 `taekwondo.json` / キャラの教育）として書き込む。使っていない種で比べ直して良いときだけ採る。結果を `docs/arena/kicklab_*.md` に残す。
   - ボットの判断が変わったら `BoxerBot.LogicVersion` を上げ、履歴に 1 行。

## 完了の条件（優先順）

1. テスト（数値で物理を確かめる）:
   - 膝の制御点が目標の位置へ近づく（膝の位置の誤差が小さくなる）。
   - `KneeTwist` を与えると腿のねじりがその角へ向かう。フリーなら股のサーボがねじりへトルクを掛けない（ねじりが外から与えた回転のまま残る、など）。
   - `KneeBend` で膝が曲がる・伸びる。フリーなら膝はバネで戻らない。
   - 回し蹴りが、kicklab で決めた間合いで相手に当たり、当たったスネの点が膝から 0.5〜1.0 の範囲に入る（種を複数）。
   - 蹴りを入れた記録が再生で一致する。
2. kicklab の表（間合い × 威力・当たり・当たった点）と、採った間合い。
3. 回し蹴りの動画（3 つの間合い。`--slow` 相当で遅く）を撮り、コマを PNG に抜いて自分で見る: 膝が横へ上がり、前へ回りながらスネが伸びて、スネの下の方が当たっていること。動画の作り方は Arena の既存のコマンド（`karatelab --video` や `imitate`、なければ小さく足す）。
4. 全テスト `dotnet test tests/MiniRing.Tests --filter "FullyQualifiedName!~Probe"` が通る。README のテスト件数を合わせる。
5. 文書: `docs/TAEKWONDO.md`・`docs/KARATE.md` の蹴りの節を膝の制御に書き換え、`CLAUDE.md` §8 の空手 (2)・テコンドーの近道（足首 1 点の力の上限 → 膝の点の力）を直す。
