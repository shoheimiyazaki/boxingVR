## 式と実装

来る点の速さ v を腕の長さ/s、到達までを t 秒とし、r=(v/12)²×(Horizon+0.12)/(max(t,0)+0.12)、流す割合 y=r/(1+r)。傾きは 0.05+(1.1−0.05)y rad、押し込み 0.3(1−y) 腕、引き 0.08y 腕。迎える所は来る点より 0.3 腕手前、自分の刀の Forte 0.35、相手の握り側 Bind 0.3。全係数は SwordDefense/JSON で指定できる。

足と頭の割合は 1−(1−y)t/(t+CounterTime)/(1+d)。d は相手の届く半径へ体が残る深さ（腕単位）。打ちの種類の分岐は使わず、方向の分類はドリルの報告だけにある。迎える線は最初の観測で固定し、負荷の量は毎歩追う。向きの符号は前の受けを基準にする。

押す向きは相手の刃の軸に垂直な面へ射影するので、式の角度は射影前の目標。実際の刀の向きは幾何にも依存する。上からの打ちではほぼ水平、軸に沿う突きでは横に押すことをテストした。質量・残った筋力は見ず、速さ²を負荷の代理にする近似は CLAUDE.md §8 に記録した。

返しは、脅威が消え、相手の剣先の向き・速さが体の外へ向き、刃全体が 0.12 秒先まで体の線から 0.6 腕以上離れるときに許す。既存の Counter が間合いの差が小さい技を選ぶ。新しい打ちが来たとき・計画の時間切れで、保留した返しを取り消す。

## 検証

最終係数の Release ビルドで守りの 18 テストが成功（新規 9 件）。速さだけを変えたときの単調性・連続性、頭上の水平な目標、突きの横への押し、同種の指令と実体ドリルの決定性、返しの中断・時間切れ、同じ打ちの加速に追従することを確認した。

Probe を除く全体を Release で実行した（916 件、13 分 44 秒）。最初は 911 成功・2 失敗・既存スキップ 3。失敗は既存の LiveStreamTests の 2 件で、環境の ffmpeg 4.2.1 が NVENC の p4 と SRT を持たないためだった。テストの期待値や配信コードは変更せず、対応版をテスト出力先へ一時配置して該当 2 件を再実行し、2 件とも成功（9 秒）。再実行を反映した内訳は **913 成功・既存スキップ 3**（うち visual 16 成功、通常は 897 成功・3 スキップ）。README を実測件数へ合わせた。係数調整後のビルドでも、別の出力先で守りの 18 件を再実行し成功した。

対応 ffmpeg は [FFmpeg 公式のダウンロード案内](https://ffmpeg.org/download.html) に掲載された [Gyan の配布物](https://www.gyan.dev/ffmpeg/builds/) 9.0.2。SHA-256 は 4705843ccaaf54257c16ad90f3e952ece33c17df964ecf7bfdbb0f49c7171077 で配布元と一致した。システムの ffmpeg は置き換えていない。全体の TRX は `.visualcheck/testresults/sword_defense.trx`、再実行は `sword_defense_live_fixed.trx`。独立レビューは 2 回実施し、相手以外の接触の誤集計、保留返しの失効、負荷の初回固定を修正し、回帰テストを追加した。
