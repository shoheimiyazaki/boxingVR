# 指示書 C: 団体ごとに別の番組にする（番組の型の骨組みと VFC の番組一式・放送席）

先に読む: 根の `CLAUDE.md`、`docs/LLM_CONTENT.md`（LLM で作るコンテンツの軸。**必ず守る**）、`docs/TV_BROADCAST.md`（§1.1 団体・§3 映像の演出）、`docs/commentary/styles/prospective.md`、`docs/VFC.md`、`docs/plans/VFC_PLAN.md`。
コード: `games/MiniRing.Arena/TvShowGraphics.cs`・`VideoMaker.cs`・`TvDirector.cs`・`Organization.cs`・`Orgs/*.json`・`VfcEmblem.cs`・`WvcEmblem.cs`、`games/MiniRing/Audio/Broadcast.cs`、`tools/tvshow/tvshow.ps1`・`tools/tvshow/prospective/run.js`・`config.json`、`tools/commentary/Synthesize.ps1`、`games/MiniRing/Characters/CharacterPortraits.cs`（ボクセルから写した肖像）。

## ユーザーの指定（2026-11-18）

> 中継中の UI や選手紹介や対戦カード表示、その他の構成自体を各団体で全く違うものにして、完全に別系統の大会・テレビ番組であることを強調してください。

- **WVC**: 格式の高いボクシング団体の、地上波の格式ある中継（今の番組がこれ。金・白・濃紺、ゴング、本日のプログラムの表 → 金の紋章 → 選手の比較の表 → 試合 → 判定・ダメージ表）。
- **VFC**: 何でもありの、レフェリーなし・相手が死ぬまでの金網の試合。**深夜の有料配信のケージファイト**の番組にする。WVC の番組の画面・順番・言葉を流用しない（色を変えただけに見えないこと）。

## 目的

番組の構成（試合の前の場面の並び・試合中の画面・休みの画面・リプレイの出入り・決着の画面・放送席）を、**団体ごとの「番組の型」**として差し替えられるようにし、VFC の番組を一式作る。WVC の番組は今のまま（出力がバイト単位で同じ）。

## 守ること

- 試合の物理・決まりには触れない（描画・音・中継の記録・台本だけ）。`BoxingGame` は読むだけ。
- コードに団体名の分岐（`if (org.Id == "vfc")`）を書かない。団体のファイルが番組の型の id を持ち、型ごとのクラスが描く。
- **WVC はバイト単位で今と同じ**: 変更前後で、WVC の冒頭・表・試合中・休み・リプレイ・勝敗の画面の図形と文字を一時テストでダンプして比べる（前の作業で B がやった方法）。音も同じ（ゴングは今日 0.45 に下げた後の値が基準）。
- LLM に渡す物は `docs/LLM_CONTENT.md` に従う: 放送席の人物の説明に、口ぐせ・言い回しの例・「〜を言え」を書かない。役割・人物の経歴・場（番組の性格・どれだけ時間があるか）だけ。
- 見えている状態だけを画面に出す（CLAUDE.md §1.7）: 体の図は、見えている欠損（失った部位・折れた部位・削れた量）から描く。見えない数値（意識・臓器の割合・スタミナの数字）は画面に出さない。

## やること（優先順）

### 1. 番組の型の骨組み
- `games/MiniRing.Arena/Shows/`（例）に番組の型の抽象（例 `TvShowFormat`）を作る。最低限の口:
  - 試合の前の場面の並び（場面ごとの id・中継の記録に書く出来事の種類・秒数・画面の説明の文）と、場面ごとの描画（2D の重ね絵。場面によっては試合の 3D の絵を下に敷く: 下の「生の絵の上の場面」）
  - 試合中の重ね絵（`MatchHud` 相当）、休み中の重ね絵（無ければ何も足さない）、リプレイの重ね絵と出入りのワイプ、決着の画面
- 今の `TvShowGraphics` の WVC の描画を `WvcShow`（例）へ移す（中身は変えない）。`VideoMaker` は試合の前の時間（`TitleSeconds`）・決着の画面の秒数を、番組の型の場面の並びから決める。
- 団体のファイルに `"show": "<型の id>"` を足す（WVC は今の型、VFC は新しい型）。検査は他の欄と同じ（知らない id は例外）。
- 中継の記録（events.json）: 試合の前の場面は、それぞれの出来事（種類と画面の説明）を書く。**プロスペクティブ実況（`run.js`）が新しい種類を団体の名前で知らなくても扱えること**: 試合の前の場面だという印（例 `"prefight": true`、または events.json の上の方の場面の一覧）を events.json に書き、`run.js` の `SCREEN`・`triggers`・`frames`・`knownFrom` がそれを使う（団体名・場面の名前の決め打ちを `run.js` に足さない）。`tvdraft`・`tvdigest`・`tvlint` も新しい場面で壊れないこと。

### 2. VFC の番組（`VfcShow`）
色は団体のファイルの値（黒・クリーム・赤）。字形はボクセルの角張った文字（`VoxelWord` 系を使ってよい）か、太いゴシック。斜めの切り口（平行四辺形の帯）・赤い斜線・荒い四角。WVC の金の細い罫・菱形の飾り・中央揃えの上品な配置・角丸の板は使わない。

試合の前（合計 22〜26 秒。場面の秒数は型の中の名前つきの定数にし、理由をコメントに書く）:
1. **コールドオープン**（約 5 秒）: 暗い檻の生の絵（試合の 3D の絵。カメラは檻の外をゆっくり回る）に、短い字幕を 1 行ずつ: 「レフェリーなし」「ダウンなし」「どちらかが死ぬまで」。最後にホーンと一緒に VFC の紋章が強く入る（少し揺れる・大きくなって止まる）。
2. **ファイトポスター**（約 6 秒）: 2 人の肖像（`CharacterPortraits` の全身か顔。キャラクターなら必ず出す）を左右に大きく、間を赤い斜めの切り口で割る。大きな名前・武器（はめる物）・大会名と何試合目。「今夜のメインイベント」の看板の作り。WVC の比較の表（行ごとの年齢・身長…の表）は使わない。
3. **入場（ウォークアウト）** 赤・青 各約 5 秒: 生の絵（その選手を低い所から映すカメラ。既存のカメラの種類を使ってよい）の左下に斜めの帯: 名前・本名・武器／はめる物・身長・体重・リーチ・戦績（VFC の言い方。判定は無い）・選手の口癖（名簿の資料にある物を引用として）。
4. **フェイスオフ**（約 4 秒）: 2 人の顔の窓を画面いっぱいに左右に並べる（顔のカメラ。既存の facecam の仕組み）。中央に「FACE OFF」。終わりにホーン → 試合。
- 札に複数の試合（`program`）があるとき: WVC の「本日のプログラム」の表の代わりに、VFC の「ファイトカード」（縦に並んだ対戦の帯、済んだ試合は勝者と決着の部位）を、ポスターの前に出す。

試合中（`MatchHud`）:
- 左上: 黒い斜めの板に赤い縁、「R1 / 5」と残り時間（真ん中の大きな時計は使わない）。右上: 小さな VFC の紋章と赤い「● LIVE」ではなく「PPV」などの深夜配信の札（言葉は団体のファイル）。
- 下: 画面いっぱいの黒い帯に、左右に両者の名前（角張った字）、その内側に**体の図**（頭・胴・両腕・両脚の小さなボクセルの人形。無傷はクリーム、削れた割合で赤へ、折れた部位はひびの入った暗い赤、失った部位は輪郭だけ）。データは `BoxerBody`（見えている欠損）から。
- 顔の窓（facecam）を使うなら、WVC と違う形・位置（例: 帯の上に台形の窓）。
- ダウンのカウントは無い（団体の `countsDowns`）。

休み（`Interval`）:
- 画面の左 1/3 に「INTERVAL」と「傷は治らない」の看板と、両者の体の図を大きく。図の横に、見えている傷を短い言葉で（「左前腕 骨折」「右上腕から先を失った」「右目」）。休みの最初の 8 秒ほど出して消える（カメラの切り替えは今の `TvDirector` のまま）。

リプレイ: 出入りは赤い斜線が画面を横切るワイプ、左上に「REWIND」と巻き戻しの記号、画面の上下に細い赤い帯。WVC の金の帯のワイプは使わない。

決着の画面（秒数は型が決める。今の 9 秒でもよい）:
- 黒の背景に、勝者の名前を大きく、その下に「決着」と、言葉にした死因（「首を断たれて」「脳を壊されて」など。死因の訳は今の表を使う）、時刻（R1 0:16）。両者の最後の体の図（敗者の図は灰色に沈める）。
- 両者生還の引き分け: 「両者生還」と両者の体の図。
- WVC の「与えたダメージ」の表（判定の名残）は出さない。

音: コールドオープンの紋章・試合開始・決着の合図はホーン（今の `HornSound`。大きさは今日 0.45 に下げた）。新しい合成音を足すなら、試合の終わりのように驚くほど大きくしない（ピークはホーン以下）。

### 3. VFC の放送席（実況・解説の人物と声）
- 団体のファイルに放送席（`cast`）を足す: 席ごと（`announcer`・`commentator`）に名前・人物の説明のファイル・声（`Synthesize.ps1` の `speakers` の形: 声の名前の断片・rate・pitch・volume・excited）。WVC は今の立花・佐伯と今の声（値を今の既定から写す。出力が変わらないこと）。
- VFC の人物を新しく 2 人作る（`docs/commentary/personas/<id>.md`、`docs/LLM_CONTENT.md` §1 に従う: 経歴と役割と場だけ。口ぐせ・言い回しの例・話題の指定は書かない）:
  - 実況: 深夜の格闘配信を長く担当してきた実況（名前は架空の日本人名を付ける）。
  - 解説: VFC のケージドクター（リングドクター）を務めてきた元救命救急医。体の壊れ方・失った部位・残っている体で何ができるかを読む人。
- 声は WVC と聞き分けられるように（Windows の日本語の声は Ichiro・Ayumi・Haruka・Sayaka。VFC の実況は Ichiro の pitch・rate を変える、解説は Sayaka など。実際に読み上げて聞き分けられるか、波形の長さ・高さで確かめる）。
- `run.js`（`config.json` の `seats`）と `write-commentary.ps1`・`Synthesize.ps1`・`tvshow.ps1` が、札の団体の放送席を使う（団体のファイルから読む。`run.js` に団体名を書かない）。

### 4. 確かめる
- 各場面の PNG（VFC: コールドオープン 3 コマ・ポスター・入場 赤青・フェイスオフ・試合中・休み・リプレイ・決着・両者生還・ファイトカード。WVC: 今の全場面）を `.visualcheck/` に出し、**自分で開いて見る**。VFC と WVC を並べて、別の番組に見えるかを自分の言葉で報告に書く。
- WVC のバイト一致（上の「守ること」）。
- 全テスト `dotnet test tests/MiniRing.Tests --filter "FullyQualifiedName!~Probe"`（件数を報告、README を合わせる）。新しい描画・場面の並び・events.json の印・放送席の読み込みにテストを足す。
- `tools/tvshow/cards/vfc-test.json` を `tvshow.ps1` で**最後まで**回す（下見 → 撮影 → プロスペクティブ実況（LLM、Haiku）→ 声入れ → 点検 → 結合）。下見の種の数は 4 に減らしてよい。動画のコマ（試合の前の各場面・試合中・決着）を切り出して自分で見る。読み上げた台本を読み、新しい放送席の 2 人が話していること・試合の前の場面で話せていることを確かめる。かかったトークン・料金が出せれば報告。
