# 指示書: 棒を手の中で滑らせる握り（2026-11-17）

先に `CLAUDE.md`（特に §1・§4・§8 の棒術）と `docs/BOJUTSU.md` を読むこと。日本語でコメント・文書を書く。

## ユーザーの指定（そのまま）

- 棒を手の中ですべらせることができる物理にする。VR でトリガーを引いている間は保持、引いていないときは棒が滑る。
- 棒術では持つ場所を動きの中で滑らせて変え、左右を入れ替える。それを再現する。
- **両手で持っているとき**は位置へのバネ（両手とも）。
- **片方のトリガーを離しているとき**（滑らせて左右を入れ替えるときなど）は、握っている手で **位置＋モーメントのバネ**。
- **滑っている手からは棒に力が伝わらない**。
- 両手のトリガーが引かれていると、VR コントローラの距離が一定でないため、棒の握る位置と矛盾が出る。その場合、片方の手を滑らせて矛盾を小さくする。**滑らせるのは棒の中心に近い方の手。端を持っている手は固定。**

## 決めたこと（設計）

1. **入力の契約**: `HandCommand.Slide`（bool、既定 false = 握ったまま）は追加済み（`FighterCommand.cs`）。VR はトリガーを離している手を `Slide = true` にする（VR 側は別の作業）。
2. **滑らせられる武器**: `Weapon.SlideSpanOf(WeaponKind)` → 握れる X の範囲（武器のローカル、null なら滑らない）。棒は「両端の丸み・`StaffTipInset` を除いた軸のほぼ全体」。刀・ロングソードなど柄の短い物は null（今まで通り。`Slide` は無視）。種類の一覧に足す形は既存の `CanTwoHand` と同じ近道（§8 に書く）。
3. **手ごとの握りの状態**（滑らせられる武器だけ）: 「握っている（握りの点 x）」か「滑っている（つなぎ無し）」。
   - 握っている手: 拳と棒を玉継手（既存と同じ `AddBallSocket`、30 Hz）でつなぐ。握りの点は `(x, 0, 0)`。
   - 両手とも握っている: **手首の角度のサーボは使わない**（最大トルク 0 か外す）。位置のバネ 2 つの偶力だけで棒が回る。
   - 片手だけ握っている: その手に玉継手 ＋ 手首の角度のサーボ（既存の `WristServoHz`・`WristMaxTorque`・`OneHandWristShare` の考え方）。向きの目標はその手の `HandCommand.Orientation`（null なら握った瞬間の相対の向きを保つ）。
   - 滑っている手: 棒とのつなぎ無し・力無し。拳の目標は **その手の指令の目標**（VR ならコントローラ）。腕の反作用は体へだけ。
   - 握り直し: `Slide` が false になった歩に、拳から棒の軸への最寄りの点が `SlideSpanOf` の中で `SupportGripReach` 以内なら、その x を新しい握りの点にしてつなぐ。届かなければ滑ったまま（届いたら握る）。
   - 左右の入れ替え: 今の「利き手（`Held`）＋ 添え手（`Support`）」の役は残してよいが、利き手が滑り、添え手だけが握っているときは、**添え手を利き手に昇格**させる（`Wields`・`WieldedBody`・`WeaponSense`・`CarriedMass`・`LoosenGrip`・死んだ手の握り・自分との衝突の切り方が壊れないこと）。両手とも滑っている間も、武器は本人の物（自分の体との衝突は切ったまま、握り直せる）。
4. **両手で握っている間の目標**: 滑らせられる武器では、添え手の拳の目標も **その手自身の指令**（`SupportTarget` の上書きをしない）。ボットの棒の型（`StaffForms` → `SwordForms.FromKeys`）は左手を「右手 − 棒の向き × Spacing」で出しているはずなので、`FormSwordsman` などが実際に左手に何を送っているかを確かめ、食い違えば左手の指令を棒の上の握りに合わせる（判断の側で。`LogicVersion` を上げる）。
5. **矛盾の解消（両手とも握っている）**: 両手の目標の距離 d_cmd と、握りの点の間隔 d_grip = |x_L − x_R|（ワールドの長さ）の差を、**棒の中心（x = 0）に近い方の手**の握りの点を棒に沿って動かして詰める。速さの上限 `FighterTuning.GripSlideSpeed` [m/s]（値と根拠をコメントに）。端の手の x は変えない。握りの点は `SlideSpanOf` の中・両手の最小間隔（手の幅ほど、`FighterTuning` に）より離す。玉継手のずれは `PhysicsWorld.SetBallSocketOffsets` で変える（作り直さない）。これは「握ったまま滑る」近道で、摩擦の上限から出したものではない → §8 に書く。
6. **版**: `Fighter.PhysicsVersion` を上げる（棒の両手持ちの物理が変わる）。`ReplayFile` の版を上げ、`Slide` を記録する（古い版は false で読む）。判断を変えたら `BoxerBot.LogicVersion` も。

## 完了の条件（優先順）

1. テスト（`tests/MiniRing.Tests`、数値で物理を確かめる）:
   - 滑っている手は棒に力を伝えない: 右手だけ握り、左手を `Slide` にして左の目標を大きく振り回しても、棒の動きが「左手を使わない」ときとほぼ同じ。
   - 片手で握ると向きの目標へ回る（手首のモーメントが効く）。両手で握っていると手首のサーボのトルクが 0。
   - 両手で握り、目標の距離を握りの間隔より広げると、中心に近い手の握りの x が動き、端の手の x は変わらない。
   - 入れ替え: 右手で握り、左手を滑らせて別の x で握り直し、右手を離す → 左手が利き手になり `Wields` は続き、棒は落ちない。もう一度右手で握り直せる。
   - `Slide` を入れた記録が再生でビット単位に一致する（`ReplayTests` の流儀）。
2. 棒術の物差しを前後で比べる: `dotnet run --project games/MiniRing.Arena -c Release -- handlelab --pairs daichi:jin,daichi:konrad --bouts 4 --seconds 40 --out docs/arena/staff_slide_handlelab.md`（変更前の数字は main の同じコマンドで、または `docs/arena/` の既存の記録）。自傷・当たりが大きく悪化したら原因を調べて報告（直せれば直す）。
3. 棒の型の動画を 1 本: `... -- imitate --weapon staff --only tsuki --slow 4 --out docs/video/staff_slide_tsuki.mp4`。コマを数枚 PNG に抜いて自分で見る（両手が棒の上にあり、棒が手から外れていない）。
4. 全テスト `dotnet test tests/MiniRing.Tests --filter "FullyQualifiedName!~Probe"` が通る。README のテスト件数を合わせる。
5. 文書: `docs/BOJUTSU.md` に「滑る握り」の節、`CLAUDE.md` §8 の棒術 (2)（両手の握りは固定の 2 点）を書き換え、矛盾の解消・種類の一覧の近道を足す。

## 注意

- 他の武器（刀・ロングソード・こんぼう・トンファー・盾）の物理は変えない。既存のテストのチェックサムが変わったら、棒を使うものだけであることを確かめる。
- 別の作業が並行で `Footwork.cs`・脚の部分・`KickSpec`（蹴り）と VR ホスト（`games/MiniRing.Vr`）を触る。そこは触らない。`Fighter.cs` は腕・武器の部分だけを触る。

- 最後の報告: 変えたファイル・設計の判断・テスト結果（件数）・handlelab の前後の表・動画のパス・残った問題。確かめていない数字は書かない。
