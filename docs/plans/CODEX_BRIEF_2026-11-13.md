## 作業 B: キーボードの「意図」で動かす操作（計画 → 実装）

### ユーザーの要望（原文の趣旨）
シェンムーやゴースト・オブ・ツシマのように、方向キーと行動キー（弱攻撃・強攻撃・回避など）の組み合わせ ＋ 状況から技を出す。キー入力からプレイヤーの意図を読み取って行動させ、**命令している感覚ではなく、自分でダイレクトに動かしている感覚**にする。

### 守ること（CLAUDE.md の軸）
- 出力は `FighterCommand` だけ。体はバネで追う。アニメーション・姿勢の書き込み禁止（§1.1・§1.2）。
- **意図 → 技の選択 → 目標の経路**の 3 段（§2）。技の実行部はボットと共有する（`Bots/` の `PunchSpec`・`Technique`・`DefenseBook`・`Combo`・`OpponentRead`）。ボットの「頭」と、キー入力の「意図の解釈」は差し替え可能な選択部。実行部を二重に書かない（§1.5）。
- 「強い」はボタンで倍率を掛けず、溜め（予備動作）の大きさで表す。威力は体のバネから出る（§1.3）。
- 決定的であること（§1.6）。入力の記録・再生（`ReplayTests`）が壊れないこと。

### 直接動かしている感覚のための要件（設計の核）
1. **遅れを作らない**: キーを押したその歩で目標が動き出す。技の選択は押した瞬間に決め、選んだ技の経路の最初の部分（引き・踏み込み）はすぐ始まる。
2. **方向キーは体の動き**: 押している間は足が動く（前後左右・回り込み）。攻撃・回避キーと組み合わせると、その方向が技の向き・種類を決める（前＋強 = 踏み込んだストレート、横＋弱 = 横からのフック系、後ろ＋回避 = スウェー/バックステップ、前＋回避 = 来る拳に合わせてスリップ・ダッキング・ウィービングを `OpponentRead`＋`DefenseBook` で選ぶ）。
3. **押し方の長さ**: 短く押す = 速い軽い技、長押し = 溜め（逆へ引く予備動作が深くなる）→ 離した瞬間に打ち出す。溜めている間も目に見えて体が沈む・ひねれる（物理で）。
4. **連打 = コンビネーション**: 技の途中で次のキーを先行入力として受け、つながる技（`Combo`）へ自然につなぐ。受付の窓は技の経路の進み具合から決める（数値は `FighterTuning` か新しい設定へ。コードに埋めない）。
5. **状況で読み替える**: 間合い（遠ければ踏み込み付き、近ければ短い技・ボディ）、相手の拳の読み、自分の体勢（回避の直後 = 返しのカウンター、体のバネの反発を使う）。
6. **ガード**: 何も押していないときは構え。回避キー単押し（方向なし）はブロック/ガードを固める。
7. **中断できる**: 回避キーは攻撃の途中でも優先する（読みが当たれば間に合う）。

3. **実行部の切り出し**: BoxerBot の技の実行（経路を `FighterCommand` へ変える部分）を共有の部品へ。リファクタの前後でボット同士の試合がビット単位で同じことを確かめる（同じ種のチェックサム、`ReplayTests`・既存のボットのテスト）。同じなら `LogicVersion` は上げない。変わるなら上げて理由を書く。
4. **意図の解釈部**（例 `IntentControl : IFighterControl`）: ホスト非依存（`games/MiniRing/` 側）。キーの状態（押下・押した長さ・離した瞬間・先行入力）を受け、`FighterSense` と合わせて技を選ぶ。キーボードの読み取りはデスクトップのホストだけ。
