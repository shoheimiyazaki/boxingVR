# 作業指示 8（2026-11-14）: 意図操作をゲームパッドでも

最初に `CLAUDE.md`・`docs/INTENT_CONTROL.md` を読む。日本語。コミット・プッシュはしない。

## やること
キーボードの意図操作（`games/MiniRing.Desktop/IntentKeyboardControl.cs` → `FighterIntent` → `IntentControl`）を、ゲームパッド（Xbox 系の標準配置）でも同じように操作できるようにする。

- **入力の読み取り**: エンジン（`src/Aigis.Platform` など）が使っている窓・入力の仕組みに、ゲームパッドの読み取りがあるか調べる（GLFW の gamepad API など）。あればそれを使い、無ければ OSS（Windows なら XInput を呼ぶ小さな部品）を足す。依存を増やすなら理由を書く。ゲームパッドが無くてもキーボードだけで動くこと。
- **写し方（キーボードと同じ `FighterIntent` へ）**:
  - 左スティック = 移動（カメラ基準、キーボードと同じ）。**倒した量を連続の量として渡す**（半分倒せば半分の速さ。デッドゾーンは小さく、調整値に）。
  - X = 弱攻撃（前の手）、Y = 強攻撃（後ろの手）、A = 回避（方向なし = ガード）、B = 予備（キーボードに無ければ空けておく）。長押しの溜め・タップのジャブ・先行入力・コンビネーションはキーボードと同じ仕組み（押した時間・離した瞬間）。
  - 右スティック = カメラの回転（描画だけ）。
  - Start / Back = ラウンドのやり直し（キーボードの R）。
  - 割り当ては表にして `docs/INTENT_CONTROL.md` に。値（デッドゾーン・スティックの曲線）は調整値へ。
- **一つの現象に一つのモデル**（§1.5）: キーボードとゲームパッドは同じ `FighterIntent` を作るだけで、意図の解釈・技の選択・実行は共有。入力元ごとの分岐を `IntentControl` に入れない。
- 記録・再生は今と同じ（記録は指令を持つので、入力元が変わっても再生が一致する）。
- `run-keyboard.cmd` のヘルプにゲームパッドの割り当てを足す（名前はそのままでよい）。
