# ボクシングボット（`games/MiniRing/Bots/`）

CPU とボット同士の対戦に使う、ボクシングの技を持つボットです。ボットが決めるのは**指令だけ**（拳の目標・頭の位置・移動）で、当たるかどうかや、どれだけ効くかは物理（[BOXING.md](BOXING.md)）が決めます。乱数は種付きなので、同じ種なら同じ試合になります（リプレイも再現できます）。

改善の経緯と、データにもとづく判断の記録は [BOT_PDCA.md](BOT_PDCA.md) にあります。

## 1. 技

### パンチ（`Technique` / `PunchSpec`）

経路はどれも「構え → 溜め → 狙いの奥 → 構え」です。溜めを取る方向で技が変わります。打つ間は頭（体の軸）も動かします（体重移動・レベルチェンジ）。

| 番号 | 技 | 手 | 溜め | 狙い | 体の使い方 |
|---|---|---|---|---|---|
| 1 | ジャブ `Jab` | 前 | なし（まっすぐ） | 頭 | 小さく踏み込む |
| 2 | ストレート `Cross` | 後ろ | ほぼなし | 頭 | 前の足へ体重を移す |
| 3 | リードフック `LeadHook` | 前 | 横・肘より高く | 頭（顔を横切って振り抜く） | 後ろ側へひねる |
| 4 | リアフック `RearHook` | 後ろ | 横・肘より高く | 頭（振り抜く） | 前側へひねる |
| 5 | リードアッパー `LeadUppercut` | 前 | 下 | 頭 | 沈んでから伸びる |
| 6 | リアアッパー `RearUppercut` | 後ろ | 下 | 頭 | 沈んでから伸びる |
| 1b | ボディジャブ `BodyJab` | 前 | 少し下 | 胴 | 膝を沈める（レベルチェンジ） |
| 2b | ボディストレート `BodyCross` | 後ろ | 少し下 | 胴 | 膝を沈める |
| 3b | リードボディフック `LeadBodyHook` | 前 | 横・下 | 胴（レバー側） | 沈んでひねる |
| 4b | リアボディフック `RearBodyHook` | 後ろ | 横・下 | 胴 | 沈んでひねる |
| oh | オーバーハンド `Overhand` | 後ろ | 上 | 頭 | 前へ大きく乗る |
| f | フェイント `Feint` | 前 | なし | 途中で引く | 相手の守りを引き出す |

「前の手」はオーソドックスなら左、サウスポー（`Southpaw`）なら右です。

#### 技表はデータ（`PunchBook` / `BotStyle.Punches`）

拳の技の値（溜めの横・低さ、打ち抜く量、時間、頭のずれ、踏み込み、振り抜き）は、守りの `DefenseBook` と同じく**スタイルの値**です（`games/MiniRing/Bots/PunchBook.cs`）。

- 既定の値の出どころは `PunchBook.Default` の 1 か所（以前は `PunchSpec.Of` に直書き）。`PunchSpec.Of(t)` は既定の値を返すだけです。ボットの実行（`BoxerBot`）・意図操作（`IntentControl`）・守りのドリル（`DrillCue`）は `Style.Punches`（`_style.Punches`・`attacker.Punches`）を使います。
- JSON 用の値は `PunchMove`（`HeadShiftX/Y/Z` は float。`Vector3` は JSON に出ないため）。書いていない技・値は既定になる（`PunchBook` の `JsonObjectCreationHandling.Populate`）ので、技 1 つ・値 1 つだけの JSON でよく、既存のスタイルの JSON は書き換えていない。
- 狙いの点は、経路を作る前に自分の胸の前（肩の中心から前へ 0.25 腕: `PunchPath.NearestStrike`）より手前に来ないように寄せる（`PunchPath.Strikable`、`Through` が必ず通す。古い CPU・従来のキーボード操作・肘打ちの狙いも同じ。横・高さはそのまま、LogicVersion 55）。胸が付くほど詰まると相手の頭が自分の肩の横・後ろへ回り、その点を打ち抜く経路が背中側へ伸びて腕が後ろへ回っていた（2026-11-19、`ArmBehindProbe`・`PunchAimTests`）。ボットと意図操作が共有する。
- `Validated()` は技の正体（`Lead`・`ToBody`）を既定へ戻し、`Extend` を `Feint` 以外 1 に固定する（`TechniqueExecution.Spring` は `Extend >= 1` のときだけ体のバネを拳へ移すので、1 未満は「フェイント化」と「移送の切れ目」を混ぜてしまう）。ほかの値は `PunchRanges`（名前・最小・最大の表。根拠は値の横）へ収める。守りも同じ形で `DefenseRanges` を `DefenseMove.Validated()` と `Mutation.Move` が共有する。
- `BoxerBot.KindOf`（技 → 拳の種類）だけは `PunchBook.Default` で決める。技の種類は技の番号で決まり、磨いた値で変わってはいけない（守りの選び方・合図・ドリルが使う）。
- 既定の値では試合は 1 ビットも変わらない（`LogicVersion` は据え置き）。進化（CMA-ES）で磨く計画の最初の段（`docs/LEARNING_PLAN.md` §9 の P0a）。

### コンビネーション（`Combo.All`）

`1`, `1-1`, `1-2`, `1-1-2`, `1-2-3`, `1-2-3-2`, `2-3-2`, `1b-2`, `1-2-3b`, `3b-3`, `2b-3`, `6-3`, `5-2`, `6-3-2`, `3-4`, `4b-3`, `1-oh`, `f-2`, `f-3`, `f-1-2`

次のパンチは、前のパンチを始めてから「そのパンチの時間 × `Gap`」後に出します。同じ手が続くときは、その手が構えに戻るまで待ちます。

### 守り（`Defense`）

相手の拳がこちらへ来るのに気づき、反応時間（`ReactionTime`）が過ぎたら、守る率（`DefenseRate`）に従って守りを 1 つ選びます。

**気づき方（`Anticipation` で変わる）**
- 拳の速さは、相手の胴の速度を差し引いた「腕の動き」で見ます。歩いて近づくだけでは反応しません。
- 読まない（0）: 拳がまっすぐ頭・胴へ速く向かってきてから気づきます。近い間合いでは、気づいてから当たるまでが 0.12〜0.18 秒しかなく、人並みの反応時間では間に合いません。
- 読む（1 に近いほど）: 拳が相手の体に対して動き出した早い段階で気づきます。
  - フックは、外へ振りかぶった時点で気づきます。振り込みが始まってから当たるまでは約 0.11 秒で、そこから見たのでは間に合わないためです。
  - 代わりに、フェイントや構えの揺れにも反応しやすくなります。

**予測で避ける（`Prediction` で変わる）**
- 実際のボクサーは拳を見てから避けるのではなく、間合い・リズム・打つ前の体の動き（肩と腰）・相手の癖から次の拳を予測します。
  拳は 0.2 秒足らずで届き、見てからの反応では間に合わないためです（docs/BOT_PDCA.md 予測編）。
- ボットは試合の中で相手を覚えます（`OpponentRead`）。間合い・踏み込みの速さ・胴のひねりの速さ・肩の前傾の速さ・前の拳からの時間について、
  「その時、0.15 秒以内に拳が出たか」を数え、まもなく来る確からしさ・来る手・種類を見積もります。
- 確からしさが閾値（`Prediction` が大きいほど低い）を越え、体の手がかりが「打たない」側を示していなければ、拳が出る前に守りを始めます。
  覚えるまでの最初の数発は読めません。大きくするほど早く動けますが、空振りの守りで自分の攻めを止めます。
- `EdgeRange`: 覚えた相手の打ち始めの間合いの少し外に立ち、相手に踏み込ませます。

**打つ前の溜め（`Telegraph`、予備動作）**: 連打の最初の拳の前に、打つ手の肩を後ろへ引き、拳を引き、頭を引いて膝を沈めます（体のバネを縮める）。
打ち出すと、縮めたバネの反発と体の動きが拳に移ります（場合分けなしの物理: 溜めが長いほど深く引けて、ジャブ・ストレートが速く重い）。狙いは溜めの始めに決まります。
長い溜めは威力が出る代わりに読まれやすく、時間もかかります。カウンターとストップジャブは溜めません（回避や前の拳で動いた体の勢いが乗ります）。

**選び方**: 重み = スタイルの好み（`BlockWeight` など）× 来る拳の種類への効き目（防御ドリルで測った値）。効き目 0 の技は選びません。
**しゃがみの疲れ**: 頭を腕の長さの 0.25 より沈めている間は疲れが溜まり、立てば抜けます。0.4 秒を超えたら抜けきるまで、頭を沈める守り（ダッキング・ウィービング・沈むスリップ）は選びにくくなり、拳が来続けても沈んだまま守りを延ばしません。沈む守りを延ばせるのは 0.45 秒までです。ずっとしゃがんだまま戦わないためです（BOT_PDCA.md 足運び編 F3）。リーグの報告に「しゃがんでいた時間」が出ます。

| 守り | 動き（防御ドリルで最適化した後） | よく効く拳 |
|---|---|---|
| ブロック `Block` | 拳で顔を覆ったまま少し沈み、上体を引き、足でも下がる | フック・アッパー |
| ダッキング `Duck` | 深く沈み、頭は前へ、足で下がる | ストレート・フック（アッパーには使わない） |
| ウィービング `Weave` | 真ん中から U 字に深く沈み、拳を上げたまま反対側へ抜ける（`Sweep` の技はこれだけ） | フック |
| スリップ `Slip` | 頭を拳の線の外へずらす | フック |
| スウェー `Sway` | 上体を大きく反らし、長く保ち、足で下がる | ストレート・フック・アッパー |
| バックステップ `StepBack` | 足で下がる | ストレート |
| サイドステップ `SideStep` | 足で横へ大きく出て、拳の線から外れる | ストレート・フック |
| インサイドスリップ `SlipIn` | 頭を外しながら半歩踏み込み、打ち返せる距離に入る | ストレート |
| ローリング `Roll` | 拳の進む向きへ頭を沈めながら流す（`Sweep`） | フック |

上の「よく効く拳」は champion の値での傾向です。回避編で、連打の攻め手を相手に回避技だけを磨き直した表（[evasion_combo_book.json](arena/evasion_combo_book.json)）では、次のとおりでした。
- フックとアッパーには回避がよく効く（30〜52%）。ウィービング・サイドステップ・バックステップが強い。
- 連打のストレートは、回避だけではほとんど防げない（よくて 17%）。ストレートには間合いと構えで対する。

**回避の足**
- **届く拳だけ避ける**（`EvadeReach`）: 相手の肩から自分の頭までが腕の長さ × この値より遠い拳は避けない。届かない拳まで避けると、自分から間合いを崩してかえって打たれます。見送った拳も毎回見直し、相手が踏み込めば避けます。
- **ロープを背負わない**（`RopeEscape`）: 背中側のロープが近いほど、下がる動きを空いている横への動きに替えます。逃げる向きは、ロープを感じたときに決めて離れるまで変えません。守りの最中は、来る拳から離れる側へ逃げます。

- **ボディ打ちには、どの技も使いません**。構えたままの拳がもともと胴を覆っていて、動けば覆いが外れるためです。
- 守りの動き（頭の位置、時間、足、拳の高さ・幅など）は、技ごとに `DefenseBook` の値で決まります。
- 値と効き目の表は、`run.cmd arena drilltune` で作り直せます（[BOT_PDCA.md](BOT_PDCA.md) の防御編）。

### カウンター・クリンチ・投げ・足

- **カウンター**: 守りを始めたときに `CounterRate` の確率で打ち返すと決め、打たれなければ打ち返します。
  - 防御技ごと・来る拳の種類ごとに、打ち返しの型と打ち始めを持てます（`DefenseMove.CounterStraight` / `CounterHook` / `CounterUppercut` と `…At`）。
  - 打ち始めが 1 未満なら、回避しながら打ちます（回避の進み具合がその値に達したとき）。ブロックは常に守り終えてから打ちます。
  - 回避編の研究では、ほぼすべての回避で「回避しながらの 1-2」が最も強く、フックを流す・くぐる回避からなら決まった返しの約 3 倍でした（`run.cmd arena counterlab`）。
  - 型を持たない場合の決まった返しは、守り方で決まります。
  - スリップ → ストレートとフック
  - ダッキング → アッパーとフック、またはボディフックとフック
  - スウェー → ストレート（プルカウンター）
  - ブロック・バックステップ → ジャブとストレート
  - ウィービング → 抜けた側のフックとストレート
  - サイドステップ → 角度を取ってストレートとフック
- **クリンチ**: 続けて打たれたら（約 1 秒で 14 ダメージ以上）、`ClinchRate` の確率で相手の胴を抱えて止め、投げにならない速さで離します。
- **投げ**: 近距離の攻撃のうち `ThrowRate` の割合で、片手で掴んで引き倒します。
- **足（間合い）**:
  - 普段は `NeutralRange`、打つときは `AttackRange` まで間合いを詰めます。
  - 打ち終えたら、`ExitAfterCombo` の確率で外へ出ます。`PivotAfterCombo` の確率で、前の手の側へ回り込んで角度を取ります（ピボット）。
  - 攻めていないときに相手が間合いの内側へ踏み込んできたら、`StopJab` の確率でジャブを合わせて止めます（ストップジャブ）。
  - 普段は前の手の側へ回ります（相手の強い後ろの手から離れる）。
  - ロープ際に近づくと中央へ戻ります。

## 2. スタイル（`BotStyle` / `BotCatalog`）

`BotStyle` は戦い方の値をすべてまとめた、不変のレコードです。JSON に読み書きできます（`ToJson` / `FromJson`）。

| 名前 | 内容 |
|---|---|
| `legacy` | 最初の単純な CPU（`AiControl`）。改善の基準として残してある |
| `boxer` | バランス型。ジャブで組み立てて 1-2-3、守りも一通り |
| `outboxer` | 遠い間合いからジャブ、打ったら離れる、回る、スウェーとバックステップで外す |
| `swarmer` | 拳を寄せて顔に近づけたピーカブーの構えで、頭を振りながら詰め、胴とフックの連打。回避編で磨いた回避（ウィービング・ダッキング・ローリング・インサイドスリップ）と、回避しながら打つカウンターの表と、右ストレートの外側へ腰から沈むダッキング（基本動作編）を持つ（値は `Bots/swarmer.json`） |
| `counter` | 手数は少なく、守り切ってから打ち返す |
| `slugger` | 守りは薄く、大きなフック・アッパー・オーバーハンドで倒しに行く |
| `jabber` | 自動調整で強さだけを求めた結果（ジャブ連打のアウトボクサー）。総当たりの勝率がいちばん高い |
| `champion-v1` | 1 代目の CPU。自動調整で技の幅を保って強くした攻めのボクサー（1-2・1-2-3 が軸）。守りは手書きのまま |
| `champion` | 2 代目。攻めは 1 代目のまま、防御技をドリルで磨き、守りと間合いを実戦で調整した間合いの名手（腕の長さ 1.3 倍の外から打ち、踏み込まれたらストップジャブ、打ったら出る）。総当たり 70-0-0。**ゲームの CPU はこれ**（値は `Bots/champion.json`） |

**間合いの層**（`RangeSense`、LogicVersion 12〜13、詳細は [LEARNING_PLAN.md](LEARNING_PLAN.md) の §4c）: 相手の拳が自分の頭へ届きうる所にいる度合い（危険度、0..1）と、
そこで打たずに居続けた時間（さらされ）を、ほかの判断より先に見る層です。打たれてから守るのでは間に合わない（ストレートは構えから約 0.05 秒で届く）ので、
危ない所にいること自体を手がかりにします。下がって避ける使い方は試合がつまらなくなった（ユーザー評価）ので、**居続けを打って解消する**使い方にしています。

| スタイル | `RangePress`（居続けたら早く打つ） | `RangeGuard`（危ないほど構えを上げる） | 考え方 |
|---|---|---|---|
| `boxer` | 0 | 0 | 基準のスタイル（多くのテストの相手）なので使わない |
| `outboxer` | 0.5 | 0.6 | 外から打つ。入られたら構えを上げる |
| `swarmer` | 2 | 0.6 | 前へ出て打ち合う |
| `counter` | 0.5 | 0.8 | 待って返す。構えは厚く |
| `slugger` | 2 | 0.3 | 前へ出て打ち合う。構えは薄い |
| `jabber` | 1 | 0.4 | 手数で解消 |
| `champion-v1` / `champion` | 1 | 0.6 | 中くらい |

ほかに、頭を動かす（`RangeHeadMove`）・当てずっぽうの回避（`RangeGuess`）・外へ出る（`RangeExit`）・届かない所に立つ（`RangeKeepOut`）の使い方も持てますが、
試合が守り合いになる・使う側が有利にならないので、どのスタイルも使っていません。

**人並みの制約**: `Validated()` で次の範囲に収めます。改善は反射神経を超人にすることではなく、技の選び方・間合い・守りの選び方で勝たなければなりません。

| 値 | 範囲 |
|---|---|
| 反応時間 | 0.12 秒以上 |
| 守る率 | 0.85 以下 |
| 手の速さ | 1.15 倍以下 |

## 3. 対戦場（`games/MiniRing.Arena`）

ボット同士を、物理ごとヘッドレスで戦わせます。

- 試合は決まった時間で行い、KO・リングアウトでラウンドが区切られます。
- 勝敗は「KO・リングアウトで取ったラウンド数」で決め、同じなら「与えたダメージの差」で決めます（差が 5% 以内なら引き分け）。
- 試合ごとに物理のワールドが分かれているので、並列に回せます。結果は順序に依らず決定的です。

```bash
run.cmd arena league --bouts 6 --seconds 60
```

```bash
run.cmd arena tune --base outboxer --gens 10 --pop 8 --log docs/arena/tune.md --out docs/arena/tuned.json
```

| コマンド | 内容 |
|---|---|
| `league [--bots a,b,...] [--bouts N] [--seconds S] [--seed X] [--out f.md]` | 総当たりの順位表、1 対 1 の対戦成績、技ごとの手数・命中率・平均ダメージ、守りごとの成功率 |
| `tune --base NAME [--focus all\|defense] [--gens G] [--pop P] [--gauntlet a,b] [--log f.md] [--out f.json]` | スタイルの自動調整。1 世代ずつ PDCA を回して記録する。`--focus defense` は攻めを固定し、守り・間合いの値と防御技の動きだけを変える |
| `drill [--book f.json] [--bouts N] [--seconds S]` | 防御ドリル: 防御技 × 拳の種類（ストレート・フック・アッパー・ボディ）ごとに、被ダメージの減りとカウンターの取り返しを測る |
| `drilltune [--defense a,b\|all\|evasions] [--book f.json] [--ranges 1.0,1.15] [--counters true\|false] [--combos true\|false] [--gens G] [--pop P] [--log f.md] [--out book.json]` | 防御技ごとの最適化（ドリルで PDCA）。最後に効き目の表を測り、守りを選ぶ重みにする。`--counters false` で回避そのものの性能だけを、`--combos true` で実戦と同じ連打を相手に測る |
| `counterlab [--book f.json] [--defense evasions] [--combos true] [--ranges 1.0,1.15] [--log f.md] [--out book.json]` | 回避からのカウンターの研究。回避技 × 来る拳の種類ごとに、打ち返しの型 × 打ち始め（回避の途中・後）を総当たりし、別の種で 2 回確かめて本に書く |
| `basics [--punch 2] [--slot Duck] [--style swarmer] [--cue 0,0.04,0.08] [--move f.json] [--gens G] [--pop P] [--log f.md] [--out move.json]` | 回避の基本動作の最適化。攻め手は 1 つの型（既定は右ストレート `2`）だけを打ち、受け手は 1 つの回避で外す。値は「形」（拳の外側へ・腰から沈む・拳は構えの高さに残す）の中だけで動かす。`--cue` は拳が出てから回避を始めるまでの遅れ（練習の合図。複数なら全部で測る、`none` で受け手自身の目と反応）。最初に構えの形（`--guards` 高さ・`--widths` 開き・`--reaches` 出し）だけの表を出し、`--gens 0` ならそこで止める。`--cues=-1,0,0.04` で遅れごとの表 |
| `video [--red A] [--blue B] [--seed X] [--seconds S] [--out f.mp4]` | ボット同士の試合を mp4 に描く（GPU のヘッドレス描画 + ffmpeg）。タイトル → 試合 → 結果の構成で、試合中は技・守り・重い一撃の字幕と打撃音が入る。既定は champion 対 jabber、45 秒、`videos/` へ。`--drill 2 --defense Duck --move f.json --cue 0.04` で基本動作のドリル（赤が回避、青が 1 つの型だけを打つ） |

### `cmatune`（CMA-ES でドリルの点を上げる、作業 17）

拳 1 技・守り 1 技の値を、CMA-ES（`Evolution/CmaEs.cs`・`Genomes.cs`）でドリルの点に向けて動かします。結果は**データとして出すだけ**で、`champion.json`・`BoxerBot` の判断・体の物理は変えません（`LogicVersion` も上げません）。

```bash
run.cmd arena cmatune --target punch:2 --gens 40 --out docs/arena/cma_punch2.md --json docs/arena/cma/punch2.json --resume docs/arena/cma/punch2.state.json
run.cmd arena cmatune --target defense:Slip,defense:Duck   # 対象が複数なら順に回す（探索的、有意水準は対象の数で割る）
```

| 引数 | 内容 |
|---|---|
| `--target punch:<型>\|defense:<技>` | 拳は単発の型だけ（`2` = 右ストレート、`3`、`1b` …）。守りは `Block`・`Slip`・`Duck` など |
| `--defenses Block,Slip` | 拳の対象で、受け手に**固定させる守り**の組。省略時は `punch:2` → Block・Slip・Duck、`punch:3` → Block・Weave・Duck、`punch:1b` → Block・StepBack。それ以外の型は明示しないと止まる |
| `--gens 40` `--lambda 0` `--sigma 0.15` | 世代の数・1 世代の候補数（0 = 自動 = `evo_noise.md` の推奨 12）・初めの σ（[0, 1] に正規化した空間で） |
| `--samples 48` `--seconds 40` `--seed 1` | 1 候補の標本（種）の数と 1 本の長さ（`evo_noise.md` のドリルの推奨）。同じ世代の候補は同じ種の組で測り（共通の乱数）、世代ごとに種を変える |
| `--resume state.json` | 世代ごとに状態を書く。ファイルがあれば続きから（続けて回した場合と JSON まで一致する。設定が違えば止まる） |
| `--confirm-n 96` | 最後の比べ直しの標本の数（使わなかった種）。0 で行わない |
| `--match-n 16` `--match-seconds 45` | 試合での確認（champion の技表のその技だけを替えたスタイル 対 元の champion を、boxer・outboxer・swarmer・counter・slugger・jabber 相手に対にした試合の点で）。0 で行わない |
| `--out` `--json` | 報告（Markdown）と、候補の本（`PunchBook`・`DefenseBook`）の JSON。同じ場所に champion へ重ねたスタイルを `*.style.json` で出す（`video --drill 2 --defense Slip --attacker-style <それ>` で撮れる） |
| `--parallel P` | 並列の数の上限（結果は並列の数に依らない） |

- **点**（大きいほど良い、1 標本 = 1 つの種）:
  - 拳: 受け手は champion の構えと守りの表、守りは固定、合図 0.04 s、打ち返しあり、間合い 1.15。点 = Σ（守りの組を全部回して、頭と胴に与えたダメージ − 打ち返されたダメージ）/ 秒（`PunchDrillResult.AttackPoint`）。
  - 守り: `DefenseTuner.SeedPoints`（守らない受け手との被ダメージの差 + 0.25 × 打ち返し）。
- **世代の点は「その世代の種での比べ」で、世代の間では比べられない**（表の下に書く）。
- **最後の比べ直し**: 使わなかった種・固定の n で、**始めの値**（champion）と**分布の平均 m**（最良の個体ではない。勝者の呪いを避ける）を対にして比べ（`PairedEvaluation.Confirm`）、信頼区間の下限が 0 より上のときだけ「改善」と書く。続けて試合でも悪くならないかを見る（ドリルで良くても試合で悪ければ、そう書く）。
- **予算の数え方は 1 つ**: `DefenseDrill.Run`・`DefenseDrill.Punch`・`MeasureBaseline` を呼んだ回数 × 秒数（`DrillMeter`。キャッシュで呼ばなかった分は数えない）。`cmatune` と `drilltune` の最後に同じ形で出す。
- 受け手・基準は champion（champion-v1 ではない）。`docs/arena/evo_noise.md` のとおり、今の物理では champion は champion-v1 に試合で負け越すので、試合の確認は「champion との比べ」であって強さの絶対値ではない。

ボットは名前で指定するほか、スタイルの JSON ファイルのパスでも指定できます（書いていない値は `boxer` の値になります）。

`tune` は 1 世代ごとに次の順で進みます（`StyleTuner`）。

1. **Plan**: 王者の値を少し変えた候補を作る。
2. **Do**: 全候補を同じ相手・同じ種で戦わせる。
3. **Check**: いちばん良い候補を、別の種で王者と直接対戦させ、相手陣とも再戦させる。
4. **Act**: 確認でも勝ち越したときだけ採用し、採用した王者は「殿堂」として相手陣に加える。

## 4. ゲームとの関係

- `BoxingGame` は両コーナーの操作元を `BoxingCorners` で受け取ります。既定では CPU 側が `champion` です。
- プレイヤー側にもボットを渡すと、ボット同士の試合になります。そのときホストの入力は無視されます。
- 守りのために、ボットは `FighterSense` で相手の拳の位置と速度、自分の頭の位置を見ます。
- リプレイの見出しには CPU のボット名が入ります（形式の版 2）。版 1 の記録は、CPU が `legacy` だった頃の試合として再生します。

## 倒れた相手への攻め（レフェリーなしの試合、2026-11-16、LogicVersion 29。2026-11-24 に LogicVersion 66 で直した）

`BoxingGame` は、レフェリーなし（`BoxingCorners.Referee = false`）のときだけ、ボットを `GroundStriker`（`Bots/GroundStrike.cs`）に包みます。相手が立っている間・レフェリーがいる間は中のボットの指令をそのまま返すので、既定の試合の判断は変わりません。相手が倒れている間（`OpponentDowned && MayStrikeDowned`）で、**自分は立っている間**（`!SelfDowned`。倒れたまま打ち続けると起き上がれず、床で両者がもつれた）は、いつものボットを読みつつ、手足の目標・頭のずれ・移動を `GroundStrike` が上書きします。

| 道具 | 攻め（`GroundMove`） |
|---|---|
| 素手・グローブ・メリケンサック・カタール・籠手・トンファー | `hammer`（鉄槌）・`punch-down`（真下への突き）・`stomp`（踏みつけ）・`kick`（蹴り: 足を手前へ引いてから床の近くを前へ振り抜く）。カタールは手の目標の向きがそのまま刃の向き |
| 日本刀・ロングソード（両手）・片手剣 | `thrust-down`（上からの突き下ろし）・`cut`（上段からの斬り下ろし） |
| こんぼう（片手）・棒 | `cut`（振りかぶっての打ち下ろし。棒は突き下ろしも） |

- 選び方: 武器を握っていなければ `GroundStomp` の割合で足の技、そのうち `GroundKick` の割合で蹴り（残りは踏みつけ）。続けて踏んでよい（2026-11-24 に「直前に踏んだら手の技を挟む」をやめた）。手の技は振り下ろす系か突き下ろす系かを `GroundCut`。打つかどうかは `GroundDrive`、溜めは `GroundLoad`、合間は `GroundRest`。
- 狙い: 倒れた体の軸（腰 0 → 両肩の真ん中 1 → 頭 2 の折れ線）のうち、技の狙う範囲（`GroundMove.AimFrom`〜`AimTo`）で水平にいちばん近い点。範囲は技の値（教科書・教育）で、急所の場所の狙い（種類の分岐ではない）。踏みつけ・蹴りの既定は首〜頭（1.5〜2）、刃の教科書（`katana`・`longsword`・`swordshield` の `Ground`）は斬り下ろし・突き下ろしとも首（1.5）。`Through` は狙いより前へ抜ける量（蹴り）。
- 経路の値の在りか: 素手はスタイル・教育の `Ground`（`GroundTuning`）。武器を握るなら武器の教科書・`education.weaponBot` の `Ground`（`WeaponStyle.Ground`、`BoxingGame.WithWeaponGround`）。武器の長さ・握りで合う経路が違うため。
- VFC の名簿のキャラは、とどめのドリル（`groundtime --drill`）で倒れた相手を死なせるまでの秒を CMA-ES で縮めた教育を持つ（`groundtime --practice`、`tools/ground-education.py`。docs/BOT_PDCA.md「VFC の倒れた相手への攻めを短く」）。
- 相手が立ち上がりかけて `OpponentAlive` に戻ったら、いつもの技へ戻る。

## 狙いどころ（戦略: どこを打つか、2026-11-12、LogicVersion 10）

技（経路の形・溜め・踏み込み）は変えず、**狙いの点だけ**を戦略が選ぶ層を足した。上位の戦略 AI は、スタイルの `Aim`（`AimWeights`）の重みで戦い方に幅を持たせる。

- **知覚**（`TargetMap`、相手の体から読む。人が見て分かる情報だけ）: あご・こめかみ（打つ側から見える方）・頭蓋が削れて**露出した脳**（露出しているときだけ。頭の格子が変わったときだけ数え直す）・肝臓・みぞおち・心臓（臓器の重心）・**ガードの前腕**（傷んでいる方を）。
- **選び方**（`Targeting.PickAny`）: 拳を出すたびに、使える狙いどころから重みの比で選ぶ（真ん中の重みは 1、全部 0 なら従来どおり）。狙いが拳の高さと違えば、同じ手・同じ形の拳で打ち分ける（ジャブ ↔ ボディジャブ、フック ↔ ボディフック。アッパーは頭のまま）。
- **無理のない範囲**（`Targeting.Clamp`）: 本来の狙い（頭・胴の真ん中）から腕の長さの 0.4 倍まで、肩から見た向きのずれ 28° まで。越えると体の軸と力の作用線が離れて体重が乗らず、経路の終わりが届く先を外れる。狙いがその外なら縁まで寄せる。
- 既定の重み: slugger（露出した脳 4・あご・こめかみ）、counter（あご・露出した脳）、jabber（ガードの腕 1.5）、outboxer（こめかみ・腕）、swarmer（肝臓 2.5・みぞおち・心臓）、champion（露出した脳 3・あご・肝臓）。boxer と champion-v1 は真ん中だけ。

## 体格を読む層（2026-11-16、LogicVersion 30、`Bots/BuildRead.cs`）

自分と相手の見えている寸法（`FighterSense` の `ArmReach`・`OpponentArmReach`・末尾の `SelfBuild`・`OpponentBuild`）の比から、戦い方の重みを連続に出す層。キャラ名・体格の種類では分けない。比は ρ = 自分の腕 / 相手の腕、η = 自分の身長 / 相手の身長、μ = `BodyBuild.MassRatio`（H³M²）の比で、体格が同じなら対数が 0 で全倍率が 1（従来と同じ）。係数は全スタイル共通の `BotStyle` の値（`Validated()` で範囲検証）。

| 係数（既定） | 式 | 効くところ |
|---|---|---|
| `BuildStandOff`（0.8） | 立ち位置 × ρ^(−k) | 普段の間合い・打ちに入る間合い・休む間合い・ストップジャブの間合い。長い腕は相手の届かない所の端へ、短い腕は相手だけ届く帯の外へ |
| `BuildInside`（0.5） | 打つ間合い × min(ρ, 1)^k | 短い腕ほど相手の腕の内側へ深く入る。長い腕は変えない |
| `BuildPush`（0、不採用） | 攻めの間隔の縮む速さ × μ^k、打って離れる確率 × μ^(−k) | 重い体ほど前で打ち合う。点に出ず、重い体はスタミナが先に尽きるので既定は使わない |
| `BuildDuck`（0.5） | 潜る守り（ダッキング・ウィービング・ロール）の重み × η^(−k)、引く守り（スウェー・ステップバック）の重み × η^k | 守りを選ぶ重みだけ（経路は変えない） |
| `BuildAimBody`（2） | 胴（肝臓・みぞおち・心臓）の重みに k × max(0, −ln η) を足す | 相手が高いほど胴を狙う（狙いの位置は今の見た位置から） |

根拠と測定は `docs/BOT_PDCA.md` の「体格に応じた戦い方」、生の記録は `docs/arena/build_tactics_*.md`。剣士（`SwordsmanBot`）・こんぼう（`ClubBot`）は対象外。物差しは `rosterleague`（名簿の総当たり。距離の帯・打撃・手数・スタミナの表。`--set` で係数を上書き、`--ab on` で「上書きを入れた側 対 入れない全員」）。

## 弱った相手を詰める層（2026-11-16、LogicVersion 36、`Bots/HurtRead.cs`）

相手がどれだけ打たれて開いているか（開き 0..1）を、見えている手がかりと自分の手応えだけから読み、立ち回りを連続に変える層。ボットは相手の意識の値を読まない（§1.7）。

- **読み**: 構えの下がり（相手の頭と両拳の高さの差 ÷ 相手の腕の長さ）が、その相手の普段の構え（下へ 1 秒・上へ 12 秒で追う基準）より `HurtSagStart`（0.06）を超えて下がった分を `HurtSagSpan`（0.12）で 0..1 に。測ると意識がはっきりした体は 0.26（疲れても同じ）、薄れ始めで 0.43、深く 0.49（`HurtCueProbe`）。手応えは自分の拳が当たったダメージの和を `HurtMemory`（2.5 秒）で忘れ、`HurtFeltScale`（30）で 0..1 に。開き = 1 − (1 − 構え)(1 − 手応え)、0.25 秒でならす。
- **効き方**（全スタイル共通の既定。0 なら従来の試合と同じ）:

| 係数（既定） | 効くところ |
|---|---|
| `FinishTempo`（1.5） | 次の拳までの間の縮む速さ × (1 + k × 開き) |
| `FinishPress`（1.5） | 詰める強さ p = min(1, k × 開き): 普段の立ち位置を打つ間合いへ p の割合で寄せ、危ない所から出る足・回り込み・打って離れる距離・ピボットの後ずさりを (1 − p) 倍 |
| `FinishSpend`（0.6） | 休む度合い × (1 − k × 開き)（蓄えが無ければ体が動かないのは物理が決める） |

2026-11-24 に、開きへ見える息の上がり・見えている傷み（`HurtWinded`・`HurtInjury`）を重ね、開きに比例してフィニッシュの表（`FinishCombos`、割合 `FinishComboShare`）から型を選び連打を詰める（`FinishGap`）値を足した。どれも既定 0（教育が空なら従来どおり）。練習した教育は比べ直しで良くならず、まだどのキャラにも入っていない（docs/BOT_PDCA.md「フィニッシュのコンビネーション」）。

根拠と測定は `docs/BOT_PDCA.md` の「弱った相手を詰める」、生の記録は `docs/arena/finish_*.md`（`rosterleague` に「相手が弱った間」の表を足した）。

## 戦略の層（2026-11-18、LogicVersion 50、`Bots/GamePlan.cs`）

自分と相手の**得意な間合いの表**、自分と相手の**傷み・疲れ**、自分の**意識**、試合の**時刻と点**から、毎歩「普段どの距離に立つか（d*）」と「手数」を連続に決め、足運びの普段の目標と拳の間の縮み方に重ねる層。出力は今までどおり `FighterCommand` だけで、体の強さ・威力には触れない（CLAUDE.md §1.8: 教育は入力の側）。技・状態の名前で分けず、重みと温度つきの平均（なめらかな最大）だけで書く（§1.3）。乱数・時計を使わない（§1.6）。相手の状態は見える手がかりだけから読む（§1.7）。

### 入力（`FighterSense` に足した物。読むだけで物理は不変）

| 名前 | 中身 | 出どころ |
|---|---|---|
| `SelfInjury` 0..1 | 自分の傷み（失った力）: 両腕・両脚の、残った筋の断面 × 神経の働きの平均を 1 から引く。折れて垂れた先・落ちた部位・切れた腕は 0 | `Fighter.Injury(felt: true)`（`BoxerBody.Muscle`・脊髄の働き・外れた部位） |
| `OpponentInjury` 0..1 | 相手の**見えている**傷み: 同じ式で神経を入れない（削れた肉・垂れた腕・落ちた部位）。意識・臓器は入れない | `Fighter.Injury(felt: false)` |
| `OpponentWinded` 0..1 | 相手の息の上がり（白い息・顔色・メーターの点滅で見せている量） | `Fighter.Winded`（`TiredLook` と同じ） |
| `Match` | このラウンドの経過・長さ（時間の無いラウンドは 0）・残りのラウンド数・点の差（与えた − 受けたダメージ、取った − 取られたダウン）・打ち合いの無い時間（得点が最後に動いてから） | `BoxingGame`（`MatchSenseOf`。試合が動いている歩だけ時計を進める。ダウンは数えが始まった歩で 1 つ） |

### 判断（毎歩、`GamePlan.Decide`）

1. 得の重み **M** = Boldness × (1 + 開き `HurtRead.Opening` + 相手の息の上がり + 相手の傷み) × (0.4 + 0.6 × 自分のスタミナ) × (1 − 0.5 × 意識の薄れ)
2. 脅威の重み **T** = Caution × (1 + 自分の傷み + 意識の薄れ + (1 − 自分のスタミナ)) × (0.5 + 0.5 × (1 − 相手の息の上がり))
3. 急ぐ度合い **U** = Pressure × (負けている量 × ラウンドの進み + (1 − exp(−打ち合いの無い時間 / Patience)))。負けている量 = 1 − exp(点の差 / 40)（点の差 = ダメージの差 + 40 × ダウンの差。勝っていれば 0）。M' = M (1 + U)、T' = T / (1 + U)
4. 距離ごとの見込み **S(d)** = M' × 攻め(d) − T' × 守り(d)。攻め = 自分の Dealt と相手の Taken の平均、守り = 相手の Dealt と自分の Taken の平均（片方の表しか無ければそれ）。表の間は線形に補い、範囲の外は端の値。距離の候補は両方の表の範囲を 1 cm おき
5. 好む距離 **d*** = exp((S − 最大) / 温度) を重みにした距離の平均、温度 = S の幅 × 0.25（`TemperatureShare`）
6. 手数の倍率 = (1 + U) × 2M' / (M' + T')、0.5〜2

**BoxerBot への入れ方**: 普段の立ち位置（`Footwork` の neutral。間合いの層の外へ出る分を足した後、弱った相手を詰める層の前）を d* / 腕の長さへ `Weight` の割合で寄せる。打ちに入る間合い（`AttackRangeNow`）は変えない。拳の間の縮む速さ（`UpdateAttack` の `_cooldown`）に 1 + (倍率 − 1) × `Weight` を掛ける。ほかの層（危険度・休み・弱った相手を詰める・体格の読み）はそのまま重なる。層が無ければちょうど 1 を掛けるだけで、ビット単位で変わらない（`GamePlanTests`）。

名簿の組ごとの d*（元気な両者・試合の始め）は `GamePlanProbe` が出す。初めの値（2026-11-18）: 拳の選手は d* が 17〜26 cm（普段の間合い NeutralRange × 腕の 17〜32 cm より近い。測定で「素手は得意な距離より遠い」と出ていた所）、武器の選手が相手だと 19〜22 cm（武器の内側）、vikram（カタール）が相手だと 29〜37 cm（離れる）。

### 物差し（`rosterleague` の重みつきの点）

1 試合の点 = **与えた側の点 − 0.5 × 受けた側の点**、各側の点 = ダメージ + 40 × K.O.（取ったラウンド）+ 15 × 骨折（`BoneBreakEvent`）+ 30 × 切断（`SeverEvent`）。勝ちを決めているのはダウン（勝ち点率との相関 0.92、与えたダメージは 0.23: `docs/ROSTER_REPORT.md` 初回の考察）なので K.O. を 1 試合の与えたダメージと同じ桁に重く置き、骨折・切断はその次（切断は取り返せないので骨折の倍）。優先は 1) 相手に多く与える、2) 自分が受けるのを減らす、なので受けた側は半分。

```
dotnet run --project games/MiniRing.Arena -c Release -- rosterleague --bouts 20 --seconds 60 --matrix docs/arena/<名前>.csv --out docs/arena/<名前>.md [--gameplan on|off|ab]
```

- 報告（`--out`）に「重みつきの点」の表（選手ごとの 1 試合あたりの点・与えた側・受けた側・K.O. / 骨折 / 切断の取った・取られた数）が入る。`--matrix` の 1 試合 1 行に `red_breaks,blue_breaks,red_severs,blue_severs,red_score,blue_score` の列を足した（breaks・severs はその色が相手に与えた数）。
- `--gameplan off` は全員の教育から戦略の層を外す（層なしの比べもの）。`--gameplan ab` は `--ab on` と同じ組み方で、層を入れた側（a）だけに残して層なしの全員と戦わせる（`--layered id` で a を 1 人に絞れる）。

### 近道（`docs/DEBT.md`「戦略の層」）

表は 1.2 m のリング・中央から始める試合の、全員を相手にした平均で、相手ごとの表ではない（相手の得意は相手の表として別に持つだけ）。距離は胸と胸で測った表を、ボットの肩の中心から相手の胸までの距離に当てている。式の形と係数（0.4・0.6・0.5・40・温度 0.25・手数 0.5〜2）は手で決めた。時間の無いラウンド（K.O. のたびに作り直す試合: `rosterleague` 等）ではラウンドの長さが分からないので、負けによる急ぎは効かず膠着の急ぎだけが効く。
