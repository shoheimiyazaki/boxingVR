# ボクシングボット（`games/MiniRing/Bots/`）

CPU とボット同士の対戦に使う、ボクシングの技を持つボットです。ボットが決めるのは**指令だけ**（拳の目標・頭の位置・移動）で、当たるかどうかや、どれだけ効くかは物理（[BOXING.md](BOXING.md)）が決めます。乱数は種付きなので、同じ種なら同じ試合になります（リプレイも再現できます）。

改善の経緯と、データにもとづく判断の記録は [BOT_PDCA.md](BOT_PDCA.md) にあります。

## 1. 技

### パンチ（`Technique` / `PunchSpec`）

経路はどれも「構え → 溜め → 狙いの奥 → 構え」です。溜めを取る方向で技が変わります。打つ間は頭（体の軸）も動かします（体重移動・レベルチェンジ）。

| 番号 | 技 | 手 | 溜め | 狙い | 体の使い方 |
|---|---|---|---|---|---|
| 1 | ジャブ `Jab` | 前 | なし（まっすぐ） | 頭 | 小さく踏み込む |
| 2 | ストレート `Cross` | 後ろ | ほぼなし | 頭 | 前の足へ体重を移す |
| 3 | リードフック `LeadHook` | 前 | 横・肘より高く | 頭（顔を横切って振り抜く） | 後ろ側へひねる |
| 4 | リアフック `RearHook` | 後ろ | 横・肘より高く | 頭（振り抜く） | 前側へひねる |
| 5 | リードアッパー `LeadUppercut` | 前 | 下 | 頭 | 沈んでから伸びる |
| 6 | リアアッパー `RearUppercut` | 後ろ | 下 | 頭 | 沈んでから伸びる |
| 1b | ボディジャブ `BodyJab` | 前 | 少し下 | 胴 | 膝を沈める（レベルチェンジ） |
| 2b | ボディストレート `BodyCross` | 後ろ | 少し下 | 胴 | 膝を沈める |
| 3b | リードボディフック `LeadBodyHook` | 前 | 横・下 | 胴（レバー側） | 沈んでひねる |
| 4b | リアボディフック `RearBodyHook` | 後ろ | 横・下 | 胴 | 沈んでひねる |
| oh | オーバーハンド `Overhand` | 後ろ | 上 | 頭 | 前へ大きく乗る |
| f | フェイント `Feint` | 前 | なし | 途中で引く | 相手の守りを引き出す |

「前の手」はオーソドックスなら左、サウスポー（`Southpaw`）なら右です。

### コンビネーション（`Combo.All`）

`1`, `1-1`, `1-2`, `1-1-2`, `1-2-3`, `1-2-3-2`, `2-3-2`, `1b-2`, `1-2-3b`, `3b-3`, `2b-3`, `6-3`, `5-2`, `6-3-2`, `3-4`, `4b-3`, `1-oh`, `f-2`, `f-3`, `f-1-2`

次のパンチは、前のパンチを始めてから「そのパンチの時間 × `Gap`」後に出します。同じ手が続くときは、その手が構えに戻るまで待ちます。

### 守り（`Defense`）

相手の拳がこちらへ来るのに気づき、反応時間（`ReactionTime`）が過ぎたら、守る率（`DefenseRate`）に従って守りを 1 つ選びます。

**気づき方（`Anticipation` で変わる）**
- 拳の速さは、相手の胴の速度を差し引いた「腕の動き」で見ます。歩いて近づくだけでは反応しません。
- 読まない（0）: 拳がまっすぐ頭・胴へ速く向かってきてから気づきます。近い間合いでは、気づいてから当たるまでが 0.12〜0.18 秒しかなく、人並みの反応時間では間に合いません。
- 読む（1 に近いほど）: 拳が相手の体に対して動き出した早い段階で気づきます。
  - フックは、外へ振りかぶった時点で気づきます。振り込みが始まってから当たるまでは約 0.11 秒で、そこから見たのでは間に合わないためです。
  - 代わりに、フェイントや構えの揺れにも反応しやすくなります。

**選び方**: 重み = スタイルの好み（`BlockWeight` など）× 来る拳の種類への効き目（防御ドリルで測った値）。効き目 0 の技は選びません。

| 守り | 動き（防御ドリルで最適化した後） | よく効く拳 |
|---|---|---|
| ブロック `Block` | 拳で顔を覆ったまま少し沈み、上体を引き、足でも下がる | フック・アッパー |
| ダッキング `Duck` | 深く沈み、頭は前へ、足で下がる | ストレート・フック（アッパーには使わない） |
| ウィービング `Weave` | 真ん中から U 字に深く沈み、拳を上げたまま反対側へ抜ける（`Sweep` の技はこれだけ） | フック |
| スリップ `Slip` | 頭を拳の線の外へずらす | フック |
| スウェー `Sway` | 上体を大きく反らし、長く保ち、足で下がる | ストレート・フック・アッパー |
| バックステップ `StepBack` | 足で下がる | ストレート |
| サイドステップ `SideStep` | 足で横へ大きく出て、拳の線から外れる | ストレート・フック |
| インサイドスリップ `SlipIn` | 頭を外しながら半歩踏み込み、打ち返せる距離に入る | ストレート |
| ローリング `Roll` | 拳の進む向きへ頭を沈めながら流す（`Sweep`） | フック |

上の「よく効く拳」は champion の値での傾向です。回避編で、連打の攻め手を相手に回避技だけを磨き直した表（[evasion_combo_book.json](arena/evasion_combo_book.json)）では、次のとおりでした。
- フックとアッパーには回避がよく効く（30〜52%）。ウィービング・サイドステップ・バックステップが強い。
- 連打のストレートは、回避だけではほとんど防げない（よくて 17%）。ストレートには間合いと構えで対する。

**回避の足**
- **届く拳だけ避ける**（`EvadeReach`）: 相手の肩から自分の頭までが腕の長さ × この値より遠い拳は避けない。届かない拳まで避けると、自分から間合いを崩してかえって打たれます。見送った拳も毎回見直し、相手が踏み込めば避けます。
- **ロープを背負わない**（`RopeEscape`）: 背中側のロープが近いほど、下がる動きを空いている横への動きに替えます。逃げる向きは、ロープを感じたときに決めて離れるまで変えません。守りの最中は、来る拳から離れる側へ逃げます。

- **ボディ打ちには、どの技も使いません**。構えたままの拳がもともと胴を覆っていて、動けば覆いが外れるためです。
- 守りの動き（頭の位置、時間、足、拳の高さ・幅など）は、技ごとに `DefenseBook` の値で決まります。
- 値と効き目の表は、`run.cmd arena drilltune` で作り直せます（[BOT_PDCA.md](BOT_PDCA.md) の防御編）。

### カウンター・クリンチ・投げ・足

- **カウンター**: 守りを始めたときに `CounterRate` の確率で打ち返すと決め、打たれなければ打ち返します。
  - 防御技ごと・来る拳の種類ごとに、打ち返しの型と打ち始めを持てます（`DefenseMove.CounterStraight` / `CounterHook` / `CounterUppercut` と `…At`）。
  - 打ち始めが 1 未満なら、回避しながら打ちます（回避の進み具合がその値に達したとき）。ブロックは常に守り終えてから打ちます。
  - 回避編の研究では、ほぼすべての回避で「回避しながらの 1-2」が最も強く、フックを流す・くぐる回避からなら決まった返しの約 3 倍でした（`run.cmd arena counterlab`）。
  - 型を持たない場合の決まった返しは、守り方で決まります。
  - スリップ → ストレートとフック
  - ダッキング → アッパーとフック、またはボディフックとフック
  - スウェー → ストレート（プルカウンター）
  - ブロック・バックステップ → ジャブとストレート
  - ウィービング → 抜けた側のフックとストレート
  - サイドステップ → 角度を取ってストレートとフック
- **クリンチ**: 続けて打たれたら（約 1 秒で 14 ダメージ以上）、`ClinchRate` の確率で相手の胴を抱えて止め、投げにならない速さで離します。
- **投げ**: 近距離の攻撃のうち `ThrowRate` の割合で、片手で掴んで引き倒します。
- **足（間合い）**:
  - 普段は `NeutralRange`、打つときは `AttackRange` まで間合いを詰めます。
  - 打ち終えたら、`ExitAfterCombo` の確率で外へ出ます。`PivotAfterCombo` の確率で、前の手の側へ回り込んで角度を取ります（ピボット）。
  - 攻めていないときに相手が間合いの内側へ踏み込んできたら、`StopJab` の確率でジャブを合わせて止めます（ストップジャブ）。
  - 普段は前の手の側へ回ります（相手の強い後ろの手から離れる）。
  - ロープ際に近づくと中央へ戻ります。

## 2. スタイル（`BotStyle` / `BotCatalog`）

`BotStyle` は戦い方の値をすべてまとめた、不変のレコードです。JSON に読み書きできます（`ToJson` / `FromJson`）。

| 名前 | 内容 |
|---|---|
| `legacy` | 最初の単純な CPU（`AiControl`）。改善の基準として残してある |
| `boxer` | バランス型。ジャブで組み立てて 1-2-3、守りも一通り |
| `outboxer` | 遠い間合いからジャブ、打ったら離れる、回る、スウェーとバックステップで外す |
| `swarmer` | 頭を振りながら詰め、胴とフックの連打。回避編で磨いた回避（ウィービング・ダッキング・ローリング・インサイドスリップ）と、回避しながら打つカウンターの表を持つ（値は `Bots/swarmer.json`） |
| `counter` | 手数は少なく、守り切ってから打ち返す |
| `slugger` | 守りは薄く、大きなフック・アッパー・オーバーハンドで倒しに行く |
| `jabber` | 自動調整で強さだけを求めた結果（ジャブ連打のアウトボクサー）。総当たりの勝率がいちばん高い |
| `champion-v1` | 1 代目の CPU。自動調整で技の幅を保って強くした攻めのボクサー（1-2・1-2-3 が軸）。守りは手書きのまま |
| `champion` | 2 代目。攻めは 1 代目のまま、防御技をドリルで磨き、守りと間合いを実戦で調整した間合いの名手（腕の長さ 1.3 倍の外から打ち、踏み込まれたらストップジャブ、打ったら出る）。総当たり 70-0-0。**ゲームの CPU はこれ**（値は `Bots/champion.json`） |

**人並みの制約**: `Validated()` で次の範囲に収めます。改善は反射神経を超人にすることではなく、技の選び方・間合い・守りの選び方で勝たなければなりません。

| 値 | 範囲 |
|---|---|
| 反応時間 | 0.12 秒以上 |
| 守る率 | 0.85 以下 |
| 手の速さ | 1.15 倍以下 |

## 3. 対戦場（`games/MiniRing.Arena`）

ボット同士を、物理ごとヘッドレスで戦わせます。

- 試合は決まった時間で行い、KO・リングアウトでラウンドが区切られます。
- 勝敗は「KO・リングアウトで取ったラウンド数」で決め、同じなら「与えたダメージの差」で決めます（差が 5% 以内なら引き分け）。
- 試合ごとに物理のワールドが分かれているので、並列に回せます。結果は順序に依らず決定的です。

```bash
run.cmd arena league --bouts 6 --seconds 60
```

```bash
run.cmd arena tune --base outboxer --gens 10 --pop 8 --log docs/arena/tune.md --out docs/arena/tuned.json
```

| コマンド | 内容 |
|---|---|
| `league [--bots a,b,...] [--bouts N] [--seconds S] [--seed X] [--out f.md]` | 総当たりの順位表、1 対 1 の対戦成績、技ごとの手数・命中率・平均ダメージ、守りごとの成功率 |
| `tune --base NAME [--focus all\|defense] [--gens G] [--pop P] [--gauntlet a,b] [--log f.md] [--out f.json]` | スタイルの自動調整。1 世代ずつ PDCA を回して記録する。`--focus defense` は攻めを固定し、守り・間合いの値と防御技の動きだけを変える |
| `drill [--book f.json] [--bouts N] [--seconds S]` | 防御ドリル: 防御技 × 拳の種類（ストレート・フック・アッパー・ボディ）ごとに、被ダメージの減りとカウンターの取り返しを測る |
| `drilltune [--defense a,b\|all\|evasions] [--book f.json] [--ranges 1.0,1.15] [--counters true\|false] [--combos true\|false] [--gens G] [--pop P] [--log f.md] [--out book.json]` | 防御技ごとの最適化（ドリルで PDCA）。最後に効き目の表を測り、守りを選ぶ重みにする。`--counters false` で回避そのものの性能だけを、`--combos true` で実戦と同じ連打を相手に測る |
| `counterlab [--book f.json] [--defense evasions] [--combos true] [--ranges 1.0,1.15] [--log f.md] [--out book.json]` | 回避からのカウンターの研究。回避技 × 来る拳の種類ごとに、打ち返しの型 × 打ち始め（回避の途中・後）を総当たりし、別の種で 2 回確かめて本に書く |
| `video [--red A] [--blue B] [--seed X] [--seconds S] [--out f.mp4]` | ボット同士の試合を mp4 に描く（GPU のヘッドレス描画 + ffmpeg）。タイトル → 試合 → 結果の構成で、試合中は技・守り・重い一撃の字幕と打撃音が入る。既定は champion 対 jabber、45 秒、`videos/` へ |

ボットは名前で指定するほか、スタイルの JSON ファイルのパスでも指定できます（書いていない値は `boxer` の値になります）。

`tune` は 1 世代ごとに次の順で進みます（`StyleTuner`）。

1. **Plan**: 王者の値を少し変えた候補を作る。
2. **Do**: 全候補を同じ相手・同じ種で戦わせる。
3. **Check**: いちばん良い候補を、別の種で王者と直接対戦させ、相手陣とも再戦させる。
4. **Act**: 確認でも勝ち越したときだけ採用し、採用した王者は「殿堂」として相手陣に加える。

## 4. ゲームとの関係

- `BoxingGame` は両コーナーの操作元を `BoxingCorners` で受け取ります。既定では CPU 側が `champion` です。
- プレイヤー側にもボットを渡すと、ボット同士の試合になります。そのときホストの入力は無視されます。
- 守りのために、ボットは `FighterSense` で相手の拳の位置と速度、自分の頭の位置を見ます。
- リプレイの見出しには CPU のボット名が入ります（形式の版 2）。版 1 の記録は、CPU が `legacy` だった頃の試合として再生します。
