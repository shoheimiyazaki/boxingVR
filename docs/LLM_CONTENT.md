# LLM で作るコンテンツの軸（2026-11-18）

ユーザーの指定: 「LLM を使ったコンテンツを作るときの軸として、このセッションで培ったノウハウを文書化してください」。

実況・解説（プロスペクティブ制、`docs/commentary/styles/prospective.md`）を作り直してきた中で、ユーザーに指摘されたこと・測って分かったことをまとめる。中継の実況に限らず、LLM に何かを語らせる・書かせるコンテンツ（台本・心の声・解説動画・キャラの台詞など）を作るときの軸にする。ゲーム本体の軸（`CLAUDE.md` §1「物理と材料で書く」）と同じ考え方で、**出力を指示で直さず、入力と構造で直す**。

---

## 1. 誘導しない。指示・例を書かず、役割と場だけを渡す

> 「実況解説で喋る内容を制限していたり、誘導する指示をできる限りなくしてください。毎回選手の体重や身長ばかり説明してて単調です」

- 指示書に「何を言え」「この順で」「たとえば〜」を書くと、LLM はそれを毎回なぞり、単調になる。**例は写される**（例として書いた言い回し・話題がそのまま繰り返された）。
- 渡すのは、役割（実況・解説、または役割すら無いフリートーク）と、しゃべれる時間・場のしくみだけ。何を言うかは LLM に任せる。
- ユーザーが「例です。これをそのままルールにはしないでください」と添えて出した具体例は、ルールに書き写さない。その例が起きている**原因の構造**を探す。
- 口調だけは場の性格として渡してよい（フリートークは「プロ寄りの配信者: です・ます基準で砕けて、主に視聴者へ」）。ただし言い回しの指定（語尾の「ね」の数など）は書かない。

## 2. 繰り返し・単調さは、入力から直す（対症療法の禁止を書かない）

> 「似た表現、同じ表現が何度も重なるのが気になります。これも明示的に指示せず、根本的に解決出来るようにしてください」

「同じ言い回しを使うな」と書くのは対症療法。重なりは入力の作りから出ている。測って見つけた出どころ:

| 出どころ | 直し方 |
|---|---|
| 渡す出来事の文が**決まり文句の台詞の形**（「X のいい左が、Y のこめかみに入った」、強さの形容つき） | 出来事は**事実だけ**（「当たり: X の左拳 → Y の右前腕（ガードの上）」）。強さは数字（速さ・エネルギー・削れ）で渡し、形容は LLM に任せる |
| 解釈を一文で言い切った文（「ボディが効いている。膝が落ちやすい」）を何度も渡す | 解釈の文を渡さず、元の量（意識・スタミナ・臓器の打撲の %）を渡す |
| **自分が何を言ったか**が見えない（会話を作り直すときの要約が直近 8 行だけ） | ここまでの台詞を**全部**見せる（1 試合で数千字。安い） |
| 入力の**解像度が低い**（武器の当たりが「武器」としか分からず、毎回「一撃が」） | 何のどこで当たったか（刀の切っ先・棒の後ろの端・こんぼうの頭）まで渡す。言葉の種類が勝手に増える |

物差し: 読み上げた台詞の「同じ 8 字が 2 回以上出た割合」と「決まり形（〜が、〜に入りました）の数」。直す前後で同じ試合を書き直して比べる（13 % → 8 %、決まり形 6 → 0。武器の試合 16 % → 7 %）。

## 3. 生に近い情報を、数字と言葉で渡す

> 「LLM に生に近い情報を渡してください。…言葉だけで情景をほぼイメージできるレベルに」

- 下ごしらえした要約より、生の量を渡す: 技の名前、頭と両拳の軌跡（直近 1 秒の動き・高さ・前後左右）、姿勢（腰の沈み・前傾・傾き）、当たりごとの速さ・運動量・エネルギー、削れたセルの数と材質、意識・スタミナ・臓器。
- 数字には言葉を添える（「腰の高さ 74 cm（立った時より 20 cm 沈んでいる）」）。体の場所は細かい辞書（おでこ・目・頬・こめかみ・みぞおち…）で言葉にする。長さは人の大きさの cm に直す。
- 「数字はそのまま言わなくてよい。情景を思い描くのに使って」とだけ添える。
- 情報は席ごとに非対称でよい（実況には外から見えるもの、解説には体の中まで）。資料は全部を渡さず、席ごとの**索引**を渡して必要なときに読ませる。

## 4. 時間を資源として扱う（場のしくみを本物に近づける）

> 「TV の時間は固定でリソースとして扱う」「マイクは 1 本で同時に 1 人しかしゃべれない」

台本を後から書くのでなく、試合の時間の上で LLM を動かす（プロスペクティブ制）:

- マイクを渡されたら、そこまでの記録をもらい、試合を止めて考え、話す・パスを選ぶ。話すなら秒数を予約して自由に話す（秒数の上限は付けない）。出来事が起きたらマイクが戻り、どこまで言えたか・何が起きたかが届く。
- **言葉の終え方は LLM に選ばせる**: 割り込まれたとき、いま止める・次の区切りまで・文の終わりまで・最後まで（それぞれあと何秒か）と、短い締めの言葉を、伝える大事さと言葉の途中で切れる聞き苦しさを比べて決めさせる。単語の途中で切れる回数が 102 → 18 に減った（ユーザー: 「言葉の区切りは非常に自然になり良いです」）。
- 興奮の感嘆は 1 本のマイクの制限から外して重ねてよい（本物の中継でも重なる）。
- 秒数が決まっている場面（リプレイ・タイトル・表）は、前もって番組の予定として知らせる。
- 長さの見積もりは本物の読み上げで測る（見積もりと実際が 1〜3 秒ずれて映像とずれた）。

## 5. 映像とのずれは、渡す時点の「今」を揃えて直す

> 「しゃべっている内容と映像が合っていない場合があります」

- マイクを渡すたびに、その瞬間の画面のコマと状態（倒れている選手・カメラ・直近の打撃数）を渡す。
- 言うことを「今」と「その後」の 2 段に分けさせる。
- 決めてから時間がたった返事は、声に出す前にもう一度聞き直す。

## 6. 映像そのものを LLM に見せる・見えにくい物を見える形にする

- 要所のコマ（ダウン・骨折・リプレイ・傷のアップ）を画像で渡す。休みには傷へ寄る手持ちカメラのズームの絵も渡す。
- 体の中の損傷のように、映像に映らないことは語れない。語らせたいなら、見た目に出す（内部の損傷を皮膚の色のあざにする。息切れの青と見分けられる暖色にする）か、出来事として渡す（休みの動作: 「水を飲んでいる」）。**語りは見えているものと矛盾しないこと**。

## 7. コストと再現性も軸に入れる

> 「今日のセッション数が跳ね上がっている（2000 ぐらい）」「1 試合当たりで使うトークンと API 換算料金はどのぐらい？」

- 呼び出しのたびに CLI を起動すると、毎回既定の指示・設定・会話の全部を読み直す（1 回 8 万トークン・1 日 2,000 セッション）。席ごとに 1 つ常駐させて問いを流し込み、指示を席の説明だけに差し替え、設定・MCP を読まず、一定回数ごとに要約を付けて作り直す（1 回 1.2 万トークン・1 試合 6 セッション）。
- 1 試合あたりのトークンと料金を出して報告できるようにする（Haiku で 1 試合およそ $0.09）。
- 呼び出しを記録し、同じ入力なら再生する（試合の決定性と同じ: 作り直すときに変えた所だけ呼び直す）。入力が変わったら古い記録は脇へ退けて取り直す。
- 一発で作れること（札 1 枚で撮影 → 台本 → 声 → 点検 → 結合）。手で直す工程を残さない。

## 8. 確かめ方

- 動画ができたこと・点検が通ったことは正しさの証明ではない。**読み上げた台本を読み、動画のコマを自分で見る**。
- 重なり・切れ方・ずれは数で測り、同じ試合を書き直して前後を比べる。
- ユーザーの言葉が正（「単調」「重なる」「ずれる」「自然になった」）。数字が良くても聞いた感じが違えば直す。
- 直すときは「その症状を禁じる一文」を足したくなったら止まり、入力・場のしくみ・情報の解像度のどこから出ているかを先に探す。
