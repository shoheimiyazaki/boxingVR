# キャラクター（体格・顔・目）

キャラ 1 人は「スタイル JSON（ボットの性格）＋ 体格（`Build`）＋ 顔（`Face`）」で決まる。体格と顔は **見える寸法** で、強さはそこから出る（CLAUDE.md §1.7 見た目が脅威を伝える）。

```jsonc
{ "Name": "titan", "RingName": "タイタン",
  "Build": { "Height": 1.18, "Arms": 1.15, "Legs": 1.1, "Muscle": 1.35 },
  "Face":  { "EyeSpacing": 0.9, "Nose": 1.25, "Jaw": 1.28, "EyeTilt": 0.25, ... },
  ... ボットの性格（Aim・ComboWeights など）... }
```

例は `docs/characters/titan.json`（大きい）・`shrimp.json`（小さい）・`eyehunter.json`（目を狙う）。`--red docs/characters/titan.json` のようにそのまま `video`・`league` に渡せる。`Build`・`Face` を省くと、基準の体格と、リングネームから決まる顔になる。

## 1. 体格（`BodyBuild`、基準 = 1.0）

| パラメータ | 意味 | 効くところ |
|---|---|---|
| `Height` | 身長（全部位の長さ・太さ） | 体の寸法 → 質量・間合い |
| `Arms` | 腕の長さ（身長に掛ける） | 拳の届く距離（`Fighter.ArmReach`） → `FighterSense.OpponentArmReach` → `RangeSense` / `EngageRange` |
| `Legs` | 脚の長さ | 歩幅・脚の関節トルクのてこ |
| `Muscle` | 筋肉の太さ（手足の断面の辺、胴の幅と奥行き） | 断面積 → 筋力 |

指定できる範囲は 0.6〜1.5（`BodyBuild.Validate`）。

**ボクセルの数は変えない**。部位の箱の寸法（半径）だけを変え、同じ数のセルを引き伸ばす（`BoxerBody` が基準体格の中身を作って箱へ写す）。セルの大きさが変わるので、質量は部位の体積に比例する（セルあたりの質量は同じ材質の配置のまま）。

### 力の出どころ（一つの式）

| 量 | 式 | 備考 |
|---|---|---|
| 腕の力 | 状態 × 断面積比 `Height² × Muscle²` | 拳を目標へ引く PD 力（`Fighter.ArmStrength`）。筋力は断面積に比例（生理の近似） |
| 脚の力 | 状態 × 断面積比 × 脚の長さ比 `Height × Legs` | 関節のトルク = 筋力 × てこの腕（`BodyBuild.LegTorqueRatio`）。ホバー・歩く力・蹴りの足首の力にも同じ値を使う |
| 立てるか | 脚の**状態**（体格に依らない） | 痩せた脚が健康なまま立てなくならない（`Fighter.LegCondition`） |
| 質量 | 部位の体積に比例 | §8 の近道（材質の密度から直接は出していない） |

基準体格（`Muscle = Height = Arms = Legs = 1`）では比がちょうど 1 で、今までの物理と同じ（テストが比 = 1 と質量比 = 体積比を確かめる）。

### 筋肉が傷むと力が落ちる（残った断面）

`BoxerBody.Muscle(部位)`:

- 腕・脚（梁の軸のある部位）: 軸に沿った薄切りごとに、残った肉（皮膚と筋肉のセル）の数 / 元の数 を出し、**いちばん細い半分の薄切り（肉のセルが最大の 4 分の 1 未満の端は除く）の平均**を取る。筋肉は直列に力を伝えるので、どこか 1 か所が細くなればそこで力が決まる。一様に削れた部位では体積の割合と同じ。
- 頭・胴など軸のない部位: 体積の割合。

以前は全部「残った体積の割合」だった。1 か所だけ深くえぐれても（体積はほとんど減らない）力が落ちなかった。テスト `MuscleStrength_FollowsTheWeakestCrossSection_NotTheVolume`。

力 = `MinMuscleStrength + (1 - MinMuscleStrength) × 残った断面`（肉が無くなっても腱・骨で動かせる分が残る）。

## 2.0 顔の部品の表と組み立て（F1、2026-11-19。F2 から試合の頭の顔の層: §2）

- **部品の表**: `games/MiniRing/Voxels/FaceParts/*.json`（部位ごと: `jaw`・`hair`・`beard`・`eyes`・`brows`・`mouth`・`nose`・`ears`、各 6 種と土台 `base.json`）。出どころは Codex の参考図（`docs/plans/face_refs/`）で、`py -3 tools/face-parts/build_face_parts.py` が txt から作り直す。
  部品は参考図の格子（1 セル = 2.5 mm、頭の箱 20 x 28 x 20）の文字の格子（正面・横・上）と留める点と材質。読み込みは検証し、壊れていれば止まる（`FacePartLibrary`）。
  `parts2/`（参考図 D）の追加は既存の部位の部品として足した（`build_face_parts.py` の `build_extra`）: 目 = まぶたの違い 6（一重・内側に覆いかぶさる・二重・奥目・大きい・厚いまぶた。白目 + 黒目は 3〜4 セル幅）、口 +6（唇の厚み 4・人中の短い／長い）、あご +5（顔の形: 広い・長い・四角・卵形・下顎が前。上からの輪郭付き）、髪 +6（髪質: まっすぐ・うねり・ゆるい巻き・細かい縮れ・縮れのハイトップ・長髪）、ひげ +1（もみあげと頬の下まで覆う全体のひげ）。眉の張り出しと鼻筋の高さだけは横の輪郭の別の部位 `browridge`（4 種）。
- **組み立て**（`FaceComposer.Compose(spec, nx, ny, nz)`、2026-11-20 にシンプルな顔へ作り直した。ユーザーの「顔がキモい → かわいいシンプルな顔」）:
  頭の輪郭（`FaceShape`）→ 髪・ひげ（正面 × 横の積）→ 眉・唇・目を表面から塗る → 鼻（`NoseShape`）・耳を足す。
  - **頭の輪郭** `FaceShape`: デッサンの組み立て（Loomis の「側面を切った球 ＋ あごの塊」、Asaro の頭の面）に合わせた 2 つの塊の距離の場のなめらかな和（smin、幅 2 セル）。
    頭蓋 = 側面を平らにした超楕円体（幅は頭の幅）。顔の塊 = 前から台形（頬骨の幅 → あごの角の幅 → あご先へ放物線）、横からくさび（前の面は目・口の深さを基準に、眉の張り出し `BrowRidge`・あご先の前後 `Jaw` で動き、真ん中が平らで横の端で下がる。頬骨 `Cheekbones` が出ているほど平ら）。前と横の角は面取り。
    頭とあごの幅・あご先の下端はあごの部品（jaw.*）の正面の絵から測った値に `FaceWidth`・`JawWidth` を掛ける。部品の絵の視体積だった頃は、顔の線に 1 セルの凸凹が出て気持ち悪かった。
  - **鼻** `NoseShape`: 鼻すじのくさび（幅 2、鼻根の行は高さ 0 から鼻先へ直線で前へ）＋ 鼻先（幅 4〜6、真ん中がいちばん前）＋ 底の行の [小鼻][穴][鼻柱][穴][小鼻]（2 つの穴の間に必ず皮膚。鼻柱は穴より 1 段前）。
    長さ・高さ・幅は鼻の部品（nose.*）の絵から測って `NoseLength`・`Nose`・`NoseWidth` を掛け、セルへ丸める。鼻根は目の中心の 1 行下、底は口の 1 行上まで。
  - **目**: 白目は幅 3〜4 × 高さ 2〜3、黒目は 1 セル（幅 3 は真ん中、幅 4 は真ん中 2 列の目頭側、高さ 2 は上の段、3 は真ん中）。部品の絵をそのまま写す（大きさ・傾きの値で崩さない。中心はセルの格子へそろえる）。
    `tools/face-parts/simple_parts.py` が eyes.json・brows.json の正面の絵を書き直す。
  - **眉**: 途切れない形（4 近傍でつなぎ、最大のかたまりだけ）。目と髪から 1 マス以上離す（上へ 0〜4 マスずらし、触れるセルがいちばん少ない位置を選んで、触れるセルを削る）。
  - 名簿の目と眉は 1 キャラ 1 部品（混ぜると 3×3・3 行の眉に太った）。部品の重みは他の部位では今も混ぜる（重み付きの和を閾値で切る）。出力は任意の解像度の材質の格子（`FaceMaterial`）で、同じ入力から同じ出力。
- **キャラの顔**: 名簿の `"face"`（任意）: `{ "parts": { "nose": { "nose.2": 0.6, "nose.3": 0.4 }, "beard": {} }, "values": { "NoseWidth": 1.2 }, "skin": [r,g,b], "hair": [..], "iris": [..] }`。
  書かれていない部位は名前から決める（`FaceSpec.For`）。`"face"` が無いキャラは `look` の髪型・眉・ひげを部品に当てる（`FaceSpec.FromLook`）。人種・国の見た目の違いは、色・`FaceParts` の値（`FaceWidth`・`Cheekbones`・`Jaw`・`NoseWidth`・`Lips`・`BrowRidge`・`Freckles` ほか）・部品の重みという連続の値でファイルに書く（種類の分岐をコードに書かない）。
- **見た目の決まり（F3）**: 髪は頭の輪郭の外へ `reach`（部品のデータ。普通 1.5〜2 セル、アフロ・ポニーテール・長髪だけ大きい）まで。髪質は `frizz`（0..1）で、頭の外へ座標のハッシュ（乱数なし）で毛先を足す。ひげの密度 `density`（無精ひげ = 0.45）。ひげは唇の左右にあれば唇の隙間を空ける。頭頂（`FaceShape.CrownRow` より上）の髪は、その行の髪の絵で塗る（地肌の点が出ない）。色は `FacePalette.Resolve(spec)`（肌・髪・瞳の 3 色から他の材質を一つの式で出す。瞳の既定は暗い茶色）。
- **人種・国の違い**: 名簿の `"face"` の値（まぶた・眉の張り出し・唇・髪質・顔の形の部品の重みと `FaceParts` の値、色）だけで書く。沖縄 3 人（二重・奥目・眉の張り出し・広い顔）、日本本土 2 人（一重・細い・平ら）、韓国（一重・平らな鼻筋・V ライン）、ヨーロッパ（鼻・髪・ひげ・瞳の色の組）など。`tools/face-parts/roster_faces.py` が `roster/*.json` へ書く。比較図は `docs/plans/face_refs/compare/fighter_<id>.png`・`roster_composed.png`。
- 近道: 影の皮膚（耳の内側）は 1 つの材質（`Shadow`）にまとめている。眉の張り出しの部品（`browridge`）と、目の大きさ・傾き（`EyeSize`・`EyeTilt`）は、シンプルな顔では形に効かない（読み込みと検証だけ）。

## 2. 顔（顔の層 `FaceLayer`・`FaceParts`、2026-11-19 の F2 から）

**頭は 2 つの格子**（PhysicsVersion 57）: 頭の剛体は、5 mm の頭の格子（10 × 14 × 10）と、同じ箱を 2 倍の細かさで分けた**顔の層**（20 × 28 × 20、約 2.5 mm）を持つ（手の層と同じ `VoxelBody.AddCompanion`）。

- **5 mm の頭** = 頭蓋骨・脳・首の中（頸椎・脊髄・首の筋肉）だけ。脳のセルは作った頭から 1 つも変えない（意識のモデルの量は同じ）。頭蓋骨のうち、顔の目と重なる所（眼窩）と、脳に面していない骨で顔の外へ出る所は抜く。
- **顔の層** = `FaceComposer` がキャラの `FaceSpec`（名簿の `"face"`、無ければ `look` と名前から: §2.0）から組み立てた顔の、頭蓋骨の外の所（頭皮・顔の肉・目・鼻・唇・耳・髪・ひげ）と、頭蓋骨を包む 1 層の皮膚。外の 1 層が皮膚、その下は筋肉。同じ所を 2 つの格子が持たない（`FaceLayerTests`）。
- 首の段（頸椎の段まで）は顔ではないので、あご・ひげと重ならない首の皮膚・筋肉は 5 mm の格子に残る。
- 質量: 頭の質量（体格の寸法から）は変えず、2 つの格子の体積で分ける（顔の層の 1 セルは 5 mm のセルの 1/8）。顔の層の体積は、5 mm の頭から抜いた外側の 1.0〜1.6 倍（F3 の名簿の 18 人。髪が輪郭の外へ出る・あごが広い）。剛体の当たりの箱と質量は作ったまま（頭の箱）で、削れたときに残ったセルへ合わせ直す（ほかの部位と同じ）。
- 色: 顔の層のセルは、組み立てた顔の材質ごとの色（`FacePalette`: 肌・髪・瞳・影・眉・唇・鼻の穴・そばかす・無精ひげ）で描く（`FaceCellColors`。材質は皮膚・髪・目…のまま、見た目だけ）。名簿の `"face"` の肌・髪・瞳の色は体の色にも使う（`FaceLayer.LookWith`: 顔と首の肌がそろう）。**肌の色の出どころは一つ**: 名簿の `"face"` の `skin`（無ければ `"look"` の `skin`）。体の全部位の色の表・顔の層は `LookWith` で、素手の拳（手の皮膚 `HandSkin`、武器の描画 `Weapon.AddDraws` が持ち主の `BoxerBody.SkinColor` で塗り直す: `HandSkinTint`）も同じ色になる（2026-11-21。手の格子は共通の材質の表から作るので、手だけ既定の淡い色のままだった）。見た目だけ（材質・物性・チェックサムは変わらない）。確かめ: `SkinToneTests`、目で見る `SkinToneVisualTests`（`SKIN_TAG` で前後を比べる）。
- 描き方（全部のボクセル、2026-11-19）: 面の明るさは、面の向きを周りのセルが作る面の向きへ寄せて決める（`VoxelVolumePipeline`: 3 × 3 × 3 の埋まり方の勾配）。細かい格子の階段の段ごとに上の面が光る細い線が出なくなった。縁の光（リム）は、外に開いた面だけ。白目は明るい面（テクスチャの alpha 0.5）として描き、陰でも灰色に沈まない。
- **当たり**: 顔の層は頭の格子の前に調べ（外の層から当たる）、接触ではいつも打たれる側（`VoxelBody.PreferField`: 粗いグローブ・すねに対しても、面の下が潰れるのは顔）。腕・脚の後ろの質量は、同じ剛体の格子のうち最初に触れた層だけが受ける。首を曲げる力は顔の層から頭の梁へ渡す。打撃の削り（`BoxerBody.Impact`）は顔の層 → 頭蓋骨の順で、使い残した分が下へ行く。
- **目**: 白目・黒目は顔の層だけ。見え（`BoxerBody.Vision`）は顔の層の白目の体積に対する残り（意味は前と同じ）。黒目・まぶた（§2.5）・急所の点（`BodyLandmarks`: 目・こめかみ・あご）・あざ・チアノーゼ・顔色・再生（頭蓋骨と脳が先、顔は後）も顔の層を読む。
- 肖像（メニューの顔）は顔の層の細かさ（1 ピクセル = 約 2.5 mm）で写す。`miniring-arena faces [--names ...]` は試合の頭（2 つの格子）を正面・横・上・斜めで並べる。目で見る: `FaceLayerVisualTests` → `.visualcheck/face_layer_views.png`。
- 近道は `docs/DEBT.md`「顔の層」。

### 前の顔（5 mm の頭に巻き付けるテンプレート。今は顔の層の下の頭蓋骨を作る途中だけで使う）

頭のボクセル（約 10 × 14 × 10 セル。1 セル 5 mm）に、部位ごとのテンプレートを巻き付ける（`Voxels/FaceTemplates.cs`）。F2 からは、その外側（皮膚・目・髪）は顔の層へ置き換わり、試合には残らない。すべて基準の顔に対する相対値で、`FaceParts.Default` が基準:

| 部位 | パラメータ | 作り方 |
|---|---|---|
| 目 | `EyeSpacing` `EyeSize` `EyeHeight` `EyeTilt` | 白目・黒目のセルを、基準の目の位置へ逆写し（傾き・寸法・間隔・高さ、表面からの深さを保つ）して作り直す。黒目は表の白目のうち目の中心にいちばん近い 1 セル。**白目の体積が視力の材料**なので、潰せる体積を持ったまま動く |
| 眉 | `BrowHeight` `BrowTilt` `BrowThickness` | 目の上の細い帯を傾け・太さを変えて、表面の皮膚を髪の色にする（`FaceLook.Brows` のとき） |
| 鼻 | `Nose` `NoseWidth` `NoseLength` | 鼻筋と鼻先の起伏（前へ盛る） |
| 口 | `MouthWidth` `MouthHeight` `Lips` | 唇の帯（材質 `lip`: 皮膚と同じ強さ・密度、色だけ肌から赤みへ） |
| 耳 | `EarSize` `EarHeight` | 頭の横の起伏（外へ盛る） |
| あご・頬骨 | `Jaw` `JawWidth` `Cheekbones` | あごの突き出し・下顎の幅・頬の盛り上がり |
| 髪 | `Hairline`（髪型は `FaceLook.Style`） | 生え際の高さ（`Full`・`Crop`）。髪型・色・ひげは従来どおりリングネームから |

起伏は「柱ごとに表面を前後（左右）へずらす」ワープで作る: 皮膚は 1 層のまま、その下の肉・骨が引き伸ばされる（空洞を作らない）。頭の中身（脳）は動かさない（テストが脳のセル数が変わらないことを確かめる）。

**解像度の限界**: 頭は 10 × 14 × 10 セルしかなく、目は 2〜3 セル、鼻は 1〜2 セルの盛り上がりにしかならない。パラメータの連続な差は、セルの丸めで階段状に現れる。見分けの主役は肌・髪の色と髪型・ひげ・目の位置と寸法・眉の傾き・口の太さ。この限界のため、F2 で顔だけ 2 倍の細かさ（2.5 mm）の顔の層にした（上）。

`docs/images/gen13_faces.png`: 全キャラの顔（左 = 正面、右 = 斜め 40 度）。`miniring-arena faces [--names a,b,f.json] [--columns N]` で作る。

## 2.5 黒目が見ている方へ動く・まぶた・まばたき（2026-11-18、見た目だけ）

頭の目は 2 × 2 セルの白目の面（`EyeScan` の通り、表に出ている白目だけが見える）。**材質のセルは動かさず、描く色だけ**を動かす（打撃・視覚・チェックサムに響かない。`PhysicsVersion`・`LogicVersion` は上げない）。実装は `Voxels/EyeLook.cs`（`EyeGaze`・`EyeBlink`・`EyePose`）と `VoxelPart.Draw(cyanosis, eyes)`（あざ・チアノーゼと同じ塗り直しの道）。

- **黒目**: 眼球を、目の表のセルの重心から奥へ `BallRadiusCells`（2.5 セル）の所を中心とする球と見なし、見ている向きにいちばん近い向きにある、表の白目のセル 1 つを黒目の色で塗る（左右の目それぞれ）。削れた白目は塗らない（残った白目の中で動く。無くなれば塗らない）。向きの後ろ向きは `MinForward` で正面寄りに丸める。2 × 2 セルの目なので、黒目は向いた側の列・段へ 1 セル動く。
- **注目している点**（`EyeGaze.TargetOf`）: 相手の頭。相手の拳がこちらへ速く近づいているとき（近づく速さ 5 m/s で 0.8）は、その拳の方へ視線が連続に寄る。意識（`Fighter.Awareness`）が `FocusAwareness`（0.35）未満か死んでいれば、焦点が合わず正面を向く。見た目の値で、ボットの読み・狙い（`OpponentRead`・`AimWeights`）は使わない（描画が判断の側へ逆流しないように）。
- **まぶた**: 目のセル（白目・黒目）を、上の段から順に、顔の皮膚の色（あざ・チアノーゼの色を含む）へ塗り替える。段数は閉じ具合 × 目の高さを丸めたもの。
- **まばたき**（`EyeBlink`、試合の歩の中で `Fighter.Eyes` が進む）: 間隔は落ち着いて 4.2 秒、息の上がり・痛みの記憶が増えるほど 1.4 秒まで連続に詰まる（×0.55〜1.45 の揺らぎはファイターごとの決まった数列: 頭の初期位置から作る種）。1 回 0.16 秒（疲れるほど 0.22 秒）、閉じる側 35 %・開く側 65 %。意識が薄れるほどまぶたが落ち（`(1 − 意識)^1.5 × 0.95`）、意識が無ければほぼ閉じ、死ねば閉じる。痛みは目を細める（最大 0.3）。
- **打たれたときの反射**（`EyeBlink.Flinch`、`BoxingGame.ApplyHit`）: 強さ = (1 − exp(−E / 15 J)) × exp(−目までの距離 / 0.4 m)。すぐ閉じ、強さに応じて 0.12〜0.67 秒閉じたままで、痛みの記憶（0.5 × 強さ、毎秒 0.12 ずつ抜ける）が残ってまばたきが増える。近道: 秒数・距離・エネルギーは見た目の値で、生理の測定ではない。
- 確かめ: `EyeLookTests`（黒目の動き・削れた目・まぶたが上から下へ・材質と格子の版が変わらない・まばたきの回数と状態・反射）と、`EyeLookVisualTests`（`.visualcheck/eyes_gaze_blink.png`）。

## 3. 目が潰れる（`VisionState`・`VisionPerception`）

目の白目・黒目のセル（材質 `eye`・`pupil`）の残り HP の割合が、左右の目それぞれの「見える度合い」（`BoxerBody.Vision`）。連続で、場合分けはない。

- **ボットへ渡す情報**（`BoxingGame.ArmedSense`）: 両目が無事なら今の状態そのまま。損傷があれば、`VisionPerception` の低域フィルタ（毎ステップ更新）を通した写しを渡す。見えない側の視野にある相手の拳・肩・腰・頭は、更新が遅れ（`VisionLagSeconds` × 失った割合²）、位置がぶれる（`VisionNoiseReach`）。ぶれは試合の種付きの乱数（§1.6）で、参照回数に依存しない。拳の速さも見える度合いで縮み、`TargetMap`（狙いの点）は実体への参照を切って写しにする（傷んだ目から現在位置を逆引きさせない）。
- **人（キーボード・意図操作）**: 意図の解釈も同じ `ArmedSense` を受け取るので、同じ遅れ・ぶれが入る。画面は、潰れた目の側の端が暗くなる（`BlindHud`、失った割合に連続）。
- **VR**: ホストの描画は別（計画: HMD の左右の目それぞれの画面の端を、その目の失った割合で暗くする。`PlayerSense.SelfVision` を読めばよい）。未実装。
- **ボット側の狙い**: `AimWeights.Eye`（目）・`BlindSide`（見えない側）。重みは相手の見えが悪いほど増える（`Targeting.Weight`: 目は `2 − 両目の平均`、見えない側は `1 − 悪い方の目`）。空手家の貫手・一本拳（`KarateHandChoice`）と結びつく。
- 測定は `miniring-arena visionlab` と `docs/BOT_PDCA.md` の gen13。

### 方針
- **実在の人物はモデルにしない**。顔・名前の権利の問題と、体が削れ・切断され・死ぬゲームで実在の人を描く問題のため。名簿は全員が架空で、実在の特定の人を連想させる名前・顔にしない（顔は肌・髪・瞳の色と、基準の顔の小さな個人差だけ）。
- **国らしさは、その国の格闘の伝統（武器・戦い方）と、名前・装い・体格で出す**。人種の身体的な特徴を戯画化（誇張した顔の造作など）はしない。肌の色・髪・瞳は、その地域に普通にある色を選ぶ。顔の部位（`FaceParts`）は基準の ±15 % 以内の個人差だけ（あご・眉の太さ・頬骨・口の幅）。
- **強さは見えている体から出る**（CLAUDE.md §1.7）。大きい体格のキャラは実際に強い。能力値の数字は名簿に持たない。ボットの性格（`style`）は入力元の違いで、体の強さではない。
- **武器はキャラクターごとに固定**（メニューに武器を選ぶ行は無い）。握る武器（`weapon`: katana / longsword / ironSword / club）か、手にはめる物（`wear`: glove / none / knuckles / katar / gauntlet）。

### 肖像（メニューの顔・全身の絵）
`CharacterPortraits` は、試合の体と **同じ関数**（`BoxerBody.BuildPartGrid`: 基準体格の格子 → 体格へ伸縮 → 顔を巻き付け）で部位の格子を作り、立った姿（`Fighter.Spawn`）に置いて、腕だけ肩を軸に脇へ下ろし（回すだけ）、正面から奥へ光線を通して **いちばん手前のセルの材質** を四角（ドット絵）に写す。別の絵を描き起こさない。明るさは手前のセルの奥行きの段差から出した左上からの光だけ（顔の起伏が見える）。顔は 1 ピクセル = ボクセル 1 つ（5 mm）、全身も同じ細かさで、背の高さ・太さは体格の寸法のまま（同じ尺度で並べる）。作るのは重いので `PortraitSet` が背景スレッドで 1 人ずつ作り、できた人から出す。

## 11. プロフィール（2026-11-16、`Characters/CharacterProfile.cs`）

各キャラクターのファイル（`roster/<id>.json`）の `profile` に、作中の経歴と人柄を持たせる。キャラクターの軸（名前・国・肩書き・教科書・体格・武器・顔と矛盾しない人物像）を作り、テレビ中継の実況・解説が参照する（`events.json` の `redDossier`・`blueDossier`、台本の資料 `bN.digest.md`、冒頭の「選手の比較の表」）。全員架空。

- 項目: 年齢・身長 [cm]・体重 [kg]・出身・拠点・構え・リングネームの由来・戦績（勝・敗・分・K.O.）・経歴（年ごと）・トレーナー・戦い方・強み・弱み・人柄・趣味・家族・エピソード・口癖・中継の小ネタ。
- **身長と体重は物理の体から**（§1.7、2026-11-24 から）: 身長 = 物理の体の立った高さ（足の裏から頭の上。部位の箱を生成の並びで積み、つなぎ目の重なりを引く: `BodySizing.PhysicalHeightMeters`）、体重 = 物理の体の質量（部位の体積に比例。試合の体の `Fighter.TotalMass`: `BodySizing.PhysicalMassKg`）。どちらも四捨五入。読み込みで一致を確かめ、合わなければ例外（見た目・物理と紙の上の数字を食い違わせない）。基準体格は 145 cm・68 kg。それまでの紙の式（175 cm × 身長の比・72 kg × 身長の比² × 太さ）は物理の体と基準で 29 cm・4 kg、マーカスで 32 cm・21 kg ずれていたので、名簿 18 人の数字を物理の値へ直した（体格の比は変えていない: 試合は同じ）。
- 強さ・能力値は持たない（強さは体から、上手さは教育から: §1.8）。戦績・経歴は作中の物語で、試合の判断には使わない。
- キャラクター同士の因縁（過去の対戦）は、両方のプロフィールに同じ年・同じ結果で書く。

## 12. キャラメイク（作成ツール、2026-11-24、`miniring-arena maker`）

```

```

- **画面を Web にした理由**: 名前の入力・写真のファイルの選択・目印の点のドラッグ・スライダーはブラウザがそのまま持っている（ゲームの UI は図形だけで文字の入力が無い）。絵はゲームの物で、試合の頭（`FaceSheet.HeadViews`: 頭の格子 ＋ 顔の層）と全身（`CharacterPortraits`: 試合の体と同じ格子）を CPU で写す（描き起こさない。1 回 1〜2 秒）。
- **保存する物は名簿のファイルそのもの**（新しい形式は作らない）。下書き（`CharacterDraft`）→ `FighterCharacter` → `CharacterFile.Write` → **名簿の読み込み（`CharacterRoster.FromFiles`）を通してから**保存する（壊れたファイルは保存しない。どの欄かを画面に出す）。教育は空（教科書そのもの）、育ちの記録は空、順番は名簿の最後の次。

  - 「キャラの場所へ保存」: `%LOCALAPPDATA%/MiniRing/characters/<id>.json`（`--save-dir` で変える）。組み込みと同じ id は断る。`video --red-char <ファイル.json>` にそのまま渡せる（`CharacterRoster.LoadFile`）。
  - 「ダウンロード」: 同じ中身をブラウザから保存。「ファイルから」で読み戻せる。名簿のキャラを読み込んで直すこともできる: 教育・育ちの記録・順番はそのまま運び、身長・体重を変えなければ体格の比もそのまま（`CharacterMakerTests`）。`look` は `face` から作り直す（髪型・眉・ひげ・色を顔の層に合わせる。試合の見た目は `face` が決めるので変わらない）。

### 体（`BodySizing`）
- 身長 [cm] と体重 [kg] から体格を**解く**: 物理の体の高さが指定の身長になる身長の比（脚の長さの比のとき）を、次に物理の質量が指定の体重になる太さ（`Muscle`）を二分法で解く。名簿の式（`CharacterProfile.HeightOf`・`WeightOf` = 物理の体）で出し直すと指定の身長・体重にちょうど戻る（`Solve` が確かめる）。体重の幅は太さが 0.6〜1.5 倍に入る所（画面のスライダーの幅、腕・脚の長さでも変わる: 体積に比例）。
- **体型**（`maker.json` の `bodyTypes`: 細身・標準・筋肉質・重量級・リーチ型・ずんぐり）は太さと腕・脚の長さの初めの値。選ぶと体重を太さから出し、体重を手で動かすと太さを体重から解き直す。腕・脚の長さは別のスライダー。
- 能力値の倍率は無い（§1.7）。画面には、筋肉の太さ・腕の力（断面の比 H²M²）・見た目の重さの比（H³M²）・体の質量の丸める前の値を並べる。体重（計量・階級・プロフィール）は物理の体の質量そのもの（`BodySizing.PhysicalMassKg` = 試合の体の `Fighter.TotalMass`）。

### 顔
- **ルーツ**（`maker.json` の `roots`、人種の代わりの言葉）: 東アジア・東南アジア・南アジア・中東・北アフリカ・北・東ヨーロッパ・南・西ヨーロッパ・サハラ以南アフリカ・ラテンアメリカ・太平洋の島々。肌・髪・瞳の色の候補と、部品の重み・顔の値のテンプレートで、**見た目だけ**（体格・強さは変えない: テスト）。値は名簿の 18 人の選び方（`tools/face-parts/roster_faces.py`）から控えめな物だけを取った（戯画化しない: §5「方針」）。当てた後は全部変えられる。
- 部位ごとに部品を 1 つか 2 つ選ぶ（2 つなら混ぜる割合）。目と眉は 1 部品（名簿の決まり）。髪・眉・ひげ・眉の張り出しは「なし」にできる。寸法・位置の値（`FaceParts`）はスライダー（幅は `FaceParts.Validate` と同じ。ダブルクリックで既定）。色は色の選び。

### 写真から（`PhotoFace`）
- 写真を選ぶと、ブラウザの中で 640 px に縮めて表示する。顔の目印 24 点（目頭・目尻・まぶた・眉・鼻・口・あご・頬・あごの角・生え際）を、**ブラウザの中の MediaPipe Face Landmarker**（Apache-2.0。ライブラリ `@mediapipe/tasks-vision@0.10.14` とモデルは初回だけ CDN から読む。写真は送らない）で自動で置くか、真ん中の型から手でドラッグして置く。
- **信頼の境目**: 自動の目印のライブラリ（CDN の JavaScript と WASM）は、この画面と同じ所（localhost の口）で動く。版は固定しているが、CDN の中身を信じることになる（写真を読める・口へ送れる）。信じたくなければ自動の目印を押さずに手で点を置く（そのとき外から読む物は何も無い）。口はほかのサイトからの要求を断る（Host・Origin・JSON だけ）。
- 「この写真から顔を作る」で、縮めた写真（PNG）と点を localhost の口へ送り、`PhotoFace.FromPhoto` が顔の値にする。**写真はメモリの中だけで扱い、ファイルにも記録にも残さない。リポジトリにも入れない**（テストは合成の絵: `PhotoFaceTests`）。
- **形は似顔絵**（2026-11-24、ユーザーの指定「平均からのずれを増幅してパーツを配置。似顔絵みたいに」）: `FaceProportions.Measure` が、目の線を水平に回した枠で、顔の幅 W（頬の端から端）と高さ H（額の目印からあご先）に対する比を測る: 縦横比 H/W・あごの幅/W・目の間/W・目の幅/W・目の開き（高さ/幅）・目・眉・鼻先・口の位置（額から下へ/H）・小鼻の幅/W・口の幅/W・唇の厚さ/H。`Caricature.Apply` が、平均からのずれを **強さ（画面の「似顔絵の強さ」、既定 2.5）倍** にして（誇張した比 = 平均 + 強さ × (測った比 − 平均)）値と部品へ写す。
  - 長さの比は既定の値への倍率（口の幅・目の間・鼻の幅・あごの幅・唇・顔の幅 = 平均の縦横比 / 誇張した縦横比）。位置は顔の層の格子の行のずれ（比 1 あたりの行数は、平均の目と口の位置の差が格子の目 13.5 行と口 21.5 行の差になるように決める）を位置の値（目・眉・口の高さ、鼻の長さ）に直す。
  - **おでこ**（2026-11-24、ユーザーの指定「おでこの大きさがかなり違う」）: 額の目印（MediaPipe の 10 番）は額の中ほどなので、髪の色を探して見つけた生え際（0.05 IOD ずつ上へ）から目の線までを H で割った比を測る（平均 0.406 ± 0.071。12 の比の中でいちばんばらつく）。誇張した生え際の行のずれを生え際の値（`Hairline`、負 = 上・正 = 下、−0.25〜0.12）にする。生え際の値は額の生え際の所だけ髪の絵をずらし、頭頂へ向かって 0 にする（PhysicsVersion 93。前は絵全体をずらしたので、下げると頭頂に地肌の点が出た）。坊主・生え際が見つからない写真では測らない。
  - 目の絵は引き伸ばさない（2026-11-20 の指示）ので、目の開きと幅は目の部品（一重・まぶたの厚い・二重・大きい）の選びで表す。唇・鼻・あごは並んだ 2 つの部品を、誇張したずれ（標準偏差で割った z）で混ぜる。
  - 平均の顔（ずれ 0）と強さ 0 は既定の顔そのもの（テスト `PhotoFaceTests.TheAverageFace_IsTheDefaultFace_AndTheGainScalesTheDeviation`）。誇張が入るように顔の値の幅を広げた（目の高さ ±0.2・口の高さ ±0.14・目の間 0.7〜1.4 など。名簿の顔は前の幅の内側なので変わらない）。
  - **平均とばらつき**（`maker.json` の `photoNorms`）: 同じ目印（MediaPipe）で生成の顔（実在しない人）40 枚を測った値（顔が見つからなかった 1 枚を除く 39 枚。写真は残していない）。縦横比 1.199 ± 0.060・あごの幅 0.797 ± 0.021・目の間 0.438 ± 0.015・目の幅 0.195 ± 0.011・目の開き 0.322 ± 0.058・目の位置 0.318 ± 0.014・眉 0.177 ± 0.013・鼻先 0.572 ± 0.029・小鼻の幅 0.307 ± 0.018・口の位置 0.743 ± 0.020・口の幅 0.425 ± 0.045・唇の厚さ 0.130 ± 0.028。文献の平均（Farkas の北米の成人の顔の計測: 頬骨弓幅 約 134 mm・瞳孔間 約 62 mm・口の幅 約 52 mm・鼻の幅 約 33 mm・下顎角幅 約 94 mm）を W で割った比（目の間 0.46・口 0.39・鼻 0.25・あご 0.70）とは、MediaPipe の頬・小鼻・あごの角の点が解剖の計測点より外・上にあるぶん違うので、測り直した値を使う。生成の顔は笑顔が多く、口の幅と唇の厚さのばらつきが大きい（口を開けて笑った写真は唇が厚く出る）。
